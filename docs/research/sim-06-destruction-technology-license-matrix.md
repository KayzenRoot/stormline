## Technical selection protocol
1. Choose future smallest NECESSARY playable proof: one authored wall/prop, parent and 16-64 chunk candidates (illustrative fixture, not runtime default) with legal original geometry, damage thresholds, two collision LODs, visual dust and ground/nav commit.
2. Compare **offline** Voronoi cell generation + **owned** robust mesh intersection vs Blast authored fracture; measure cooker input complexity, output manifoldness, correct volumes/inertia, crack/interior material UV, runtime baked blob bytes and native tool dependencies. Do not assume a mesh algorithm is complete because Voronoi cells exist.
3. Evaluate Blast core without PhysX extensions and document every transitive license, optional Packman-downloaded tools, SDK/toolchain and macOS/Web viability. Demonstrate ability to bind to SIM-02 backend through private adapter, else PROVE-OR-DROP.
4. Use optional OpenVDB only in offline editor/build if sparse volumetric cuts are shown to be materially better vs simpler recipe. Pin v12+ or newer and verify exact checkout LICENSE and ABI **not** the contradictory legacy static license page. OpenVDB v14.0 changes serialization, so binary/cache migration must be tested.
5. Declare licensing/attribution and asset rights manifest before any runtime/copied code. File-level GPL-affected libigl APIs are not permitted by default; NLE-D009 engine license still undecided.
6. Quantitatively benchmark CPU+RAM cook, native/headless physics constraints, per-frame CPU/GPU VRAM, stream/collider activation latency, failed partial commit, visual quality and false-world holes with original test scenes. No early speed or visual superiority claims.
