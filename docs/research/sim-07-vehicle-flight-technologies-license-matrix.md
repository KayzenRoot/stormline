## Technical choice and legal protocol before code
1. Pin future exact C++ compiler, ISA/FP/SIMD mode, Jolt/Chrono/Bullet/JSBSim commits/releases, LICENSE per file/module, SBOM and all asset model rights. **No current selection/installation**; MIT/BSD/zlib permissive upstream is not engine legal clearance.
2. Build **one coherent PHYS owner** at a time. Compare Jolt wheeled/tracked baseline vs SIM-02 oracle and a separately run Chrono high-fidelity reference on equal road/terrain/force curves. Avoid fake direct cross-solver equivalence and mixed Jolt-Body + Chrono-body authority.
3. Test proposed owned water displacement and wind/aero forces in headless oracle fixture. JSBSim full FDM may supply reference outputs under pinned conditions, but its solver cannot be transparently treated as a force-only Jolt addon. Any adapter requires explicit single-state/step/inertia protocol and no double integration.
4. Audit authoring XML/JSON/license content, exact source dimensions and legal calibration datasets. Do not copy copyrighted game cars, aircraft rigs, third-party demo models or paid telemetry datasets without permission. Document license notices and service-packaging/relocation responsibilities if LGPL is ever integrated.
5. Record versioned native target support (Windows/Linux/macOS), ARM and browser/WASM scalar/threads, validated build, memory and CPU cost. **No native/Web/ARM guarantee** from upstream README alone.
6. Benchmark p50/p95/p99 physics/contact/controls and memory with real original cars, tracks, boats and airplanes/rotors, plus server RTT/jitter/loss/rollback, flight trim/stability, steering response and headless reproducibility. Do not approve numeric budgets without baseline and test owners.
