# NET-02 — Headless Authoritative Server Tick, Security, Isolation and Deployment Benchmark Protocol

**2026-11-15 | P00 benchmark design only; no server binary, fixture, connected user, host network fault, cloud deployment, measured result or runtime test.** N02-T001..N02-T128 FUTURE/NOT EXECUTED.

## 1. Falsifiable hypotheses
H1: an original Stormline native process can launch, progress CORE-04 fixed ticks and run GAME-04 commands/WORLD-01 ECS **without GPU/renderer**. H2: only authenticated player-intent requests can mutate server authority; arbitrary client Health/Position/Inventory/world snapshots fail closed without changing state. H3: per-match state, player principal, RNG and resources cannot leak across matches even during reconnect/crash. H4: measured tick, CPU/memory, ingress latency and overload/queue policies are bounded under realistic network faults, with explicit degraded behavior. H5: a local native process is viable without mandatory cloud fees or orchestration, and optional OCI/Agones does not change authoritative game semantics. H6: rollback or lag-comp can be added only if proven by NET-04 and bounded history, not assumed by default.

## 4. Methodology and statistical safety
1. Build from approved pinned source with reproducible C++ flags/clock/physics and real headless binary, record OS dependency inspection, compile/memory/runtime logs. Test GPUless VM/container where system truly lacks GPU as well as display-unset; suppressing window creation alone is not proof.
2. Use virtual network under controlled seed for unit and fuzz; real 2-machine isolated LAN/controlled WAN for performance, not broad unsolicited Internet traffic. Network impairment tool under permission only. Network RTT/clock and server command commit time are distinct metrics; transport ACK is not an application commit.
3. Run warmup/repeats and produce raw sample counts, confidence interval estimates and p50/p95/p99 percentiles (not p99 from ten samples), invalid/missing data and heavy-tail histogram. Report CPU per tick, wall time and deadlines, memory RSS and peak, network in/out, queue depth, dropped/denied, actor fairness, script gas, total cpu cost/CCU and server process count.
4. Compare single-thread baseline vs CORE-03 scheduled phases only when gameplay correctness parity proven; never assume thread count scales linearly. Test same-content replay hashes for exact OS/compiler/FPU setting before claiming cross-arch deterministic state. Vary fake renderer presence; server game state must be identical for headless and client *only if that integration is implemented*.
5. Security and anti-cheat: generated adversarial action streams, spoofed actor/state, invalid signed tickets, session revoke while connected, duplicate rewards, clock/time manipulation, fuzz parser/decompressor, CPU queue flooding, per-match isolation and admin privilege escalation. Use Address/Undefined/ThreadSanitizer when supported; verify no DDoS traffic to external targets. Treat attack rejection as correctness, not full anti-cheat guarantee.
6. Crash/recovery: inspect persistence and event cursor, snapshot commit, no duplicated irreversible GAME-04 operation, expired lease fencing, forced SIGKILL cannot guarantee clean checkpoint, owner-authorized rollback only where safe.
7. Deployment comparison: local bare process vs optional container/Agones isolated infra, cold/warm startup, process lifetime and slot scheduling overhead, memory/network and monetary hosting cost plus standby capacity. Kubernetes/Agones is not selected as mandatory; no cost-free hosted cloud claim or automatic provisioning.
8. Gate: if any HIGH/CRITICAL in forged authority, privacy, data corruption, race/split brain, license or privilege route, future implementation BLOCKED; no source CodeQL/SAST runtime claim merely because Docs Validation passed.
