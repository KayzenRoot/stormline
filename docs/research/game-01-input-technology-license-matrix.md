## Selection strategy and safety gates
1. **Preferred native architecture:** CORE-01 SDL3 zlib adapter once approved and pinned; GAME-01 never owns SDL3 event pump. Evaluate alternative OS bridges only for reproducible missing capabilities, not performance marketing.
2. **Third-party controller mapping data:** separate `gamecontrollerdb.txt` dataset from SDL source code; repository zlib listing is not automatic provenance/attribution for every entry or permission for runtime update service. Freeze and review exact dataset commit/entry set and no private IDs.
3. **Browser:** PLAT-03 owns DOM and Permissions Policy, Web Gamepad WD/Pointer Events REC and Pointer Lock permissions. GAME-01 consumes a normalized host event/focus snapshot with unavailable/denied as explicit outcomes.
4. **OS-specific:** GameInput and Apple Game Controller are not drop-in portable permissive libraries; any native adapter must avoid duplicate device read, follow vendor terms, respect event thread and be disabled when unnecessary.
5. **Accessibility and privacy:** no global hooks, silent keyboard capture, unconsented device fingerprinting, hidden accessibility overrides or remap trapping the user. WCAG guides concrete tests but is no certification claim.
6. **Device evidence:** Windows x64/ARM feasibility, Linux Wayland/X11, macOS arm64/Intel target scope, Web browsers and headless test harness with actual keyboard layouts, different gamepads and assistive input. No blanket 100% compatibility.
7. **Pin before shipping:** exact version/hash, official license/SDK terms, platform binaries, build flags, SBOM, allowlist device mapping, test fixture rights and rollback. No SDK, dataset or code was added to this repo in this research.
