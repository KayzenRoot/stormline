## 2. Proposed operations, no runnable API
- `InspectSessionCapabilities(Target,ProviderProfile)`: honest LOCAL_TEST / SELF_HOSTED / EXTERNAL_PROVIDER availability and exact unsupported reason. `Preview/Stage/Validate/CommitSessionProfile` via DATA-04 expected revision and authorized operator, no network bind/issuer keys/billing. Editor/CLI/MCP semantic parity on config only.
- `AuthenticatePlayer(ProviderProof)` / `RefreshAuthSession` / `RevokeSession`: identity issuer, expiry, keys/alg pin, proof audience and current revocation. Local-test provider loopback-only requires privileged explicit test mode, no production anonymous bypass.
- `CreateParty`, `InvitePartyMember`, `JoinParty`, `LeaveParty`, `TransferPartyLeader` with idempotency, atomic capacity and role checks.
- `CreateLobby`, `ListAuthorizedLobbies`, `IssueLobbyInvite`, `AcceptLobbyInvite`, `JoinLobby`, `LeaveLobby`, `KickLobbyMember`, `SetReadyState`, `CloseLobby`: expected revision and typed receipts. Lobby join is not NET-02 admission; public views redacted, private role audience enforced.
- `SubmitMatchmakingTicket` / `CancelMatchmakingTicket` / `InspectQueueStatus`: future optional adapter; local-first selection can be manual. No matchmaking result auto-joins the game.
- `ReserveNET02GameServer` / `AllocateMatchSession` / `IssueScopedMatchJoinTicket`: server/lease readiness and atomic capacity; **no** authenticated user access to raw server minting keys. `ValidateAndAcceptMatchJoin` occurs **in NET-02** after signature/current authorization/nonce/lease checked, return separate game admission receipt.
- `RequestReconnect`: reauth current subject, refresh matching party/lobby and server lease, rotate ticket/transport epoch and invalidate NET-03/04 view histories; fail typed on expiry/ban/closed match/capacity. `LeaveMatch` distinct from `LeaveLobby` and DATA-04 durable game save.
- `ResolveServerDiscovery` / `RequestConnectivityProfile` delegates NET-01 NAT/ICE/TURN, protects private IP disclosure and provider costs. Never accept arbitrary user-supplied relay URL/cert.
- `ExportRedactedSessionDiagnostics` excludes tokens, contacts and private online state; `InjectSyntheticDisconnectOrProviderFailure` test-harness-only, prod unavailable.

## 3. Invariants and distinguishable receipts
1. Identity AuthSession ACTIVE **does not** prove lobby membership; LobbyMembership ACCEPTED **does not** reserve dedicated server; ServerReservation ALLOCATED **does not** authorize NET-02 actor. NET-01 packet ACK, NET-05 lobby mutation, NET-02 join admit, GAME-04 command commit and DATA-04 durable checkpoint are distinct.
2. JWT/token verification pins `alg, typ, iss, aud, nbf, exp, kid` from trusted configured registry, and **current** subject/session/role/ban/revocation/one-use nonce. No `alg=none` production, arbitrary `jku/x5u` key fetching, reuse of invite code as game ticket, or unbounded clock skew.
3. Join/invite/ready/leave/allocate operations compare expected generation+revision and idempotency key; simultaneous joins cannot overbook, stale client callback cannot resurrect lobby. Network retry may repeat calls but never double-create membership or game allocations.
4. Optional reconnect grant never extends expired server lease or bypasses ban. New NET-01 connection must reauthenticate and rotate generation; NET-03 baseline and NET-04 prediction history reset. Lobby host migration/admin transfer is separate from dedicated authoritative game state migration, disabled by default.
5. Presence HIDDEN and private lobby visibility prevent listing/notification/log leakage. Unknown audience/role/privacy => DENY, not public fallback. Blocked users' invite/code should be rejected despite stale cached friend lists. Client-provided lobby metadata is untrusted text with size/sanitization/profanity/URI limits.
6. No mandatory SaaS. External provider missing/paid service declined returns explicit fallback only if **secure local self-host profile is properly configured**, never public guest bypass. Direct local loopback test mode not accepted on untrusted/public interface.
7. Admin actions require separate privileged capabilities; no generic MCP "join as player", issue magic session, deploy paid GameLift/PlayFab or upload keys. Token/PII retention and deletion policy versioned.
