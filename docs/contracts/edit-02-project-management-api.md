## 2. Proposed semantic operations (all NOT IMPLEMENTED)
- `ListProjectTemplates` / `InspectProjectTemplate`: show original offline template versions/digests/licenses without fetching or executing. `ValidateCreateIntent`: names/path/root user capability/compatibility, zero side effects. `PreviewProjectCreation`: immutable plan with expected file hashes/space/accessibility errors, not a permanent project.
- `StageProjectCreation` creates a private sibling staging root only with validated DATA-01 handle (future) after explicit user consent; `ValidateStagedProject` verifies schema/asset refs/permissions, no hidden package scripts, bounded file bytes. `CommitStagedProject` checks absent destination, same volume/atomicity capability and stage hash, performs supported flush/rename and returns proof. Invalid/out-of-date idempotency => typed CONFLICT, not overwrite. `AbortOrQuarantineStage` never deletes an existing valid project.
- `OpenProjectReadOnly` and `AcquireProjectWriterLease` distinguish inspection from mutation. `OpenProjectWritable` checks source CAS/lease/perms; a second window cannot silently create split-brain. `ValidateProjectGraph` requests DATA-02 and DATA-04 owners for refs/schema and GFX/Web for capability profiles.
- `PlanProjectMigration` / `PreviewMigrationSemanticDiff` / `StageMigrationBackup` / `ValidateMigratedProject` / `CommitMigration` / `RollbackOrRollForwardMigration`: requires explicit approved steps/backup and permission, never auto upgrade on open or destructive downgrade.
- `InspectProjectArchive` / `ImportVettedProject` / `ExportSourceSnapshot` validate nested sizes/link/path and third-party licenses before action; imported foreign engine format needs separate converter ADR, default DENY/UNSUPPORTED.
- `RegisterProjectRecentEntry` delegates UI to EDIT-01 and safe stored reference to DATA-04, not canonical project state. `InvokeProjectOperationFromMCP` same semantic permissions/preview/CAS/audit and user approval as manual UI.

## 3. Failure, compatibility, data safety invariants
1. No project appears VALID unless **complete committed descriptor and required source hashes** verified. Crash before commit leaves quarantine/recoverable stage, never partial target treated as valid; existing target never overwritten.
2. Path authority from **DATA-01 rooted handle**, not user path string or `realpath` check followed by reopening. Reject symlink/junction/reparse/hardlink/ADS/UNC/drive traversal and archive escape according to OS policy, fail closed on unsupported secure primitives.
3. Stable ProjectId and DATA-02 AssetId never derived from path. Move/rename and clone semantics preserve or explicitly remap refs, no silent lost deps. Scene schema transforms belong DATA-04.
4. Distinguish process crash, power loss and remote/network filesystem durability; flush and same-volume rename guarantees only where validated. SQLite WAL local-host only and synchronous=NORMAL durability caveat; do not promise ACID for entire project tree.
5. Migration only with last-known-good backup, semantic diff, approved version edges and checksums. Unsupported newer schema => READ_ONLY/UNSUPPORTED, no silent downgrade or lost optional fields.
6. No side effects from **preview/validate**, and untrusted templates/imports cannot execute scripts, network fetch or read outside authorized roots.
7. UI/CLI/MCP parity on typed public permission checks; create requires user root grant; delete/export/private dependency URLs/paid actions need separate explicit approval.
8. Actual feature support for modes 2D/2.5D/3D/Web must be checked against GFX/WORLD/TWO/Web capabilities; declaring WEB mode does not produce a working Web export.
9. Logs and recent list hide full private paths and project secrets from unauthorized actors; no parser error leaks local filesystem user info.
10. **No runtime exists at P00**. Error result and audit claims require future runnable tests and the 128 E02 scenarios.
