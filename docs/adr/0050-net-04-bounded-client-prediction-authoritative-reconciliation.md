# ADR-0050 — Bounded owner prediction and authoritative client correction; server rewind opt-in and read-only

**Status: PROPOSED / NOT OWNER-APPROVED / NOT ADOPTED**, 2026-11-15. Research [#240](https://github.com/KayzenRoot/stormline/issues/240) | WO NLE-P00-WO-002-NET-04 | coding [#65](https://github.com/KayzenRoot/stormline/issues/65) OPEN/BLOCKED. Engine code license NLE-D009 OPEN.

## Context
Stormline aims for responsive multiplayer without trusting arbitrary client state. Formal prereqs NET-03 snapshots and SIM-03 movement are researched only. NET-02 owns authoritative server simulation; CORE-04 owns TickId; GAME-04 owns authoritative effects; NET-03 owns secure visibility-filtered client snapshots; NET-01 owns secure delivery. Network latency and snapshot jitter create a perception delay; per-client prediction can hide the delay but must be corrected on server state. Unity Netcode for Entities [prediction](https://docs.unity.cn/Packages/com.unity.netcode%401.5/manual/intro-to-prediction.html) shows selective rollback/resimulated ticks and heavy CPU; [edge cases](https://docs.unity.cn/Packages/com.unity.netcode%401.5/manual/prediction-details.html) describe partial snapshot and predicted spawn hazards. [Interpolation](https://docs.unity.cn/Packages/com.unity.netcode%401.5/manual/interpolation.html) deliberately delays remote actors to smooth jitter. Valve Source SDK has a **restricted** license, not reusable as MIT.

## Proposed decision
1. **Predict only explicitly authorized local owner movement subset first**, with canonical SIM-03 motor replay at CORE-04 fixed tick, a bounded immutable per-client input+predicted-history ring and server-authenticated `lastProcessedInput` cursor in NET-03's authorized snapshot. Apply server correction to sandboxed local predicted state and replay only still-pending inputs up to **bounded CPU/tick/memory**. Server never accepts predicted state/hit outcomes as truth. Collision dependency cohort completeness must be verified; otherwise gracefully disable prediction for that actor/mode.
2. **Remote actors interpolate authorized NET-03 snapshots** on an adaptive but bounded delay timeline. Uncertain/out-of-order/jitter/loss -> hold/slow correction; extrapolate only bounded and permitted, stop at timeout. Separate predicted gameplay physics from visual smoothing transform/camera so a cosmetic correction cannot affect hitbox, collision or server authority.
3. **Clock mapping is approximate**: server authenticates TickId; NET-01 provides monotonic latency/RTT signals; client maintains bounded slew time estimator with uncertainty. Client-supplied offset, one-way delay, age or TickId is never authoritative.
4. **Gameplay side effects are not replayed:** speculative client abilities/VFX are idempotent visual previews only, actual combat/loot/quest/score and storage only GAME-04/NET-02 server commits. Ignore duplicate event replay and corrected predicted spawns until canonical server identity arrives.
5. **Server historical lag-comp is optional, disabled initially.** If game-specific owner approval occurs, perform bounded read-only collider/hitbox rewind query using server-stored world history and clamped server-derived client command age, apply validated hit at current TickId via GAME-04. No global rollback/rewind of WORLD-01, durable DATA-04 checkpoints, purchases, loot, inventory or irreversible side effects. Fairness policy/RRT classes evidence required before enabling.
6. **No third-party game/SDK source or runtime adopted by this decision draft**, and no fixed tick/hz, RTT, rewind window, correction threshold, supported player count or SLA asserted before benchmarks/owner DoD. Client/server cross-platform deterministic bit equality not assumed.

## Alternatives considered
| Strategy | Benefit | Failure/cost / disposition |
|---|---|---|
| Pure server only, no prediction | secure simple source of truth | input-to-feedback RTT delay, acceptable for some strategy/casual modes; **supported fallback** |
| Client authoritative movement/hits | instant response | exploits, divergent inventory and teleport, invalid security model; **reject** |
| Predict every remote physics object | local smooth contacts | partial snapshots/different contact groups, high resim CPU, leaks hidden object data; **defer** |
| Interpolate all including owner | inexpensive, stable | owner input lag and perceived sluggishness; fallback in unsupported platforms |
| Bounded owner-only prediction+correction | responsive local controller, single authority, bounded proof surface | complexity of replay/scene asset consistency/smoothing; **leading proposal** |
| Rewind full server world for late input | historical global consistency in some deterministic turn games | retroactive irreversible economy/quest, fairness/split-brain, huge CPU; **reject baseline** |
| Bounded read-only hitbox historical query | optional fairness assistance for hitscan | abuse/peeker advantage, moving geometry ambiguity, memory; opt-in separate policy/benchmark |
| Lockstep deterministic across platforms | low bandwidth, synced simulation | cross-CPU float nondeterminism and lost inputs stall; game-specific FUTURE, not generic v1 |

## Security, performance and acceptance gates
**Authority:** NET-02 session/actor ownership/rule checks, GAME-04 receipts, NET-06 clamp and ban/abuse; no cheating by changing clock/snapshot/sequence. **Correctness:** replay consistency per pinned toolchain/physics config, bounded history/clock/CPU, safe reset on stale epoch and partial collision cohort, no speculative reward duplication or hidden data. **Fairness:** RTT bucket comparisons of peek/hit, victim experience and approved max server rewind window, no game-mode assumption. **License/IP:** no UE/Unity/Valve code copy, no implicit license compatibility, source package file-level and exports to be approved. **Evidence:** future 128 tests + real native/Web server-client and impairment benchmarks, comparator acceptance based on owner thresholds. HIGH/CRITICAL trust or durability defects BLOCKED. Merging this research does **not** approve a backend, game timing algorithm or coding. All 80 code packets remain BLOCKED.
