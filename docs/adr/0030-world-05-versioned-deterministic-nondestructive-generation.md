# ADR-0030 — Versioned Deterministic Procedural Graph and Non-Destructive Regeneration

**Status: PROPOSED / NOT APPROVED FOR CODE**  
**Date:** 2026-11-14 | Research #171 | WO NLE-P00-WO-002-WORLD-05 | Future implementation issue #45 OPEN/BLOCKED.

## Context
The catalog demands that the same seed and version produce identical procedural results and preserve manual edits. A global RNG or compiler-dependent floating point breaks this guarantee under job scheduling, negative cell coordinates, CPU vs browser/WebGPU, graph edits and version upgrades. A generator that directly rewrites artists' patches/scene graphs can irreversibly delete work. Reusing a proprietary PCG engine violates portable original-engine boundaries; unconstrained WFC and untrusted graph scripts are potential denial-of-service and arbitrary code execution.

## PROPOSED decision
1. **Pure, typed, bounded generator DAG** with stable GraphGuid/NodeGuid, AlgorithmId+Version, explicit typed ports, units, global coordinate and output schemas, dependency asset hashes, source and manually authored input version. Graph cycles prohibited; bounded iterative solvers isolated as one node with limits, type-check and rights-check before work.
2. **Canonical determinism identity** is \`MasterSeed128 + graph/node/algorithm/schema versions + asset/source hashes + numeric/precision encoding + global region/patch/cell and sample/element key\`. Domain-separated counter/keyed seed generation, fixed global coordinates, stable serialization and tie-breaks independent of evaluation order/number of workers. Avoid ambient RNG, nondeterministic containers, fast-math drift, undefined integer overflow and local-cell edge discrepancies. Only assert actual cross-platform equality after golden binary output tests; GPU shader preview **noncanonical** unless proven byte-identical.
3. **Generator emits immutable proposals** with stable source-independent item IDs and recipe fingerprint, not side-effecting ECS/asset writer. WORLD-04/02 source authoring owners and DATA-04 source journal/CAS decide what to accept; DATA-05 owns cook/cache and WORLD-03 streaming, CORE-06 jobs; GFX/PHYS/GAME/NET own runtime/render/authority. Treat this as own small module, not duplicate a Blender/Houdini/Unreal application.
4. **Artisan overlay is preserved**: source generated base old vs newly proposed base plus manual artist overrides in DATA-04. Propagate unmodified generated fields only. Preserve manual sculpt/paint/biome/placement, deleted generator objects via tombstones, and manually added objects. Deleted/changed generated item that has manual edits becomes an explicit orphan/conflict with preview/choices; never silent merge, overwrite or reimport restore. Transaction receipts and undo/redo owned DATA-04.
5. **Version change is explicit**: graph, library algorithm, numeric profile, port schema, source AssetId/hash, seed or scope changes recipe fingerprint. No silent “same seed” compatibility across algorithm upgrades. Migration maps stable IDs and changed version with authenticated source/cook rights, old golden hash and author approval before publishing.
6. **Cell seams and region solvers**: neighborhood halos/sample coordinates global and stable across WORLD-03 cell origin/stream order; wide rivers/roads/WFC global constraints must use declared bounded region scope and deterministic shared solution, not falsely independent per-cell generation. Empty/contradictory result is typed failure, not a loop.
7. **Security and resource caps**: graph max nodes/edges/cycles, input graph AssetIds, no plugin script or arbitrary external file/URL from MCP/graph, max region+halo, WFC steps/retries and output geometry/entities/memory/time, DATA-03 import validation, DATA-02 ownership and capability. Preview never performs source/live mutation.
8. **Ownership:** WORLD-05 controls deterministic pure generation only. WORLD-04 authored biome/terrain/foliage and geometry hints; WORLD-02 prefab/scene edits; WORLD-03 streaming; DATA-04 persistence/undo; DATA-05 cache/cook; GFX shader/graphics; GAME/NET PHYS authoritative state. Headless CPU reference mandatory for future test, GPU source only after proof.
9. **SCDI incremental deterministic dependency invalidation optional PROVE-OR-DROP**; compare full recompute oracle after arbitrary edits, source/cell/halo/invalidation; discard if wrong/complex or p99 and memory cost too high. No superiority/novelty claim.
10. **No coding authorization**. Future WORLD-05 code depends on merged audited WORLD-04 + DATA-03 coding, 1.0 Scope/DoD and owner-APPROVED ADR, actual raw-byte SHA-256 Context Lock and compiler/hardware proof, licenses/SBOM. All 80 coding WOs BLOCKED/executor_ready=false; ADR-0030 remains PROPOSED and CORE-04 historic research gap unresolved.

## Rejected unconditional defaults
Global \`rand()\` or default std RNG shared over threads, floating timestamp/clock seed, CPU/GPU floats claimed equal without tests, WFC assumed to always terminate successfully, hidden arbitrary script node/embedded Python execution, generator directly overwrites artist's terrain layers, deletion resurrects generated objects, implicit cross-cell indexing that changes seed at borders, copying Unreal/SideFX licensed plugin code/assets, and keeping old cache after algorithm/source changed.

## Future independent proof obligations, NOT EXECUTED
CPU byte exact golden source recipe and stable IDs across Windows/Linux/macOS/WASM at identical version and compiler-prescribed numeric profile; scheduling and cell order invariance, negative world/halo boundaries, WFC contradiction bounded deterministically; clear manual overlay/three-way conflict and source crash/undo/redo; hostile graphs/permissions/resources, real streaming/PHYS/GFX integration and actual CPU p95/p99/memory. No runnable engine exists today.
