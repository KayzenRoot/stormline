# ADR-0082 — Signed Immutable Release Lifecycle, TUF-Grade Trust and Data-Safe Rollback

**STATUS: PROPOSED / NOT OWNER-APPROVED / NOT IMPLEMENTED / NO RELEASE AUTHORIZATION.** 2026-11-16 · BIZ-03 research [#370](https://github.com/KayzenRoot/stormline/issues/370), coding #97 OPEN/BLOCKED, source `3d2ad393ab4b70460e7d5cb46f82e03d2f5c9935`. Catalog `catalog_order=79` zero-based (80th of 80), only formal deps **PLAT-05 + BIZ-01 + QA-04**; upstream ADR-0074/0080/0078 all PROPOSED. NLE-D009 engine license OPEN, NLE-D013 public MVP prohibited until full v1.0 DoD.

## Context
A tested exported binary is not necessarily signed, licensed, installable, roll-back-safe or suitable for unsupported hardware. App installer updates, signed release feeds and project/save migrations must remain independent layers; unattended updates cannot take irrevocable control of creator projects. Apple Developer ID/notary, Windows signing/Store and Linux package-manager signatures have distinct qualification and possible costs. Public GitHub artifact attestations can support provenance for actual future artifacts but **do not sign the installer as trusted OS vendor, issue distribution rights or prove SLSA level by mere presence**.

## Proposed policy clauses
1. **Formal dependencies are PLAT-05 + BIZ-01 + QA-04 EXACTLY**, no extra DAG edges; PLAT-05 owns exporting immutable per-target payloads, BIZ-01 rights/licensing/consent, QA-04 real security evidence. BIZ-03 owns *publication, installer, updater, rollback, maintenance lifecycle* and consumes owner receipts.
2. **Immutable release identity** `ReleaseId/ChannelRevision/ArtifactDigest/TargetProfile/CompatSchema`, versioned manifest and state machine from draft to owner-approved channel. Git tag, build SHA, notarized binary, OS signing/identity, SPDX/SBOM and release URL are DISTINCT linked objects with separate cryptographic hashes.
3. **Secure update trust model** inspired by The Update Framework (TUF): offline/root trust with thresholds and rotation, delegated target scopes, timestamp/snapshot consistency/expiry anti-freeze, per-target hash+size, monotonic versions, approved channel and signed policy; **proposal**, not certified TUF client. Compromised mirror must not install arbitrary payload. Signing roots inaccessible to untrusted CI jobs/LLM/plugin.
4. **Platform-native packaging preferred where qualified**: Windows MSIX Store vs independently trusted sideload or MSI/EXE, macOS Developer ID notarized app/DMG/PKG with distinct App Store pipeline, Linux Flatpak/AppImage/DEB/RPM selected by supported distribution/updates, browser immutable manifest + service worker/cache activation, never native installer. Every platform profile has an explicitly supported installer/update authority and min supported OS/architecture.
5. **Transactional update** staged verified payload, journal/last-known-good, fsync/atomic where actual OS guarantees permit, safe reboot/health-check and recovery receipts. Do not promise cross-volume atomicity or OS-managed rollback when package manager transaction does not support it.
6. **Project and save migration is separate from app binary rollback.** DATA-04/schema owner controls source document migration; BIZ-03 invokes preview/backup/validate/commit/readback only. Incompatible schema down-migration fails closed with recovery instructions and retains last-good independent backup; never overwrite/delete user originals in silent updater.
7. **Supply-chain gate**: actual artifact file digest, pinned toolchain/source, verifiable SLSA v1.2 provenance/in-toto and trustworthy builder, SBOM SPDX3 or CycloneDX1.7, exact third-party code/asset/font/SDK/plugin notices, vuln scans and BIZ-01 owner-reviewed redistributable rights; no SLSA L2/L3 claim without satisfying definition and verification.
8. **Signing/notarization separate cost and trust gate**: Apple paid Developer Program/Developer ID eligibility, signing certificates and hosted notarization, Microsoft Store/sideload Authenticode account and Linux repository keys require explicit owner approval; never insert secrets in docs, unrestricted PR actions or GitHub public artifacts. Use zero-paid docs CI now, future release artifacts gated if cost/support unsupported.
9. **Channels and kill-switch:** INTERNAL only under current NLE-D013. Beta/stable/public never automatically activate from successful CI. Owner approval, security and product DoD, staged cohorts with falsifiable health checks, signed revocation/pause, incident response and key rotation; rollback authorized via *new signed channel revision* (not anti-rollback bypass).
10. **Crash telemetry/maintenance privacy:** OFF by default, granular purpose-specific informed opt-in, scrubbing stack/project paths/credentials, pseudonymous minimal retention, deletion/export/consent withdrawal and LGPD/GDPR legal review. Unknown legal basis or cross-border upload = disabled. Internal crash dump needs explicit local permission; support escalation must not collect assets by default.
11. **Accessibility and UX:** installer/uninstaller/repair keyboard and screen reader usable, actionable offline/permission/error messages, localized UI, clearly display source, hash, version, disk needs, channel and rollback consequences. Avoid auto-run/hidden network service, bundling unrelated software, destructive uninstall or privileged updater by default.
12. **Research ≠ implementation:** exactly eight added markdown, 128 `B03-T001..T128` future cases NOT_EXECUTED, zero PASS, ADR-0082 stays PROPOSED, all 80 implementation WOs BLOCKED, engine license NLE-D009 OPEN, 0 public binaries/notary signatures/real os compatibility tests, no package release.

## Options considered and consequences
| Option | Benefit | Why not universal default |
|---|---|---|
| HTTPS latest.json + SHA256 next to payload | simple | **REJECTED** authenticating compromised feed, no threshold/expiry/freeze resistance |
| TUF trust root with delegated targets and roles | robust updates and key rotation | **PROPOSED** with hard multi-target/backend verification and key custody cost |
| OS Store-only update | native auth + transactional logic | not available/optimal for every target and some stores prohibit external updater |
| Bundled custom updater for all platforms | uniform UX | ownership conflicts with OS package manager and platform signing/permission boundaries |
| Full installers only | simple repair | bandwidth, incremental rollout, user expectations; delta an optimization after full path safe |
| Binary delta patch-only | bandwidth | expensive failure recovery; full payload fallback mandatory, validate post-patch artifact digest |
| No telemetry | maximum local privacy | acceptable baseline; opt-in future limited diagnostics only with lawful basis |
| Forced save migration | simpler uptake | unacceptable creator data loss and rollback incompatibility |
| Auto public nightly | rapid feedback | directly contradicts NLE-D013 no public MVP |
| Sparkle/Flatpak/MSIX direct adoption now | established tooling | OS/product rights/credentials/CI/hardware and update model still unsettled |

## Proof obligations and unresolved owner decisions
Which licensed engine/runtime redistribution, release_class and complete 1.0 DoD, signed channel root/threshold/custody/recovery, Windows Store vs sideload, Linux supported distributions and update provider, Apple Developer ID/notarization funding/qualifications, browser service worker/cache and CDN control, project backup retention, operational support SLA, privacy policy and consent model, exact CI minutes/storage/runners physical hardware QA-05, full/delta rollback or migration offline tests, release versioning and revocation incident drill. No signing credentials, actual users, real build, permission to release or legal conclusion.
