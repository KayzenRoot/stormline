# ADR-0044 — Stormline-Owned Accessible UI Semantic Tree and Unicode Text Pipeline

**STATUS: PROPOSED / NOT APPROVED FOR CODE**  
**Date:** 2026-11-15 | **Research #216** | **WO:** NLE-P00-WO-002-GAME-03 | Future code issue #59 OPEN/BLOCKED

## Problem
The Stormline engine needs fast and beautiful responsive game UI/HUD across desktop and future Web without losing globalized text quality, gamepad/keyboard/pointer navigation, user focus, privacy or accessible alternatives. GFX-07 owns display/color/camera; TWO-01 owns the Canvas/glyph draws; GAME-01 owns input device/action frames; GAME-02 owns scripting API/game action intents. Importing a big UI toolkit or making a new renderer independently can duplicate these responsibilities, leak trust and create inaccessible focus models. Libraries and actual font binaries have different licenses.

## Proposed decision
1. **Single Stormline-owned `UiTreeV1` and typed widget/locale/accessibility model**. Public API is vendor-neutral, with stable ProjectId/UiDocumentId/NodeId/generation and source/data revisions; no RmlUi/Yoga/SDL/GPU native types or arbitrary HTML/JS in game scripts.
2. **One layout engine selected by proofs**, not two mandatory solutions. Evaluate **Yoga MIT** as a focused flex calculator suitable for owned widget and style model; **RmlUi MIT** as full markup/style/widget alternative requiring strict host API/unsafe script restriction and potentially conflicting retained-tree/focus scope. Evaluate minimal first-party constraint layout as reference; **do not adopt** until CPU/performance/accessibility/portability/maintenance evidence.
3. **Unicode-correct text through a versioned pipeline**: Unicode 18 UAX#29 graphemes, UAX#9 bidi, UAX#14 line-break; HarfBuzz (Old MIT with file-specific notices) shaping candidate, FreeType (choose FTL or GPLv2) rasterization/hinting candidate, explicit font fallback and per-cluster script/feature/variable-axis shaping, not raw UTF-8 codepoint-to-glyph quads. HarfBuzz new raster/GPU paths are optional comparators, no untested assumption of hinting. No universal glyph coverage claim.
4. **GFX-07/TWO-01 single presentation truth**: GAME-03 owns text/layout/glyph run proposal, focus geometry, semantic tree; TWO-01 alone owns glyph draw/atlas/clip/painter order; GFX-07 alone owns unjittered overlay projection and SDR/HDR color/paper-white/post order. No second GPU allocator, font atlas manager or display pipeline. Actual atlas/device resources must be generation/fence checked; UI no TAA jitter/double gamma.
5. **Globalization via explicit locale/versioned catalog**: BCP-47 locale, ICU79.1 Unicode-3.0 library and CLDR49 data reference, plural/number/date/unit formatting and controlled fallback; Unicode MessageFormat 2 is a stable CLDR spec but ICU79 C++/Java implementations still partly technology preview. Adopt no MF2 runtime until target APIs proven. DATA-02/03/04/05 owns catalog font rights/import/source CAS/cook.
6. **Untrusted interpolation is non-executable**: typed placeholders, bounded rich text span allowlist, bidi-isolated user labels, invisible-control/confusable-safe security policy, no translator-defined script/URL/native API, font file or arbitrary markup injection. Preserve legitimate Arabic/Hebrew/Indic without stripping meaningful characters. No dynamic font/network fetch by default.
7. **GAME-01 device routing and UI focus separated**: GAME-01 emits action frames/IME host events; GAME-03 resolves actual `UiFocusTreeV1`, focus/selection/caret, keyboard/gamepad/TV spatial navigation, touch/pointer clip hit-test, modal/Back/Cancel recovery and focus route returned to GAME-01. No second device input pump or game authority.
8. **Accessibility-first semantics**: role/name/state/value, logical reading order, user text scale, focus visible, reduced motion/contrast controls, alternative pointer/keyboard methods, subtitle/caption text from AUD-04, platform accessibility bridge as separate feasibility proof. WCAG 2.2 is design guidance; no screen-reader, native OS assistive technology or certification claim before real user/device testing.
9. **Bindings and UI actions are capability-scoped**: UI reads authorized immutable snapshot data and emits typed GAME-02/GAME/NET action intents; it does not execute arbitrary script/eval, gain game mutation authority, leak private player data, or let MCP bypass DATA-04 validated authoring.
10. **Security, quotas and lifecycle**: bounded node/depth/style cycles/text/atlas/clip/reflow and virtualized long lists; reject stale generations/window/viewport/locale/font revisions, safe fallback under source/GPU device loss, no unconsented content logging; no RT audio blocking or tick determinism assumption for presentation animation.
11. **License and proof gate**: Yoga and RmlUi MIT; HarfBuzz Old MIT with file-specific exceptions, FreeType FTL credit-clause or GPLv2 dual-license, ICU/CLDR Unicode-3.0 with additional bundled notices, Noto fonts SIL OFL 1.1 per font, msdfgen MIT optional, Skia BSD-3 optional comparator; license of engine NLE-D009 OPEN. NO library or font asset adopted or version pinned. Require correct native/Web/headless target, royalty/attribution, font embedding/subset/derivative naming, security and visual/accessibility tests before decisions.

## Alternatives and risks
- Custom widget, layout, text shaping and raster from scratch with no Unicode test suite: rejected as first assumption for quality and security.
- Adopt full RmlUi and Yoga simultaneously as competing layout/focus owners: not justified.
- Direct ASCII/UTF-8 codepoint glyph rendering with no grapheme/bidi/shaping/IME: inadequate for internationalization.
- GPU MSDF for every type/size including tiny text and color emoji, with no actual raster tests: performance/quality claim unsupported.
- Build HUD inside GFX-07 post or TWO-01 Sprite Canvas, coupling UI semantics to renderer: duplicates ownership and breaks testability.
- Reuse app's HTML/CSS/JS or arbitrary translator-supplied markup with native/script execution: unsafe.
- Claim WCAG certification and complete OS screen reader support on unbuilt UI: unsupported.

## Consequences and gate
Pros: portable game UI semantic core, renderer-independent layout, one keyboard/gamepad focus tree, safe localization and measurable typography quality. Costs: Unicode/font/shaping/font subset asset-rights diligence, hard bidi/IME/RTL/line-wrap tests, layout invalidation and GPU cache management, platform accessibility integration. Research LOW risk; future runtime ELEVATED for untrusted font/UI parsing and accessiblity/privacy. **No code, test, font, executable, benchmark or third-party library has been installed. ADR remains PROPOSED; all 80 future coding packets blocked; issue #59 OPEN/BLOCKED.**
