## Context and problem
Windows, Linux, macOS and Web exports have different ABIs, capabilities, distribution credentials and sandbox contracts. Source and cooked assets may be unchanged while compilers, timestamps, linkers, archive order, installers and signing tickets vary. A naive “build succeeded” status confuses **code correctness**, **reproducibility**, **provenance**, **authenticity**, **store review** and **permission to publish**, risking corrupting last-good projects or releasing unlicensed/notarized-as-debug binaries. Stormline 1.0 forbids any public MVP until full DoD approved.

## Proposed decisions (subject to owner ratification)
1. **Exactly five formal catalog predecessors** **PLAT-01 + PLAT-02 + PLAT-03 + PLAT-06 + DATA-05**. Their ADR-0069/0070/0071/0072/0013 only PROPOSED. Other QA-01/QA-04, CORE-01, AI, GFX/GAME, BIZ-03, UI, PLAT-04 mobile, NET/CDN are **integration owners, not additional formal edges**. PLAT-05 implements export pipeline; **BIZ-03 alone** owns installer/publication/update/rollback user lifecycle. DATA-05 owns cooking/chunk/patch primitives; PLAT-05 consumes verified immutable outputs, never edits author source or redefines cooking.
2. **Typed target profile and immutable artifact generation graph**: source asset revision -> approved target/feature profile -> pinned toolchain and export template -> DATA-05 cook manifests -> normalized unsigned stage -> verified payload digest/SBOM -> security/license checks -> optional platform signing/notary/Store candidate -> final signed digest/attestation -> owner-gated channel/staged release for BIZ-03. Exact transition/actor, inputs/outputs, platform/arch/min OS/headers, errors, fingerprints and rollback receipt; no shell execution from untrusted project or model agent.
3. **Reproducible core payload, not magically bit-identical signed output**. Prefer pinned C++20 CMake presets/Ninja/native SDK and Emscripten toolchains, deterministic locale/timezone/SOURCE_DATE_EPOCH/archive entry order and prefix mappings. Compare independent unsigned builds under declared identical input and environment; carve out platform-specific nondeterministic elements and document them, especially external certificates/notary timestamps/store re-signing. Final signatures, notarization and attestations are separate derived artifacts and hashes; require trust verification rather than asserting binary equality after signing.
4. **OS-specific paths conditional by recipient and distribution channel**: Windows MSIX requiring trusted signature and Microsoft Store/CA alternative, Linux portable tar vs AppImage vs Flatpak sandbox/portal/OSTree, macOS arm64 and conditionally universal2 with Developer ID hardened runtime/notarytool vs App Store, Web Wasm+JS/workers/assets immutable release manifest/HTTP secure headers/CSP/cross-origin isolation. Do not enable signing, paid identity or store submission automatically. Mobile exports only after separate owner approval of PLAT-04, with **no new formal DAG dependency**.
5. **Supply-chain minimum**: machine-readable SPDX3 or CycloneDX1.7 candidate SBOM with exact package+font/assets/SDK/license/notice provenance; source/toolchain/cook/payload/final artifact SHA-256; [SLSA v1.2 provenance](https://slsa.dev/spec/v1.2/build-provenance) as in-toto Statement v1 with predicateType `https://slsa.dev/provenance/v1`; optional [GitHub artifact attestation](https://docs.github.com/en/actions/how-tos/secure-your-work/use-artifact-attestations/use-artifact-attestations) tied to trusted job/head and verification result. SBOM/provenance existence does **not** prove L2/L3, legality, benign content or successful runtime.
6. **No unapproved privileged build execution**: build runner sandbox with low privileges, hermetic-ish dependency fetch with exact digests/allowlist, isolated input mounts, bounded output paths, content scanning, no arbitrary post-build scripts/URLs in projects, AI/MCP capability gating, no credentials on PR code, no unchecked shell flags, no auto-publishing. Private signing keys/paid accounts stay inaccessible until owner security authorization and HIGH_ASSURANCE review.
7. **Versioned release, downgrade/rollback and last-good**: artifact IDs/content hash and immutable channel pointers; no in-place update of authored project and no multi-file “atomic” claim where filesystem cannot guarantee. BIZ-03 rolls out after policy, controlled staging, checksum+signature and platform permission tests, restart or session drain, journal of previous active generation, crash/power-loss recovery, anti-replay/version monotonicity with signed audited rollback exceptions. Security incident/compromised signer denylist and roll-forward policy; browser service worker/cache/HTTP CDNs use origin-specific generation swaps and eventual consistency, not file rename.
8. **Release class and source code license remain undecided**, no public MVP until 1.0 DoD. Internal unsigned/private smoke exports permitted only in later approved code scope, never represent CA-signed, notarized, App-Store-approved or secure due to Docs CI. All 80 code packets remain BLOCKED, executor_ready=0, approved_adr=0, engine=false.
9. Catalog accept requires **actual reproducible exports of approved applications**, typed errors by target, real clean host smoke, device/OS/ABI/feature conformance, privacy/accessibility, source/data integrity, SBOM/rights, owner release decision and 128 actual future tests with measured benchmarks; P00 research alone is insufficient.
10. Freeze exact tools/versions/licensing, supported OS/browser, release channel, publisher IDs, signing/notarization account fees and thresholds only after further ADR approval and evidence, preserving user control for expenses/HIGH/CRITICAL actions.

## Considered alternatives, not default
| Alternative | Short-term benefit | Reason not automatically adopted |
|---|---|---|
| One generic `.zip` for all targets | easy staging | broken ABI, install permissions, Web headers, OS trust |
| Bit-identical signed apps across builders | simple claim | signing/notary timestamp/store re-sign non-determinism; compare normalized payload separately |
| Re-run DATA-05 cooking in packager | fewer APIs | violates DATA source-of-truth and deterministic cook receipts |
| Automatic “latest” dependencies | faster updates | hidden supply-chain drift/ABI/license and compromised mirror |
| Root/admin/sudo for install/build | fewer permission errors | unsafe; no source project elevation |
| Microsoft Azure Artifact Signing mandatory | convenient integration | geography/eligibility, recurring cost and owner approval unresolved |
| macOS ad-hoc/self-signed == notarized | cheap | wrong Developer ID/entitlements/Gatekeeper |
| Linux AppImage bundles all GPU libs | portability | can break host driver/ICD/dlopen ABI |
| Flatpak --filesystem=host by default | easy project access | sandbox privilege abuse, portals safer |
| Web Service Worker updates assets individually in place | immediate update | mixed app generation and infinite cache/partial fetch corruption |
| Signed hash list in same untrusted package | easy tamper check | lacks independent trust root, authenticity/provenance must be validated |
| SLSA L3 claim because GitHub attestation exists | marketing | Build L3 requires hardened builder guarantees, independently proved |
| Auto-publish on green docs CI | speed | no binary, license, owner security or full 1.0 DoD gate |
| Continuous forced silent updates | latest features | user project corruption, downgrade/security and store consent risk |
| Mobile required solely because PLAT-04 researched | platform reach | 1.0 mobile release class cost/Scope UNDECIDED |
