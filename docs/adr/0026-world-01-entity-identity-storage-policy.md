# ADR-0026 — Stable World Identities, Generational Handles and Deferred ECS Structural Transactions

**Status: PROPOSED / NOT APPROVED FOR ENGINE CODE**  
**Date 2026-11-14 | Research issue #159 | NLE-P00-WO-002-WORLD-01 | Future coding #41 OPEN/BLOCKED.**

## Context
Stormline plans first-class entity identity/component storage/lifecycle/queries and schema introspection for renderer, editor, gameplay and headless server. Entity references can become dangling/ABA after destroy/reuse, world unload and query relocation; high-performance storage layouts are in tension with safe structural changes and stable pointer assumptions. Durable scene source belongs to DATA-04 and hierarchy/prefabs belong to WORLD-02. All 80 coding WOs remain blocked; research status count at baseline 22 documented/58 pending, with old CORE-04 pending.

## PROPOSED decisions
1. **Separate stable persistent identity from ephemeral runtime handles.** `EntityGuidV1` under DATA-02 and DATA-04 is serialized; `EntityHandleV1` with `world_instance_epoch+slot+generation` is transient, validated on every unsafe boundary and **never** raw serialized/networked. Deleted generations and instance epochs invalidate all stale references; generation exhaustion retires slots, no wraparound/ABA. Exact widths and GUID format TBD.
2. One `WorldRegistryV1` owns all entity lifecycles/components per world instance. Runtime world creation, unload and clone increments epoch and resolves GUIDs; no module-specific ECS registries as separate authoritative worlds for the same scene. Data transforms and gameplay authority remain CORE/WORLD/PHYS/NET-owned.
3. **Typed, versioned ComponentSchema registry** with stable TypeId across compilers; checked construction/move/destruction/align, field constraints, portable explicit serialization via DATA-04 and migration. No raw C++ memory dumps, RTTI hash persistence, unsafe plugin dynamic code or direct scripts. Source-generated metadata portable baseline, C++26 reflection optional after OS/Web toolchain proof.
4. **Storage is an open benchmark decision:** compare archetype/chunked SoA and EnTT-style sparse sets, optionally per-component hybrid. Flecs MIT/EnTT MIT candidates, Bevy ECS MIT OR Apache-2 reference, Unity Entities proprietary design reference. No mandatory vendor library and public ABI independent of any library.
5. **Query/borrow safety and correctness:** immutable snapshots or generation/epoch scoped views, explicit read/write footprints, no raw component pointer retained across structural changes. Caching invalidated on membership/type changes; deterministic simulation queries optionally request stable ordering (with measured cost) while default iteration order unspecified.
6. **Deferred structural changes** via bounded per-worker `EntityCommandBufferV1` with world/tick/issuer/sequence IDs; CORE scheduler owns barrier, ECS validates and commits at declared safe boundaries, explicit conflict resolution and atomicity scope, no reentrant unbounded observer or chain of sync points. No false guarantee job completion order is deterministic.
7. **DATA-04 owns persistence/undo/redo and source revisions**, ECS publishes lifecycle receipts and maps persistent GUID ↔ runtime handles. Save→reload must preserve identities/schema and safely create fresh runtime handles; no separate world database, scene hierarchy, spatial or network authority in WORLD-01.
8. **Editor/CLI/MCP parity with least privilege:** allowlisted component types/fields, project/world scoped inspect/preview/edit staged transactions, expected revision/CAS/rollback, quota and audit. Network clients and untrusted AI commands cannot spoof game/server authority or mutate protected components.
9. **STLG temporal lifetime guard** OPTIONAL PROVE-OR-DROP versus basic generational handle validation, evaluated for real stale reference defect capture, no claim novel/fast/implemented.
10. **No implementation authorization:** code #41 OPEN/BLOCKED, 80 coding WOs `BLOCKED_PENDING_TECHNOLOGY_AND_CONTRACTS`, `executor_ready=false`, release class UNDECIDED, `approved_adr=null`. CORE-05 and DATA-04 code prerequisites not integrated. Historical CORE-04 research hole must be reconciled under own WO if dependency chain requires.

## Rejected defaults
One unversioned integer ID or GUID directly used as raw pointer in hot loops; serializing slot/generation or compiler `typeid`; storage choice based on vendor marketing; immediate structural mutation while iterating/parallel jobs; recursive ownership of scene hierarchy, physics or disk; exposing EnTT/Flecs structs in SDK; mandatory C++26 compiler fork or Rust FFI without evidence; silent handle generation wrap; allowing arbitrary untrusted reflection fields or schema code.
