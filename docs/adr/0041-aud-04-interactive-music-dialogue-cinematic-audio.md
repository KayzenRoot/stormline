# ADR-0041 — Engine-Owned Adaptive Music, Dialogue, Timed Text and Cinematic Audio Orchestration

**STATUS: PROPOSED / NOT APPROVED FOR CODE**  
2026-11-14 | Research issue #204 | WO NLE-P00-WO-002-AUD-04 | Future coding issue #55 OPEN/BLOCKED.

## Context
Stormline needs adaptive music, dialogue/VO, captions and localization, cinematic audio synchronization, accessibility profiles and dialogue ducking. Upstream AUD-01 owns audio device/sample clock/voice/buses/PCM; AUD-02 owns spatial/acoustic source; AUD-03 owns DSP graph/sidechain/parameter automation; TWO-03 owns authored sequence and rational timeline; CORE-04 owns simulation TickId. Current documents are conceptual only and none of these runtime modules is implemented.

## PROPOSED decision
1. **Unique authority by concern.** AUD-04 owns music transport/state decisions, dialogue/voice content resolution and priority, timed-text/locale policy, accessibility mix intent and cinematic audio cue orchestration. It does not own a device, PCM mixer, audio clock, DSP kernel, asset database, animation/cutscene timeline, gameplay state or decoder.
2. **AUD-01 sample clock is the live playback master.** All scheduled music, voice, captions and cinematic audio cues use \`AudioClockMapV1\`, \`DeviceEpoch\` and \`SampleFrameId\`; return requested/accepted/actual sample receipts. CORE-04 \`TickId\` is mapped rationally and is not an audio clock. TWO-03 sequence time remains rational and independent of GPU FPS. No wall-clock or render-frame scheduling and no false claim of physical audible onset.
3. **Hybrid adaptive score.** Combine horizontal resequencing and vertical synchronized stem layers. Author tempo/time-signature/loop/entry/exit/beat/bar markers and a transition matrix with explicit transition segments, stingers, crossfades, priority, quantization and fallback. Use deterministic seeded variation, state hysteresis/dwell and prefetch. A failed/late transition holds the last safe loop or authored fallback; no abrupt silence.
4. **Dialogue is data-driven but GAME-authorized.** Stable \`DialogueLineId\`, typed argument paths and default/fallback line resolve from a read-only authoritative GAME/QUEST context snapshot. Voice scheduler has bounded priorities/concurrency, explicit interruption/expiry and receipts. It cannot change game state, invent a missing line or synthesize a voice.
5. **Timed text is independent content.** One internal typed \`TimedTextCueV1\` supports subtitles, captions/SDH, non-speech sound cues, audio description and transcript tracks. WebVTT and TTML2 are optional import/export adapters; BCP-47 and Unicode CLDR guide locale identifiers and fallback. Keep voice, text, caption and audio-description localization status separate; never silently substitute another language.
6. **TWO-03 owns cinematic timeline.** AUD-04 supplies audio/voice/caption cue tracks and receipts. Live sync maps rational sequence time to AUD-01 sample frames; offline frame/audio schedules share a rational origin. Pause/seek/skip/loop/restart/device loss must define event cancellation, cue recomputation and epoch/dedup semantics. Authored viseme/phoneme markers are consumed by TWO-03, not implemented as a new animation engine.
7. **Ducking is split at clear ownership boundaries.** AUD-04 chooses when dialogue/AD should duck targets and its priority policy; AUD-03 supplies sidechain/ducking DSP node and bounded automation; AUD-01 applies the existing bus graph. User mix controls and snapshots compose deterministically. Critical gameplay cues are not silently ducked.
8. **Accessibility is a product capability, not a badge.** Include configurable captions/SDH, speaker and off-screen cues, audio-description track, independent dialogue/music/SFX/ambience/narration levels, mono-compatible fallback, optional reduced-dynamic-range profile and persistent text controls. WCAG 2.2 is a design reference only; no certification claim without target-specific test/audit.
9. **Middleware remains unselected.** FMOD 2.04 is a useful adaptive music/dialogue/localization/snapshot/profiling behavior reference, but its current EULA's free/limited commercial grant explicitly excludes distributing FMOD as part of a game engine/toolset; other commercial use requires a separate license. Wwise's consulted July 2024 SDK Agreement grants plugin-application rights, not a general Wwise runtime embedding license. Obtain and review the separate current runtime agreement before any commercial integration. Godot AudioStreamInteractive (MIT engine) is a transition-table reference only. OpenTimelineIO Apache-2.0 is optional editorial interchange, not runtime timeline ownership. No dependency or middleware is adopted.
10. **Content rights are independent from code licenses.** Track composition, master recording, performers/voice likeness, music stems, sample libraries, translations, subtitle/SDH and synthetic content rights at AssetId/revision level. No voice cloning, TTS, microphone capture or cloud voice upload in baseline. Engine license NLE-D009 remains OPEN.
11. **Security and boundedness.** Untrusted audio/timed-text enters DATA-03/05 validation; no host path/URL, script, unbounded XML/markup/cue/event, hidden gameplay context or arbitrary plugin. Safe text rendering, XML external-entity prohibition, quotas, actor roles, source rights and privacy redaction are mandatory.
12. **Proof before claims.** 128 future test scenarios and reproducible sync/audio quality/CPU/memory/streaming/locale/accessibility benchmarks are defined, not executed. "No glitches", sample-accurate, platform parity, intelligibility, zero underruns or perfect accessibility require measured runtime and content evidence.

## Alternatives rejected
- Embed FMOD or Wwise as a required Stormline engine runtime based on a free game/plug-in license.
- Create an AUD-04 master mixer, sample clock, DSP graph, voice allocator, decoder or new timeline instead of reusing AUD-01/03/TWO-03.
- Schedule music and captions from game TickId, wall time or variable render FPS.
- Use only one subtitle string as a substitute for subtitles, SDH captions, audio description and transcript.
- Automatically fall back to a different language, AI voice, generic dialogue or silent cutscene when an asset is missing.
- Let cutscene/audio callbacks mutate authoritative gameplay state or execute arbitrary scripts.
- Apply ducking in two independent modules, hide critical gameplay cues or use a compressor/limiter as a substitute for explicit user accessibility settings.
- Claim WCAG conformance or zero-glitch audio from a document/CI-only check.

## Consequences and approval gate
Stormline must own versioned music/voice/timed-text/locale/sequence cue semantics, deterministic rational/sample scheduling, receipts, safe fallbacks and integration adapters. This adds content-authoring, localization, rights and sync verification work but avoids vendor lock-in and duplicate runtime ownership. Before any code, require implemented/approved AUD-01/02/03 and TWO-03 contracts, a release slice and numerical budgets, exact middleware/license decision (or first-party baseline), original legally cleared music/VO/SDH/IR test fixtures, data/asset schemas, accessibility target matrix, and objective audit.
**ADR-0041 is PROPOSED. No middleware, codec, DCC adapter, audio content or runtime is approved or installed. Future implementation #55 remains OPEN/BLOCKED; all 80 implementation packets remain BLOCKED.**
