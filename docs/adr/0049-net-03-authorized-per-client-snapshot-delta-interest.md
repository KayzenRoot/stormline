# ADR-0049 — Authorized per-recipient replication projection, interest graph and acknowledged delta snapshots

**Status PROPOSED / NOT APPROVED / NOT ADOPTED** | 2026-11-15 | research #236 | WO NLE-P00-WO-002-NET-03 | coding issue #64 OPEN/BLOCKED | baseline main `d2cc5af8d8e1ffe7f0bececf934b89818692c2ec`.

## Context and threat
Stormline's planned authoritative multiplayer needs snapshots, deltas, relevance and bandwidth budgets on dedicated server. NET-02 + DATA-04 formal prerequisites are only documented. Input transport NET-01 and gameplay NET-02 do NOT perform output authorization or snapshot negotiation. A global dirty-entity list broadcast to all clients is unsafe for hidden/fog/owner-only data; a single global quantized cache may leak private data through reuse/delta/packet buffers. Snapshot loss and reconnect can also leave invalid baseline or "ghost" entities and duplicate spawns. Unreal Iris quantizes shared state with connection filtering/priority and [Unity Netcode for Entities ghost snapshots](https://docs.unity.cn/Packages/com.unity.netcode%401.5/manual/ghost-snapshots.html) combine per-client relevancy, importance and delta policies, but their engines, licenses and guarantees are not Stormline implementations.

## Proposed choice (not an adopted codec/library)
Build **Stormline-owned typed ReplicationProjectionV1** exclusively from NET-02/WORLD-01 committed authoritative state. Pipeline **recipient authorization/visibility field whitelist FIRST**, then spatial/group interest, prioritized scheduling and per-recipient schema/quantization, full or **application-ACKed** baseline delta serialization. Share common work only between same information-security cohort with epoch/schema/field equality proof, never share private owner projections. Provide bounded change journal, per-client baseline ring with epoch/capability fencing and explicit keyframe/resync if ACK absent, lost/evicted baseline or scene/role change. Respect NET-01 cryptographic delivery profile/congestion/MTU and keep gameplay application commits in GAME-04. **Do not write client-received data back to server world.**

- **Security order invariant:** authorization AND field visibility -> relevant set -> budget/rate -> allowed serialized state -> compress if permitted -> send; geometry or client interest requests never increase permissions. Revoke causes immediate future send suppression and cache invalidation; sensitive prior data already disclosed cannot be "unseen".
- **Lifecycle:** spawns, despawns and generational IDs with ordered dependency references; reliable signaling or full-baseline refresh where needed, idempotent client apply and stale deltas rejected. Transport ACK ≠ decoded/applicable snapshot baseline ACK.
- **Differential:** snapshot/delta over acknowledged **same client+match+world epoch+role/visibility version+schema+quantization**; full baseline otherwise. Use bounded ring, ACK window and monotonic sequence wrap policy. Do not reference historical frame whose projected security cohort changed.
- **QoS:** scheduler per recipient/actor with age, value, distance and fairness budgets, bounded queue; never assert a rigid global 60Hz replication cadence or 64-player support before measurement. Lower refresh/visibility changes imply eventual consistency, with mandatory critical secure control and explicit blackout/overload receipts.
- **Data:** DATA-04 source schemas provide type/version rights and migrations, but live network byte codec is a **separate typed projection** whose concrete binary schema is undecided. Quantization may be lossy for display, never for authoritative rules. Compression optional/disabled in secret-mixed contexts; no blanket use of Zstd/LZ4 before threat and CPU/packet-size benchmark.
- **Ownership:** NET-03 does not own spatial index source (WORLD-03), server authority (NET-02), gameplay (GAME-04), NET-01 congestion/crypto, client prediction (NET-04), tickets (NET-05) or anti-cheat/fuzz policy (NET-06). Its role is bounded authorized replication scheduling and receipt.

## Considered alternatives
| Approach | Advantage | Problem / outcome |
|---|---|---|
| Broadcast every ECS component to every client | easy initial prototype | exposes secrets, bandwidth O(all entities × clients), violates strict authority |
| Relevance by radius only | cheap spatial bound | LOS/fog/team/owner/hidden world and data-field access not enforced; inadequate |
| Shared unfiltered quantized global cache | amortizes CPU | leaks owner/private metadata, entity existence, deltas and timing; require cohorts |
| Pure reliable ordered message stream | simple baseline lifecycle | HOL and backlog cause stale positions / congestion; only selected reliable control lane |
| Pure unreliable snapshots w/o baseline ACK | low latency at first | missing base/despawn/joins under loss, no durable recovery; reject |
| Full keyframe every tick | simple reset and correctness | high bandwidth and CPU, 8/16/32/64 scalability unproven; fallback only |
| Third-party Unreal Iris / Unity Netcode as Stormline runtime | established concepts | incompatible engine ABI and licensing, not plug-and-play; **reference only** |
| Stormline owned authorized per-client projection + bounded spatial interest + ACKed deltas | secure boundary, modular, testable bytes/CPU, honest per-peer capability | complexity, ACK and cache bookkeeping, schema/role migrations; **leading proposal** |

## Threat model, costs, and proof obligations
Sensitive information must be **redacted before** shared extraction and compressor; filter decision based on authenticated server-issued NET-05/NET-02 role/match and GAME-04 field policy, not on client-reported location or arbitrary subscribe command. No compression of a shared secret together with attacker-controlled string without explicit side-channel review. Anti-wallhack outside-interest hiding reduces exposure but cannot retroactively erase data or stop all inference. Memory and CPU for per-peer baseline/interest can grow with clients/actors; cap and track. World->recipient projection must take a committed, race-safe snapshot; async serializers never borrow mutable ECS pointers.
**Adoption gate:** owner-approved ABI/codec/quantization/security, explicit 8/16/32/64 benchmark targets after baseline, unit/security/fuzz and realistic loss/jitter, correct owner/fog/spectator tests on actual decoded wire, client reconnect epoch reset and multi-OS/Web feature checks; implement predecessors first. No number, library, algorithm or binary is approved by merging this ADR. All 80 coding Work Orders stay blocked.
