## Future attack-surface map
1. **Untrusted bytes/files:** imported images, audio, videos, fonts, glTF/GLB, JSON/YAML/TOML, project metadata, scripts/plugins, shader sources, network frames, serialized save/scene, archives, streamed objects and decoded/decompressed blobs. Strict format/version parsing, byte/size/nesting/decompression/CPU time bounds, overflow checks, encoding/Unicode and path canonicalization with symlink defense. After parsing, *semantic validation* (IDs, capability, tenant/project scope, type/range, stale epochs) must not be assumed from syntactic validity.
2. **Native memory/thread/security:** C++20 ownership, spans/RAII, allocator lifetime, borrow and async cancellation, integer arithmetic/signed overflow, UAF/OOB/uninitialized memory, deep recursion, race conditions and concurrent device/resource/actor resets. Clang ASan+UBSan fuzz harnesses; TSan separate where supported; MSan only when fully instrumented supported platform. Static analyzer/CodeQL and direct code review complement fuzzing. No assertion that sanitizers cover all undefined behavior or that “zero findings” proves memory safety.
3. **Network multiplayer trust:** NET-06 typed `SecurityPrincipalContextV1/TrustBoundary/ValidationEnvelope`, unauthenticated path vs verified session vs admitted actor and server-only privileged operations; test duplicate/replayed/stale, quota abuse, resource exhaustion and consent/privacy boundaries. QA-04 runs negative tests; NET-06 owns real validation/recovery and NET-05 identity, never trust client role, client clock or claimed server privilege.
4. **AI/MCP agent commands:** AI-06 verified grants, permission attenuation, operation/project path scoping, expiry/revocation, owner consent confirmation, dry run vs execution and audit; tool arguments/model instructions are *untrusted data*. Test prompt-injection content in project files/tool results cannot escalate rights or erase records; distinguish semantic misuse, policy enforcement and prompt guardrails, with deny default. No secrets/authorization via raw model text; no blanket ability to execute scripts.
5. **Plugins/scripting/sandbox:** proposed capability-aware process isolation/OS support matrix, resource quotas, allowlisted host functions, memory/filesystem/network project-scoped access and import/export paths, unsigned plugin provenance, compatibility; actual sandbox availability/proof differs Windows/Linux/macOS/browser, cannot claim that WASM is secure without host capabilities and runtime mitigations. No in-process native plugin security guarantee.
6. **CI and supply chain:** GitHub untrusted fork PR read-only tokens, no signing secrets or write/OIDC, no `pull_request_target` or `workflow_run` running or promoting untrusted PR artifacts, immutable third-party Actions pin/lockfile + upstream provenance, trusted build/publish split, cache namespace/digest verification, minimal permissions, retention and scanner coverage. Current workflow uses `actions/checkout@v7` mutable major tag (observed), **future hardening separate WO** with no changes in this P00 docs PR. Zero rulesets observed, so no required status checks formally enforced today.
7. **Dependency vulnerability and license:** choose pinned SPDX 3.0.1 or CycloneDX 1.7 typed software bills containing direct/transitive dependencies, source/binary provenance, hashes/SPDX expressions/licenses/notices and declared missing inventory. SBOM is not a CVE scan or correctness proof; OSV and GitHub Advisories are candidate vulnerability feeds subject accuracy, source coverage, version range, withdrawn fixes, false positives and VEX. Track actual dependency version/commit/patch status, exploitability evidence and owner disposition, never silently dismiss HIGH/CRITICAL due to “not reached” without proof.
8. **Build attestations/release:** SLSA v1.2 has distinct build/source track requirements; in-toto/GitHub artifact attestation requires *actual trusted builder, verified subject digest, source identity and signer chain*. A JSON file with `slsaLevel` is not evidence. PLAT-05 owns packaging/signing/release artifacts, QA-04 verifies security claims; no public release until BIZ-03/owner DoD and license rights. Rollback/roll-forward must verify signatures/hashes, migration compatibility and revocation of compromised keys.

## Candidate bounded fuzzing model (future only)
- Build isolated **small harness per parser/semantic boundary** receiving raw bytes plus explicit fixture and fake time/mutable state, deterministic reject behavior, no real server network, GPU/display, privileged credentials or writing outside temp sandbox. Seed with small project-owned valid/invalid examples and format-aware dictionary; prove harness actually reaches parser through coverage and negative fixtures. No untrusted corpus file is an executable command.
- [LLVM libFuzzer](https://llvm.org/docs/LibFuzzer.html) Clang-matched in-process coverage guided C++ fuzz; notable official caveat: libFuzzer feature development is stopped (critical fixes maintained), **future alternative AFL++/Centipede decision** open. Include ASan+UBSan compatible cases and separate TSan/MSan when support exists, apply size/RSS/timeout per input and per job; no sanitizer false PASS on unsupported host.
- [AFL++](https://github.com/AFLplusplus/AFLplusplus) alternative: high-throughput forkserver/persistent/structured fuzz, **tool overall AGPL-3.0-or-later** with Apache-2.0 and other per-file components; using the external AGPL tool does not automatically force a closed source project to adopt AGPL, but *copying/linking/redistributing* components creates distinct obligations. Follow pinned source SPDX per file and counsel/owner, no commercial donation or license substitution.
- Crash **deduplicate and minimize**, store seed/corpus version, compiler/sanitizer/target flags and source SHA, required reproducibility on clean build and fix with regression test; **fuzz cycles/unique crashes/coverage trend** not interchangeable with absence of exploitable defects. Fuzzing can discover denial of service and non-memory faults by explicit semantic invariants; “no crash” alone insufficient.
- CI staged budget: quick deterministic seed corpus and static checks on PR after code approved, bounded fuzz campaigns on safe free runner schedule with separate offline local longer campaigns if provisioned, **never upload confidential corpus or auto-retry first failure green**. Refuse unbounded cost/private runner/storage and do not deploy fuzzer on real public server.

## Security gate and disclosure
- `SecurityFindingV1` severity with **uncertainty and materiality**, status OPEN/IN_REVIEW/REPRODUCED/PATCHED/VERIFIED/ACCEPTED_BY_OWNER/NOT_APPLICABLE (with evidence), affected boundary, C++ crash trace redacted, exact source commit/corpus, CVE/GHSA/OSV refs only when sourced, license and SBOM association. No fictional CVSS severity proof, exploit details or fabricated alerts.
- **HIGH/CRITICAL known** => BLOCKED, cannot release/advance via “tests pass”, suppress static scan, expire temporary waiver or self-promote checkpoint. Correction Delta same WO/PR when safe, proof of fix/regression and review. Underlying auth/key compromise or irreversible operation needs HIGH_ASSURANCE and owner approved rollback.
- Vulnerability disclosure coordinated in restricted advisory channel; public repo does not justify public exploit/crash corpus dump. Track triage time, encrypted/private reproduction, fix verification, patch version dependency, user notification and incident timeline, risk of rolling back data migrations. Separate third-party incident notices, key rotation, data retention and recovery.
- Every proposal references [test acceptance 128 future](../testing/qa-04-acceptance-matrix.md); no scanning/security of engine runtime performed here.

## 2026 cost/license and what evidence can prove
GitHub public standard hosted runner compute may be free while larger runners/private repo usage, artifacts/cache/shared storage can cost. CodeQL for C++ public code scanning is available; `none` build mode misses generated code, `manual` requires actual build and may offer best completeness. Store provenance/scan findings and version/tool licenses without private data, audit independent source, don't claim strict branch protections absent (currently zero rulesets). R$0 is a **stop condition**, not a promise of unlimited scanning.
