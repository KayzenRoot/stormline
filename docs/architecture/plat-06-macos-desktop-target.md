## 2026 platform change and compatibility proposal
- Apple announced [at WWDC26](https://developer.apple.com/videos/play/wwdc2026/102/) that macOS Tahoe 26 was the **last release supporting Intel Macs**; [macOS 27 release notes](https://developer.apple.com/br/documentation/macos-release-notes/macos-27-release-notes) confirm architecture migration details. **Apple Silicon arm64 is the mandatory candidate**; future actual physical Apple Silicon plus named minimum OS is required.
- [Apple Sep 1 2026 Rosetta notice](https://developer.apple.com/news/?id=w5ngl9k2): macOS 27 is the **last general-purpose Rosetta release**, with a limited future exception for older unmaintained game titles. Do not depend on Rosetta for Stormline distribution; an Intel-only binary executing under Rosetta on Apple Silicon is **not** an Intel Mac-native compatibility test.
- [Xcode 27 notes](https://developer.apple.com/documentation/Xcode-Release-Notes/xcode-27-release-notes): Xcode 27 installs/runs on Apple Silicon Macs only, with macOS27 SDK support for universal backdeployment to macOS12+; at a deployment target >=macOS27 the standard architectures do **not** automatically include x86_64. If Intel x86_64 is owner-selected, use explicit architectures, min OS and actual Intel hardware OS <= macOS26 for testing.
- Intel Mac support for 1.0 is **conditional and unresolved**; propose x86_64 native on eligible OS, and universal2 arm64+x86_64 only if all nested Mach-O libraries and targets pass physical tests. Rosetta on Apple Silicon is separate optional comparison. No promise macOS27 runs on Intel Mac. Source code license, hardware matrix and minimum OS are not fixed.

## Single main-thread Cocoa process and SDL3 bridge
- Candidate C++20 + SDL3 under CORE-01; narrow Objective-C++ Cocoa/AppKit/QuartzCore bridge as required. [SDL3 macOS README](https://wiki.libsdl.org/SDL3/README-macos) warns that custom NSApplicationDelegate can suppress SDL delegate behavior including quit/open-file. Delegate forwarding must preserve application activation, open project, termination request and Editor unsaved-document close veto, without duplicate NSApp or NSEvent event pumps.
- [NSApplicationMain](https://developer.apple.com/documentation/appkit/nsapplicationmain) and [SDL_Metal_CreateView](https://wiki.libsdl.org/SDL3/SDL_Metal_CreateView) require main-thread operations. No background NSWindow/NSView management; heavy shader compile, I/O, project import and fence waits remain async. Headless server/tool path must not start mandatory UI/audio/GPU.
- Distinguish app process vs each window: INIT/ACTIVE/FOCUSED/UNFOCUSED/OCCLUDED/MINIMIZED/FULLSCREEN_SPACE/BACKGROUND/CLOSING/VETOED/DESTROYED with WindowId + WindowEpoch. Editor and exported game windows have separate life cycles. Do not redraw after surface destroyed; multiple Inspector windows and project unsaved changes retain state.
- Retina coordinates: AppKit points != physical display pixels. [NSWindow backingScaleFactor](https://developer.apple.com/documentation/appkit/nswindow/backingscalefactor) may reflect scaling, not real physical pixel density; use NSView point-to-backing coordinate conversion and drawable actual size. Handle external monitor move, mirroring, display mode, Sidecar, HDR/P3/sRGB, safe areas, fullscreen, variable refresh/ProMotion and zero-size drawable. GFX-07 color/presentation and EDIT/UI layout own semantics.

## Metal presentation and capability plan
- Native Metal through **GFX-01** is primary candidate; [CAMetalLayer](https://developer.apple.com/documentation/QuartzCore/CAMetalLayer) bound to an NSView or SDL3-created Metal view. SDL_Metal_CreateView **does not attach MTLDevice by itself**; RHI assigns the selected device, manages command queues/resources and per-frame drawable lease. Prefer thin layer not duplicate MTKView scheduler unless comparative evidence proves needed.
- [Apple Metal](https://developer.apple.com/documentation/metal/) and [macOS26 notes](https://developer.apple.com/br/documentation/macos-release-notes/macos-26-release-notes) describe Metal 4, but availability is **GPU family/OS/feature-gated**, not universal on Intel or every Apple Silicon. Query MTLDevice feature sets, texture/RT formats, MSL dialect, shader compile, frame queue and limits, no Vulkan/Metal parity guarantee. GFX-01 ADR-0014 considers MoltenVK/KosmicKrisp as conditional translation comparators, never mandatory engine Mac backend.
- Unified vs discrete/eGPU matters: [recommendedMaxWorkingSetSize](https://developer.apple.com/documentation/metal/mtldevice/recommendedmaxworkingsetsize) is **advisory** budget, not GPU-exclusive guaranteed VRAM and not equivalent to total unified RAM. Use GFX-01 resource accounting, OS memory/thermal signals and per-device negotiated caps. Intel Mac hybrid/eGPU conditional, unplug/reprobe failures typed.
- Each drawable/device/layer generation invalid after resize, display detach, sleep/wake, GPU/device loss and shutdown; GFX-01 recreates resources from canonical asset owner or returns RESTART_REQUIRED. Never reuse old drawable, wait on GPU synchronously in AppKit thread, assume HDR or 60/120 FPS. 2D alpha/clip/text, 2.5D camera/layer and representative 3D geometry/material independent golden fixtures on physical Apple Silicon, Intel only if selected.

## GAME input, TCC security and distribution boundaries
- GAME-01 owns semantic actions. CORE-01 SDL3 normalizes keyboard keycode/scancode, Cmd/Option/Control physical/logical keys, dead key, IME text composition (CJK/RTL), trackpad momentum/scroll, cursor, pad connect/remap/haptics with window/device epochs. Apple [Game Controller](https://developer.apple.com/documentation/gamecontroller/) devices might also reach SDL; prevent duplicate input events. Focus loss, sleep, unplug releases held actions. VoiceOver/keyboard accessibility belongs UI but Mac TCC/focus must be surfaced.
- TCC Accessibility/Input Monitoring/microphone/camera, Sandbox network and file dialogs are explicit permission states, never silent background capture. Use user-selected NSOpenPanel/security-scoped bookmarks where required; user grant can expire. No Full Disk Access, sudo or unsigned plugin fallback. Protect UI projects from untrusted AI/MCP via Command Kernel capability policies.
- PLAT-05/BIZ-03 own package, signing, notarization, update and release: Mac .app/Info.plist identity, nested dylibs/helpers/slices, bundle resource rights, rpath, provenance and last-good migrations. Outside App Store [Developer ID notarization](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution/) requires actual valid Developer ID signature, Hardened Runtime, timestamp, approval ticket and Gatekeeper test; App Store uses separate submission and [App Sandbox required](https://developer.apple.com/documentation/security/app-sandbox). Signing is not asset provenance or code safety. Apple developer enrollment/certificates/potential spend **unapproved** and never inferred free from GitHub docs CI. [Hardened Runtime](https://developer.apple.com/documentation/security/hardened-runtime) JIT/unsigned memory/library validation exceptions require separate security proof, not blanket entitlement.
- Release target and minimum OS, Intel support class, exact Xcode/SDL3 library versions, SDK terms, third-party SBOM/NOTICE and NLE-D009 engine source license remain unresolved; internal debugging ad-hoc signing cannot be presented as public signed/notarized release.
