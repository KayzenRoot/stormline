## Android host and GPU strategy: candidate A
- **Target concept:** Android arm64-v8a native C++20 with **pinned Android NDK+SDK/AGP/CMake**, Android `Activity`/Java-Kotlin integration behind CORE-01 single event/lifecycle owner. Prefer CORE-01's candidate SDL3 as host where it covers platform needs; evaluate Android [GameActivity](https://developer.android.com/games/agdk/game-activity/get-started) with AndroidX/Prefab only as a bridge or *alternative host under CORE-01 approval*, not alongside independent SDL3/NativeActivity event loops. Google recommends GameActivity over NativeActivity for native games; GameActivity has its own `android_native_app_glue` and text input, so double polling/duplicate focus/touch would be a correctness defect.
- Android lifecycle: create/resume/pause/stop/destroy, process recreation, multiwindow/picture-in-picture (only if declared), permission dialog, app standby/Doze, ANativeWindow surface create/resize/destroy and Android Game Mode changes. Activity lifetime is **not identical** to surface lifetime. Surface epoch invalidates GPU swapchain on rotation, pause, folding, display change and background eviction; update CORE-04 time debt and GAME-01 pointer cancellations. Native callbacks and JNI references have clear ownership/global-ref validity and thread attach/detach; no JNI call from arbitrary unregistered worker.
- **Vulkan primary candidate via GFX-01**, physically query Vulkan API version/extension/profile/texture limits/precision, validation, mobile tilers and present modes. [Android Vulkan guidance](https://developer.android.com/games/develop/vulkan/overview) says Vulkan is primary low-level mobile API and Android 10/API29 new 64-bit devices require Vulkan 1.1; this is **not evidence every supported game target meets engine capability tier**. [Android native-engine guide](https://developer.android.com/games/develop/vulkan/native-engine-support) recommends API29+ / Vulkan1.1+ / Android Baseline profile as selection candidate, but real devices vary. OpenGL ES 3.x fallback can be proposed when GFX-01 approves capabilities and quality fixtures; do **not** assume all Android devices, ray tracing, compute, texture ASTC or Vulkan1.3 support. Device loss/surface invalid/swapchain recreation and GPU resource generations exclusively with GFX-01.
- Native ELF page sizes: [Android 16 KiB page guide](https://developer.android.com/guide/practices/page-sizes) states Android15 enables 16-KiB-page devices and Google Play requires compatible 64-bit native libs for apps targeting Android15/API35+, with current update deadline details. Android NDK r28+ generates 16-KiB-aligned shared libraries by default; entire prebuilt native .so chain, mmap assumptions, APK packaging alignment, 4K/16K test devices and CI inspections required. Do not hardcode PAGE_SIZE=4096. The later Feb 1 2027 update restriction is separate from default compiler behavior. Verify Play rules again before release.
- Android distribution rules in 2026: [Google Play target API policy](https://developer.android.com/google/play/requirements/target-sdk) requires new apps/updates target Android16/API36+ since **Aug 31, 2026** (with Wear/TV/Automotive/XR exceptions not relevant to mobile phone profile). Target API is *not* minimum install OS. Package splits, AAB, Play App Signing/upload keys and app content/privacy compliance belong PLAT-05/BIZ-03. [Play Asset Delivery](https://developer.android.com/guide/playcore/asset-delivery) install-time/fast-follow/on-demand asset packs are optional store-specific DATA-05 delivery integration, and do not give a generic external-CDN contract or executable code pack. No presumption Google Play fees, enrolled account, signing identity or release.
- Scoped storage/Storage Access Framework or user-granted docs, AndroidManifest permissions minimal, App Links/deep link allowlist, background execution restrictions, hardware feature manifest fidelity and Google Play policy are hard security gates, not bypassed by privileged storage/location/overlay/ACCESSIBILITY_SERVICE for general game controls.

## iOS/iPadOS host and Metal strategy: candidate B
- **Target concept:** native arm64 iPhone/iPad on owner-selected minimum OS and real device, Xcode/iOS SDK pinned (actual 2026 submission rule [Apple upcoming requirements](https://developer.apple.com/news/upcoming-requirements/): **Xcode26+ / iOS26 SDK since Apr 28 2026**; apps uploaded target **iOS13+ since Sep 9 2026**). These are **App Store Connect submission constraints, not automatic Stormline runtime min OS**. [SDL3 iOS guidance](https://wiki.libsdl.org/SDL3/README-ios) supports iOS platform framework via xcframework and UIKit event loop; choose a **single CORE-01-owned UIApplication/UIScene lifecycle** with SDL3 or a narrow ObjC++ native bridge, not two competing main loops.
- UIKit [app/scene lifecycle](https://developer.apple.com/documentation/uikit/managing-your-app-s-life-cycle): multiple scene states and background suspension. iOS foreground/background, interruption, phone call, notification, permission prompt, audio route and app termination require save/cancel/restore. Never claim a background game can render unboundedly or run unrestricted threads; use OS-approved background task only for legitimate finalization. Scene and CAMetalLayer surface generation distinct from engine/world generation.
- **Native Metal via GFX-01**, iOS CAMetalLayer/MTKView chosen by approved owner; GFX-01 owns MTLDevice/render resource, texture capabilities/mobile family/heap budget, MSAA, adaptive resolution, memory pressure/lost drawable. Mobile Metal feature sets and Metal4 require actual device/OS probes; no inference from iOS version. No MoltenVK or Vulkan-on-iOS as default; Apple public API path native Metal. Rendering quality tiers and UI/text sharpness independent of 3D dynamic resolution.
- iOS multi-touch/GAME-01 taps/drags/long-press/multi-finger/lift/cancel and Pencil (optional per device) route semantic gestures, safe areas/home indicator/notch, high DPI/orientation/iPad split view/accessibility Dynamic Type, VoiceOver, Switch Control, touch target and keyboard/controller. [Game Controller](https://developer.apple.com/documentation/gamecontroller/) haptics/connected pads conditional, no raw framework pointers in gameplay API. Motion sensors/location/microphone/camera require owner-feature approval and explicit privacy purpose/permission; **no default background surveillance**.
- Distribution through PLAT-05/BIZ-03: app bundle/IPA signing identities, provisioning profiles, entitlements, sandbox, TestFlight/App Store Connect and review, developer program/cost, privacy manifests for listed SDKs and [Apple App Privacy details](https://developer.apple.com/support/third-party-SDK-requirements/) + [App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/). No ability to ship arbitrary downloaded JIT/native executables via game projects; AI-authored project scripts and plugins require separate sandbox/code-sign compliance review. No owner-approved public MVP or Apple account yet.

## Sustainable performance and hard resource budgets
- Mobile phones/tablets are energy- and thermal-constrained; short burst benchmark != sustained performance. Proposed `MobilePerfPolicyV1`: dynamic resolution (3D only; preserve pixel-art/text/UI), fixed-step sim budget, frame cap/pacing, postprocess/texture/LOD/shadow scaling, CPU worker count, background network reduction, memory trim and QoS/visibility, user battery/performance preference. No governor frequency spoofing or thermal safety override.
- [Android ADPF](https://developer.android.com/games/optimize/adpf) Performance Hint Session/Game Mode/thermal signal candidate only if actual API/version/device supports; [thermal API](https://developer.android.com/games/optimize/adpf/thermal) must not be polled > once/10 seconds for headroom and may return NaN/unsupported. [iOS thermal state](https://developer.apple.com/documentation/foundation/processinfo/thermalstate) / low-power-mode notifications inform fallback; OS GPU/CPU clocks and memory may vary, avoid claiming deterministic FPS across power/ambient temperature. Thermal state is advisory and may be stale.
- Streaming/cooking DATA-05 immutable chunk manifests and target texture profile (ASTC/ETC2/PVRTC only when actually supported), small preload and bounded codecs/storage, background/downloading constraints, offline/partial update and last-good preservation. OS memory warning or low-memory kill requires recoverable save/boot; Android low memory trim, iOS memory warnings/jetsam may kill without callback. No full desktop assets blindly copied into mobile.
- Phone foldables/tablets: physical dp/pt vs pixels, changing display cutouts/hinge, insets/keyboard, variable refresh, portrait/landscape, touch accessibility; camera/world/input safe projection must be tested. Accessibility and localization remain UI/GAME owners with PLAT surface/view metrics only.
