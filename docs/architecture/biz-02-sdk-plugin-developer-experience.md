## Architectural objective and developer journeys
Enable an original author to create a **minimal project**, discover versioned public capabilities, author gameplay or editor extension, validate an original plugin/sample, exercise the same command via editor button / headless CLI / future MCP, build and export on a supported OS, receive typed errors and migration advice without mastering internal C++/ECS/render graph/scheduler internals. No automatic permission for commercial redistribution exists yet.

| Layer | Candidate interface and authority | Must never own |
|---|---|---|

| Gameplay extensions | GAME-02 `ScriptApiSchemaV1`, scoped script host, program/graph compiler, capability grants and tick receipts | independent second VM or direct world access |

## Public API/ABI proposal, intentionally not adopted
- One semantic schema-first API (commands, events, data types, stable identifiers, errors, ownership, capabilities, feature gates) is the authority; transport/binding implementations are generated projections that can be compared with contract fixtures and never diverge.
- **C ABI as optional native boundary candidate**, not C++ ABI across OS/compiler: `extern "C"` entry name, versioned function-table and size-prefixed structs with explicit packing/alignment and calling convention, plain fixed-width fields, length-delimited UTF-8 buffers, opaque 64/128-bit handles with generation, alloc/free callbacks owned by same domain, tagged result codes and host-managed lifetimes. Do not pass exceptions, STL types, RTTI objects, `std::string`, virtual dispatch, allocator ownership, raw engine pointers, thread-local VM objects or compiler-specific layout across boundary. C ABI alone is *not* universal binary compatibility, especially with different architecture, OS, bitness, CRT and target deployment.
- Resolve namespace + `major.minor.patch` semantic version, `abi_major`, `schema_hash`, required/optional feature flags, min/max target host API, engine build hash, export target and trust tier at handshake. Reject unknown required field, ABI major mismatch, unsupported capability/target, stale schema or unsigned/untrusted native code. Additive structs may use `struct_size` checked by both ends; never infer that zeroed unknown fields equal permission.
- **Native plugin trust:** only explicit owner-authorized and provably packaged/signature-digest pinned code, with separate OS dynamic loader. Native in-process code inherently has process privileges, cannot be honestly sandboxed by permissions in a manifest. For untrusted third-party code, require independently validated out-of-process containment (OS sandbox, IPC allowlist, quotas) or WebAssembly/WIT guest with restrictive host imports and demonstrated isolation; otherwise DISABLED/BLOCKED.
- **Web extensions:** no native DLL/dylib/so, no implicit WASI filesystem/process; run Web-compatible JS/ESM or sandboxed WASM guest with browser security model and explicit host imports only if feature matrix/proofs permit. WIT/WASI 0.2 and 0.3 compatibility and JS tooling must be tested separately. WASI 0.3 is a 2026 available spec, but broad host/compiler/browser toolchain parity is NOT presumed.
- Plugin lifecycle: `DISCOVERED -> VERIFIED -> COMPATIBLE -> STAGED -> ACTIVE -> DRAINING -> DISABLED/QUARANTINED/RETIRED`. No executing untrusted manifest contents during discovery. Activate after capability grant and at owner-safe transaction boundary. Deactivate drains async work, invalidates handles, revokes grants, releases budgets; unloaded native DLL cannot be guaranteed safe without proven quiescence/thread ref tracking, therefore **disable until restart** if uncertain. Hot reload creates staged new version, validates state migration/rollback/ABI/SDK compatibility and swaps only after successful readback; unknown/failed migration retains known-good.
- Runtime safe timing: tick commands through GAME-02 and AI-01 owners only; graphics/audio/scene authoring changes restricted to owning thread/phase via typed queue, no direct off-thread mutations. Long-running tasks get bounded jobs and cancel receipts; resource exhaustion returns fault, never global deadlock.
- Per-target package manifests include `engine_version`, compiler triple/stdlib, CRT/libc baseline, architecture, OS, wasm features, linkage modes, plugin rights/provenance SPDX, capabilities, artifact digest and supported deprecation window. Installed package must be relocatable, offline-demo capable, roll-forward/rollback safe where schema permits.

## Developer experience and release quality
- **First sample:** original deterministic Hello World that queries API and emits an authorized diagnostic via the kernel, demonstrating Editor/CLI parity on headless and platform-neutral tests; no game asset copied from competitor engines. Next samples for gameplay scripting and optional plugin only after minimal path passes. Samples separately cleared and license-granted by owner before publication; **no fake compiled examples**.
- **Reference:** searchable versioned static offline docs + examples, error code catalog, migration guides, deprecation notices, permission picker, platform support grid and API diff/changelog. Generated documentation must exactly match schema/version hashes and be tested for broken links and accessibility.
- **Build:** future CMake `install(EXPORT)` + `StormlineConfig.cmake` relocatable candidate, hermetic CMake Presets/Ninja/CTest, local offline reproducible samples, no hidden downloads/paid remote build. `find_package(Stormline CONFIG REQUIRED)` only after real package. Web NPM/ESM packaging remains a candidate requiring exact version/supply-chain policies.
- **Benchmark:** predeclare host/target/compiler and cold/warm plugin activation, command latency p50/p95/p99, memory/allocations, sandbox host-call cost, runtime throughput, build size/cold-compile, deactivation recoverability. Do not invent thresholds. Record physical vs emulated host and platform failure categories.
- **Security:** capability deny-by-default, revocable scoped grants (principal, project, world, extension, API/action, expiry, target), no global workspace credential access, path traversal/zip bombs/manifest parsing and dependency hijack guarded, permissions separate from code signatures; provenance and telemetry local-first redacted.
- **Licenses:** source engine license stays OPEN, exports and bundled SDK cannot be publicly licensed merely because source repository is visible. Exact upstream runtime/tool/sample license, transitive notices and user-created game asset ownership are BIZ-01 gates. Restrict real export before rights approval.

## Alternatives and hard stop
C++ header-only vendor types across plugin ABI, direct native plugin marketplace, no-grant WASM host imports, automatic remote dependency install, MCP-only API, separate editor/CLI execution paths, auto-enabled hot reload, binary plugin on Web, and unqualified multi-OS guarantees are **rejected as unconditional defaults**. Deciding a **single first slice** (semantic API + headless original sample and one transport) is a future owner/release-class gate after code and its dependencies actually exist. No benchmark, SDK executable, compatibility result or legal release delivered by planning.
