## 1. Product target and truth
Catalog AUD-01 acceptance: **"Testes de underruns, latência e custo por quantidade de vozes."** An original Stormline audio engine must deliver predictable low-latency playback and device recovery, independent of graphic FPS, in 2D/2.5D/3D/native/Web games with Win/Linux/macOS Editor/player and CPU/headless test render. High fidelity and good gameplay feel require measured latency and original fixtures; **no no-underrun or fixed-latency promise** across OS/hardware. Audio output is nonauthoritative for GAME, physics and NET.

Audio subsystem owns semantic AudioDevice/AudioMixWorld/Voice/Bus/Send/MixSnapshot/AudioClock/StreamSource/AudioEventReceipt contracts and a simple bounded mixing kernel. **AUD-02** owns spatial sources/HRTF/occlusion; **AUD-03** owns advanced DSP nodes/effects/RTPC/automation graph; **AUD-04** owns adaptive music/dialogues/cutscene. A future AUD-01 baseline provides default gain/pan/bus routing without replacing an entire spatial/DSP engine.

## 3. Layered original mixer architecture
```text
Game/GAME/NET/SIM event at TickId
  -> authorized AudioCommandV1 (producer, seq, asset revision, tick/time)
  -> non-RT command validation + bounded queue + scheduled sample target
  -> voice allocator / virtualizer / stream cache (preallocated, no hard waits)
  -> immutable per-quantum Voice/Bus routing snapshot
  -> RT callback: bounded f32 accumulate, gain/pan/send, optional simple limiter stage
  -> planar/interleaved conversion and src resampling if device needs
  -> thin backend adapter SDL3/miniaudio/PortAudio/cubeb candidate
  -> PCM device buffer / browser AudioWorklet / offline NullSink
```
AUD-01 owns one canonical mixing kernel with output block negotiation. Vendor SDL's built-in stream mixing is an **alternative backend detail**, not reason to duplicate mix/send/priority semantics or mix twice. Device adapter receives pre-mixed PCM, not each source stream if choosing Stormline-owned buses. A strict adapter contract must validate the output format, possible internal buffering, callback scheduling, and actual measured latency. If using SDL3 streaming API, prevent both SDL native streams and Stormline mixer independently applying gain/summing. No assumption SDL3 supplies all gameplay bus graph semantics. Headless `NullSink` must advance sample frames and report dropouts but never depend on real device hardware.

## 4. Realtime thread and queue safety
**Callback contract**: prealloc all buffer/slot memory and resampler history before entering RT; no heap/new/free, mutex, I/O, unbounded wait, logging, file access, device enumeration, decode, dynamic type registry or graph compilation. All RT code bounded by frames/channels/voices, no hidden reentrant library calls that may block; enforce callback budget with counters updated atomically and drained on non-RT thread. Distinguish thread realtime scheduling *requested* from actual OS priority guarantee: Win/macOS/Linux and browser behave differently.

Control producer → RT consumer uses bounded SPSC queue if single producer; multiple authorized producers feed non-RT serializer then SPSC, or documented bounded MPSC with measured nonblocking RT consumer. Queue overflow has typed `COMMAND_QUEUE_FULL`/priority policy. Never silently erase **critical notification** event without GAME-owned policy; cosmetic one-shots may be dropped with receipt, preexisting playing voices maintain coherent progress. Lifecycle through generational handles, atomic snapshot pointer switch at audio-quantum boundary and deferred retirement after in-flight read epoch: no use-after-free from hot-swap, device lost, stream ended or content reload.
Underflow uses **silence fill + underrun counter** and recovers cleanly, never stale unsafe memory; overrun caps queued buffering and can drop expendable audio with bounded receipt. Device callback receives arbitrary variable `frame_count` and channel layout, including unexpectedly zero/large callback sizes, and must obey explicit preallocated max plus failure recovery. Callback buffer must be initialized; silence and master mute policy include click-free ramp.

## 5. Sample clock, game time, resampling and sync
Audio hardware frame clock `SampleFrameId` counts monotonic emitted frames per **DeviceEpoch** at actual device sample rate (not UTC); `MixTime` counts internal mixer-domain frames. A rational/fixed scale transform `TickToSampleMappingV1` maps CORE-04 TickId + sub-tick offsets to target sample frames with checked integer remainder and explicit expected latency, without cumulative float drift. Device change, suspend/resume, OS renegotiation and clock drift trigger epoch change and bounded resync/crossfade policy. Fixed logical game tick must not block RT callback; render FPS independent. SIM events and music sync combine timebase tags and timestamp uncertainty to report observed end-to-end jitter rather than claiming sample-perfect sync.
**Internal PCM candidate:** float32 48kHz 2ch for baseline headless fixture, not a universal device format or promise. Runtime device can negotiate 44.1/48/96 kHz, mono/stereo/5.1/7.1 where supported; actual channel layouts with explicit labels (never assume same number means same order). Resampling choice: simple bounded linear interpolation as reference correctness/low-tier; quality resampler optional libsamplerate/SDL/miniaudio after measured high-quality aliasing/phase, interpolation and CPU. Handle differing source+sink rates, pitch/tempo change separate from device rate, drift, over/underflow, channel conversion, click-free fades. dBFS/log gain conversion must use finite clamped values and bounded master headroom, not integer overflow or NaN.

## 6. Bus graph, sends and mix logic
Start with a versioned small **DAG**: master, music, ambience, SFX, UI, dialogue, optional user-named bus, directed sends, gain/mute/solo, ducking request interfaces and priority weights. AUD-01 owns bus topology/routing/mixing; sophisticated DSP effects/RTPC/dynamic music/sidechain compressor execution belongs to AUD-03 and AUD-04; leave typed extension hooks only. Validate cycles, duplicate/foreign BusHandle, channel layout mismatch, fanout and depth quotas before installing an immutable graph at audio block boundary. Optional feedback loops must be explicitly reviewed with bounded delay memory by AUD-03 later, never arbitrary graph cycles.
Voice chain: decoded resident PCM/stream ring -> gain ramp and pitch/resampling -> optional 2D pan -> bus sends -> hierarchical stable topological sum -> master headroom, tested soft clip/limiter only with explicit latency and meter. Channels stored as tagged planar/interleaved format; voice write and bus buffers are preallocated and zeroed exactly once per quantum. Use internal f32, verify floating headroom/clipping/denormals and multi-device sample format conversions. No "perfect" peak limiter claim; true peak oversampling is future DSP specialized work.

## 7. Voice virtualization and priority arbitration
`VoiceHandleV1` has generation and stable event/asset ID. Distinguish `AUDIBLE`, `VIRTUAL`, `PAUSED`, `DRAINING`, `ENDED`: virtual sources advance logical playhead and event sequencing **without consuming full mix samples**, unless the stream/loop must prefetched for promotion. Prevent virtual voice from generating fake audible completion or missing game-critical temporal events. Prioritization: bus class UI/dialogue/accessibility vs ambient/sfx, explicit owner scope, distance/occlusion only via AUD-02 later, age/recency/cost/hysteresis. **Virtualization policy is fixed and reportable**, not hidden non-deterministic stealing. Voice stealing must fade/failure receipt and respect minimum protection for dialogue/accessibility; no infinite starvation of low-priority audio.
Caps: max active/virtual voices, max streams, per-bus outgoing sends, decoded frames/s, sample cache bytes, ring bytes, max bus channels, decode queue depth, asset size, source duration, event frequency and timer drift. Exact production numeric budgets are UNDECIDED pending verified hardware; experiments use 32/64/128/256/512 voice count **workload parameters**, not guaranteed supported concurrency.
Enforce separate **authoritative game event receipts** and **actual audio audible receipts**: game effects must not depend on a sound finishing if it was virtualized or inaudible.

## 8. Streaming, decoded data, codec security
DATA-03 validates source metadata and provenance; DATA-05 cooks decoded PCM/stream chunks and target codec/seek table/checksums. Streaming cache and decoder workers run CORE-03 off RT only; RT consumes prepared bounded chunk rings. For memory-stressed situations, prefer a graceful silence/virtualization receipt to blocking the callback for disk/network. Decode priority and prefetch adapt to measured latency but cannot overwrite critical data or create starvation. One-shot resident PCM vs long-duration streaming profile; streamed loop has sample accurate region/seek policy only where codec granularity and test evidence support it.
Official decoder candidates: dr_wav/dr_flac/dr_mp3 (Unlicense/MIT-0), Opus (BSD-like and royalty-free patent notices), PCM/WAV baseline. Review Vorbis/MP3/FLAC format support, licensing and malformed input fuzz at pinned revisions. No decoder plugins execute scripts or arbitrary URL loads; bounded compressed/uncompressed ratios, sample count/stride, channel count, metadata, loop/seek table integrity, native integer overflow and malicious headers. Audio clip licenses remain separate from code licenses.
Microphone capture, live voice chat, operating system loopback recording and raw device input are **FUTURE and OUT OF SCOPE**; must not silently request user permissions or record audio. A debug audio capture of final mix also requires explicit user authorization/retention/redaction and future privacy review.

## 9. Device management and portability
Logical `AudioDeviceHandle` binds a stable Stormline device token and `DeviceEpoch`; host OS device IDs are transient, not persistent asset identity. Candidates SDL3 `SDL_AudioStream` (SDL zlib) and miniaudio (Unlicense/public-domain or MIT-0), with PortAudio (MIT) and Mozilla cubeb (ISC-like) comparators. Core-01 owns lifecycle: list output endpoints, default selection, explicit user preference, opening/output profile, pause, resume, exclusive/shared mode capability only when proven, hotplug/lost-device event, callback retirement, safe fallback to default or NullSink, monotonic clock epoch and loss receipt. Multi-device simultaneous playback requires **separate device clocks and drift management**; no presumed bit-perfect synchronization between Bluetooth, HDMI, speakers, browser contexts. Volume and bus state persist across switch; no use of a raw retired native device pointer.
Browser: `AudioWorklet` separate thread in secure context HTTPS and user-gesture autoplay policy (MDN); no blocking, no assumptions about default 128 frames across browsers or that `SharedArrayBuffer` is available without cross-origin isolation. If unavailable, a documented coarse fallback/disabled audio state with capability report, no forced unsafe ScriptProcessorNode. OS-specific ports/backends measured in future. Headless server and CI always able to use NullSink to validate mixing independent of OS sound driver.
Accessibility: UI/dialogue priority, independent slider category, dynamic range and mute/solo policy, safe gain ramp avoiding pops; captions are AUD-04/GAME owner. Reduced motion affects visual FX, not automatic removal of audio cues. Hearing protection: avoid pathological DC, NaN and clipping, support reasonable master gain cap and warning, but real hearing safety cannot be guaranteed from software amplitude alone.

## 10. Security, observability and shutdown
Attack classes: audio bomb decompression, huge metadata/loop tables, malformed sample layout, untrusted remote asset, spam `PlaySound` intent, stale VoiceHandle, hotplug callback after stream freed (UAF), queue overflow, hidden microphone capture, copyrighted sample redistribution, unsafe lock waits, OS audio backend deadlock. Propose strict source sandbox/quota, renderer-independent CPU decode fuzz/ASan/TSan, no arbitrary external network, generational handles, epoch-bound device callback lifetime, critical event receipt and explicit privilege/capability gating for Editor/CLI/MCP. No secrets/PII in telemetry; per-game sound streams can contain private content, never upload traces without opt-in. `CORE-06` receives buffered counters: underruns, overrun, callback worst/budget, active+virtual voices, resampler CPU, decode backlog, memory, device switches, clipping and output latency measurements.
Graceful shutdown: stop new control commands, retire consumers at audio barrier, cancel decode jobs through CORE-03, drain or force silence with bounded deadline, defer buffer free until callback acknowledgments, close device under CORE-01; crash recovery of authored bus profiles through DATA-04, not volatile playback history. Future Web device switch/visibility changes and OS suspend/resume are separate tests.
