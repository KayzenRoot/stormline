## 3. Terrain source representation, patch identities and edit layers
- `TerrainAssetV1`: source AssetId/SceneId/Revision/WorldId, global origin/units, stable patch grid schema, heightfield tiles or explicit `MESH_SURFACE` path for caves/overhang/cliffs, edit-layer provenance, material weight maps, biome classification/override data and content rights. Heightfield **cannot represent arbitrary overhangs or caves**, use distinct meshes authored and streamed through GFX-04/WORLD-03. A hole mask is not a physically valid complete cave geometry.
- `TerrainPatchIdV1`: stable source asset+region+LOD-tile key independent of current GPU origin and camera, WORLD-03 CellId mapping explicit; patch revisions, neighbor keys and dependency hashes; tile coordinates use globally signed checked math. Patch IDs and border sample conventions must be shared by collision/cook and visuals; separate “authoritative source elevation” from display-only tessellation/displacement.
- Height source at approved physical units, with reversible sculpt layers: `RAISE_LOWER`, `FLATTEN`, `SMOOTH`, `STAMP`, `ERASE_LAYER` semantic brush records using stable affected patch region and immutable layer ID. `TerrainEditPatchV1` includes expected source revision, brush center/radius/falloff, sample resolution and finite clamped deltas. A stroke crossing tiles must commit at the DATA-04 atomicity scope, update neighbor border samples or detect conflict, never leave seam across one updated tile.
- **Authorability first:** base imported elevation, optional generator proposal from WORLD-05, named manually-authored edit layers and stable asset provenance. Regenerate/recook only affected tiles; preserve manual edits when upstream imported/generated base changes. Generator reproducibility and rules belong WORLD-05. Do not silently destroy a user's manual strokes or asset ownership during a streaming reload.
- Geospatial/reprojection/GIS import is optional DATA-03 contract, not assumed; Earth spheroid/origin and vertical datum need explicit coordinate conversion and source rights. The baseline authored game terrain uses local global meter units, not real-world geodata. Editor/CLI/MCP semantic brushes require per-project quotas, undo/redo source journal and preview of affected tiles with no execution claim.

## 4. Terrain LOD, tessellation, cracks, texture/shadow fidelity
- Compare **quadtree/patch LOD** with edge-stitch index variants, skirts and continuous geomorph, against **GPU geometry clipmaps** with nested camera-centered rings and toroidal height cache, not one unconditional default. The 2005 NVIDIA GPU Gems technique was demonstrated on period hardware; its published FPS cannot be transposed into Stormline. Baseline should be portable mesh/vertex path without compute/mesh shader dependency. Mesh shading/compute tessellation **feature-gated optional**, WebGL2 and WebGPU reduced tiers need verified layout.
- `TerrainLodPlanV1` accepts camera projections, screen-space error budget, actual patch neighbor levels, streaming completeness, global-origin epoch, CPU/GPU budgets and stable source revision. LOD neighbor ratio constraints, watertight edges or skirts and geometry morph must avoid cracks, T-junctions and swimming or ground penetration. GFX-04 alone owns final geometry/visibility/occlusion and mesh shader submissions; WORLD-04 supplies tile source, adjacency metadata and renderer hints. No duplicate high-frequency culling system.
- Distance-based mesh LOD and **collision authority may differ**. PHYS receives source/cooked collision heightfield/mesh revision with safe tick barrier, independently ACKs before a traversable tile becomes active. Visual displacement cannot silently move authoritative ground or produce walking through cliffs. Decorative parallax/displacement may be marked visual-only with a raycast/collision contract. Camera-relative origin shifts must match WORLD-03/CORE-05 epoch.
- Material source uses N-channel nonnegative normalized splat/weight masks with explicit zero-sum/default layer; resolution and texture resource budgets. Blending in **linear scene space** as defined by GFX-05/07; avoid sRGB double decode, undefined triplanar normal-space, mud/snow seams, inconsistent roughness on slopes. Texture arrays/virtual texturing and streaming mip ownership **GFX-05/DATA-05/GFX-03**, no independent WORLD-04 resident texture table. Height/slope procedural auto-masks as authorable proposals, manual masks highest authorized priority under approved layer precedence.
- Transition terrain↔mesh/road/river shoreline requires exact world-space anchor, source GUID, finite geometry, correct decals/height cuts, shared GFX-05 texture semantics and WORLD-03 residency; cave/road authoring outside generic heightfield data when topology differs. HLOD and meshlet batching belong GFX-04, shader feature capabilities belong GFX-02/01.

## 5. Vegetation, foliage/wind and biome semantics
- `BiomeZoneV1` holds stable authored zone ID, region, environmental profile and material/foliage palettes by AssetId; blend weights and manual override priority; `VegetationInstanceGroupV1` holds deterministic stable placement IDs, per-instance transform+prototype asset, density constraints, material alpha policy, wind mask and source revision. WORLD-04 owns **authored placement and grouping**, WORLD-05 owns generator rules/seeds and generated proposal provenance; grouping must not create hidden duplicate ECS authorities.
- GFX-04 selects instancing/batching and distance/occlusion LOD; GFX-05 material & alpha; GFX-06 shadows; GFX-07 temporal/reactive; GFX-08 weather particles; PHYS nav/collider constraints. Decorative grass can have no collision; gameplay trees/rocks need PHYS-authorized collision and WORLD-03 pin to prevent disappearing walkable supports. Default shader wind displacement is **visual**; authoritative physical wind belongs simulation/GAME/PHYS, not inferred from GPU sway.
- Vegetation LOD changes and billboard transitions should preserve perceived silhouette/lighting/shadow budget, avoid popping/alias and excessive alpha overdraw with signed measured **visual error plus p95/p99**. Scene-cell unload must release GPU buffers only after GFX-03 fences and PHYS owner release and must not duplicate vegetation on reload.

## 6. Water, coast and gameplay boundary
- `WaterBodyV1`: stable scene/source ID, class `OCEAN/LAKE/RIVER/LOCAL`, 2D region+height/flow hints, shore mask, water material asset, optional authored wave and weather visual profile; `WaterVisualPlanV1`: finite wind/current visual parameters, projected wave LOD, foam/wetness masks, shoreline depth, temporal/reactive flags, GFX-05/GFX-07 surface shading. Ownership PHYS of buoyancy, collisions/flow volumes and GAME/NET of authoritative water/wetness gameplay state.
- Portable surface reference: **deterministic simple Gerstner-style visual waves or baked height/normal fields** for limited tier, optional spectral/FFT visualization only if compute backend/profiling/support proves benefit; no promised FFT/ocean on WebGL2. A visual wave shader must not move PHYS water surface unless an approved CPU reference or sampled authority contract, and no “physically accurate” claim absent measurement.
- Reflection/refraction priority with GFX-05 material/GFX-07 post: screen-space color/depth approximate, environment probes or feature-gated planar reflection. Off-screen reflected geometry and transparent layering cannot be guaranteed by SSR; refraction and foam masks require depth/order checks and scene-linear alpha. Water/terrain intersection at coastline must not open cracks under LOD, streaming or origin shifts.
- Underwater transition is a typed camera/water volume input; GFX-06 fog, GFX-07 color post and AUDIO filters by their owners, not a new WORLD-04 full-screen effect. Weather rain splashes call GFX-08. Physics boats/AI river navigation are not implemented by this research.

## 7. Atmosphere, day-night, cloud/weather and source of truth
- `EnvironmentProfileV1`: authored sky and atmospheric parameters (sun/moon direction candidate, planet radius/albedo/pressure/altitude ranges where relevant), time-of-day **visual** settings, weather zone reference, cloud coverage/wind and precipitation VFX intents. `EnvironmentStateSnapshotV1` carries authoritative GAME/server weather and tick+WorldEpoch+revision, receives periodic typed change. WORLD-04 produces visual state and profile; GAME/NET owns weather gameplay truth and synchronization, CORE-06 owns clock. In a server headless sim, there is no mandatory GPU sky renderer.
- GFX-06 owns physical-sky light/fog/irradiance, GFX-07 HDR/exposure/temporal/color and GFX-08 rain/snow/mist particles. Bruneton's precomputed scattering **BSD** code is a future GFX owner option, not a dependency. Analytic/gradient sky is fallback for WebGL2/mobile; precomputed LUT atmospheric scattering and cloud volumetrics **optional capabilities** after named GPU and temporal history tests. No unbounded clouds volume allocated by WORLD-04.
- Weather visuals may include rain/snow particles GFX-08, ground wetness/snow material GFX-05, shadows and sun GI GFX-06, audio AUDIO, water waves WORLD-04 visuals; they share a typed `WeatherVisualIntentV1` revision/time rather than ad hoc duplicated clocks. Lightning impact/physical wind/snow accumulation in physics/gameplay remains GAME/PHYS authority. No “realistic climate solver” is implied.
- Visual quality must be measured for sunrise/sunset, cloud edges, haze/fog, shadow direction, time-lapse, fast weather transition, HDR vs SDR, light leaks, temporal ghosting and color accuracy across native/Web tiers. Avoid automatic double tonemap or physically inconsistent exposure.

- Data budgets enforce maximum brush radius/patch count/decompressed heightmap bytes, height NaN/Inf/malformed image, adversarial splat layers, grass instance count, GPU draw overdraw, weather LUT resolution, web texture limits, procedural rule recursion (WORLD-05) and network authority. Each tier requires explicit visual degradation receipt and pixel-diff/physics fidelity threshold; not promise pixel-identical output.
