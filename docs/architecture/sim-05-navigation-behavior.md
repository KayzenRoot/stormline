## 1. Product objective and acceptance
Original Stormline-owned navigation and behavior architecture for top-down 2D, 2.5D and 3D character or creature agents; native Windows/Linux/macOS, optional WebAssembly, headless server, Editor and common CLI/MCP authoring. Catalog acceptance is **NPCs navigate a dynamic world under streaming**, to be validated with built fixtures, genuine movement and reproducible CPU/memory/latency metrics, not satisfied by documentation.

Separate (a) globally admissible paths and topology, (b) local motion/collision avoidance, (c) authorized character motor intent and (d) behavior/perception/gameplay decisions. Never treat a path polygon or local avoidance velocity as a guarantee of physically traversable contact; only SIM-01/02/03 collision owner can approve motion. Headless CPU is baseline. No GPU-dependent AI correctness; no request for LLM cloud inference is required or approved for NPC logic.

## 3. Navigation representation and 2D/3D profiles
**3D grounded profile candidate:** tiled Recast build from validated static authored source geometry, voxel walkable clearance/radius/height/slope/step profile and agent traversal masks. Recast is **offline/bake responsibility coordinated through DATA-03/05**; Detour candidate executes runtime query/path over validated cooked tiles. Nav query must return path corridor topology with tile versions and explicit completeness/cost metadata. Terrain/obstacle geometry and physics collision publication are distinct; NAV tile activation only after source/revision/PHYS readiness barrier, and deactivation before traversability assumption expires.
**2D/2.5D candidate:** planar 2D grid, portal graph or 2D polygon/navmesh separate from 3D heightfield. Platformer semantics require jump/drop/ladders as authored capability-gated **off-mesh edges**, not generalized walkable planar geometry. No implicit 3D navmesh projection to support side-scroller or flying gameplay. Air/sea/vehicle steering is FUTURE and requires their own owner-specific navigation domain/constraints.
**World topology:** NavWorldId/epoch, NavTileId/coverage revision, source geometry/collider hash and optional portal/cluster graph. Negative/worldwide coordinates use CORE-05 checked math, no 32-bit tile key wrap, stable cross-tile edge stitching and explicit border resolution. Navigation tiles may reside at different source revisions only where a validated compatible boundary exists; otherwise a typed stale/incomplete result. Cache/pinning/eviction coexist with WORLD-03 leases and DATA-05 cooked bundles; never keep dereferencing freed tile memory.

## 4. Tiled generation and safe streaming publication
1. WORLD-03 announces loaded source CellId / content revision and leases, WORLD-04 terrain geometry, PHYS collider revision and DATA-05 cooked NAV source.
2. DATA-03/05 validated cook tool (future) produces bounded nav tile blob and integrity manifest recording builder/coordinate version, agent profile, voxel params, area classes, neighbor seam signatures, obstacle/collider hashes and third-party pin; no silently manufactured ground. Runtime must verify source and length/hash/schema before admitting.
3. SIM-05 stages NAV tiles on worker job with cancel token and bounded memory, checks walkable polygon/connectivity, tile limit and world epoch.
4. At the **defined CORE-04/WORLD-03/PHYS safe commit barrier**, publish new NavTopologyEpoch with immutable adjacency snapshot and pending→valid transition, after physics source readiness. Paths pinned to previous epoch must be invalidated/revalidated or consume a finite lease with explicit stale semantics.
5. A cell unloading revokes NAV coverage and path safety before or atomically with PHYS ground revocation. Incomplete queries surface PATH_PARTIAL, NAV_PENDING or NAV_UNAVAILABLE rather than a fabricated successful route.
6. Dynamic obstacles: split cheap local avoidance of moving agents from tile-affecting obstacles that require bounded topology update/re-bake, and from true collision that SIM-02 resolves. DetourTileCache is a candidate, **not guaranteed arbitrary mesh edits or instant rebake**. Large terrain edits and doors need source-revision dependency tracking and measured update latency.

## 5. Global planning and path contracts
A* on portal/nav polygon/cluster candidates with strictly nonnegative finite costs, stable tie-breaking per reproducibility profile, explicit max visited nodes/queue capacity/tick budget and cancellation. Detour poly-ref and query filter classes remain private backend details; engine-owned path waypoints/corridor IDs, projection/height and area/capability types are public.

**Cost model:** area base cost, designer-authored penalties, agent permissions/traversal ability, optional dynamic threat map with source/expiry. Every cost is bounded, monotonic where heuristic admissibility matters, and cannot be supplied by untrusted LLM tool input as arbitrary executable formula. Negative/NaN cost, invalid polygon, unreachable goal and too-expensive route yield typed errors; path length/optimality must be proven under a specified heuristic and cost policy. A path through off-mesh edge requires explicit owner authority, candidate ability and availability (ladder/jump/elevator/door), and motor/physics acceptance when actually traversed. Unloaded target may be PENDING, never confidently REACHABLE.
**Large worlds:** hierarchical portal/sector routing is an optional tier after simple tiled Detour correctness, with bounded frontier and signed lease coverage. No guaranteed arbitrary-size path without streaming/prefetch and failure receipts.

## 6. Steering, agent movement and congestion
Global path -> waypoint/corridor -> finite speed/acceleration/turn desired velocity -> local obstacle/crowd avoidance suggestion -> **SIM-03 CharacterIntent TickId** -> authoritative MotorMotionReceipt -> confirmed nav location and velocity. Local collision response must consume SIM-02 contacts/physical obstacles, not assume RVO guarantees zero collision. Native DetourCrowd and RVO2/ORCA **alternative candidates**, not combined by default. RVO2 C++ canonical library handles 2D planar avoidance (for 3D ground navigation, explicitly pick XZ plane with altitude/vertical awareness from collision world); does not magically solve flight and vertical 3D multiagent avoidance.

Congestion handling: density/occupancy feedback, reservation for narrow doors and link crossing, deadlock detectors, bounded reroute/backoff, fair priority scheduling, re-path hysteresis and oscillation/stuck counters. Prevent starvation or exponential reroute storms, and report blocked/unknown paths. Projecting to nearest nav polygon must not teleport agent to valid ground or transform physical body. Sleeping/distant NPC LOD may reduce visual/decision frequency, but keep authoritative server actions and collision-required state under GAME/NET contracts.

## 7. Behavior trees, statecharts, blackboard
Stormline-owned typed, versioned **BehaviorGraphV1** with condition/action/decorator/sequence/selector/parallel (bounded policy) nodes and **StatechartV1** for lifecycle/tactical states. Compiled graph source is a finite allowlisted declarative DAG/BT and explicit state cycles with depth/transition-per-tick cap, stable NodeGuid and deterministic order; no arbitrary code eval in authored graph.
**Tick semantics:** priorities & per-agent utility/cooldowns run against a pinned WORLD/PHYS/perception snapshot. Actions output command intents (MoveTo, Stop, LookAt, AttackRequest) through GAME/SIM-03 capability gates, never direct damage, teleport or mutation. Async task nodes have lifetime token, wakeup, timeout, cancel/idempotent completion. Transitions/interrupts must safely clear queued intents. Blackboard schema has scoped keys, typed values, revision, actor ownership, TTL, size/quota and explicit secret/PII restrictions; no unvalidated arbitrary JSON, function pointers or private memory snapshots.
**BT vs statechart:** compose small statechart lifecycle with bounded BT tactical actions and tests of failure/cancel. No forced adoption of vendor BT.CPP runtime or [Boost::ext].SML in SDK; comparator benchmarks must prove fit/cost and XML/plugin security must be reviewed. Graph editor belongs EDIT-06; no mandatory third-party paid GUI or proprietary Groot2 obligation.

## 8. Perception, memory and stealth/ARPG cases
Perception = observation candidates from WORLD-03 index + PHYS ray/shape occlusion + GAME combat/team policy, not unlimited full-scene reads. Profiles: vision cone/FOV/range, sound stimulus provided by AUDIO/GAME, proximity, damage-origin, last-known position, suspicion meter, faction relation; conservative LineOfSight requires validated resident geometry/ColliderRevision, typed MAYBE/UNKNOWN when visibility obstructed by unloaded cells. Include event Timestamp/TickId, source permissions, confidence and expiry; clear stale memory on destruction, warp, origin rebase and world unload. Perception observations are not unquestionable truth: Game authority validates attack damage/detection and NET privacy policy filters enemy knowledge.

Privacy: clients must not receive hidden AI target locations from blackboard/debug telemetry; server decides replication of perceptions. Editor/CLI/MCP may inspect authorized agent state with paging/redaction, but remote instructions cannot spoof line-of-sight or NPC authority, create arbitrary code or access credentials.

## 9. Tick ordering and replay proof
Fixed CORE-04 TickId owner. Suggested staging at barrier: WORLD-03/PHYS source publish -> immutable navigation/perception snapshot -> bounded perception update -> BT/statechart decisions -> path query or path follow -> steering suggestion -> SIM-03 intent for admissible target tick -> SIM-03/PHYS committed motion receipt -> next NAV state. Exact phase/tick relationship subject to actual CORE-04/SIM-03 integration to avoid same-tick cycles; pipeline must declare whether AI consumes last committed physics snapshot and queues next-tick intent, and must test no unintentional one-frame advantage. Path/planning jobs started asynchronously are stamped with WorldEpoch/TopologyEpoch/AgentGeneration, source filters and expiration tick, and validated at commit. Engine-wide cross-OS bitwise determinism is NOT proven; replay logs require pinned numeric/toolchain/backend/graph revisions and command order.

## 10. Threats, failure and backpressure
Reject malformed NavMesh vertex/poly data (integer overflow, out-of-bounds indices, non-manifold off-mesh refs), decompression bomb, untrusted cost/graph cycle, NaN/negative cost, stale tile/agent generation, unbounded path search, malicious perception data, hidden-world leak, unsafe plugin and AI-generated commands. Use strict CPU, heap, per-agent query/event, tile-count and graph-depth quotas; cancellations/timeout receipts. On any uncertainty, downgrade to NAV_PENDING/UNKNOWN or stop, NEVER mark terrain as traversable. Fuzz import+navigation parser at DATA-03/05 seam and run sanitizer/TSan in future code WO.
