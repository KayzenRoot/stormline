## 1. Mission and acceptance proof boundary
NET-03 generates *only permitted, relevant, bounded* network representations of **already committed authoritative world state** for individual authenticated peer sessions. Catalog scope: **State snapshots, delta, relevância espacial, prioridades e compressão.** Catalog acceptance: **"Teste de 8/16/32/64 clientes quando perf target definido."** 8/16/32/64 are **future workload axes**, not approved player counts, p99 latency targets or shipping guarantees. Security first: **authorization is not relevance**; distance, line of sight, ownership or "can replicate" flags cannot grant a secret. Server cannot send arbitrary whole-world snapshots or unfiltered actor inventories, even on reliable channels. Never claim anti-wallhack entirely solved by interest filtering: rendered occlusion, inference and timing side channels require NET-06 game-specific threat analysis.

**Three immutable boundaries:**
- **Authority:** NET-02 validates client action intents; CORE-04 fixed TickId/CORE-03 write barrier + WORLD-01 authoritative ECS + GAME-04 accepted commands produce committed state. NET-03 cannot mutate world, game event receipts, authoritative inventories or client gameplay rights.
- **Eligibility:** NET-05/NET-02 authenticated session, game/match/role/fog/owner authorization, field-level visibility, and world epoch are checked **before** any shared extraction, cache, delta, compression or serialization. Unauthorized data is never included in a shared public buffer or player cache. Spatial/visual interest then narrows authorized candidates.
- **Delivery:** NET-01 bound encrypted reliable/unreliable transport capability and congestion/backpressure; NET-03 owns bounded per-connection send selection, snapshot/delta baseline and authoritative replication ACK, not TLS/QUIC congestion/crypto/reconnect or application game commit.

## 3. Five-stage replication pipeline (concept only)
```text
CORE-04 TickId -> WORLD-01 committed immutable snapshot/ChangeJournal + GAME-04 receipts
     -> Server authority policy: match/role/actor/secret field ALLOWLIST before raw extraction
     -> Candidate interest: WORLD spatial-cell query, view/LOS/team/fog, hysteresis/cooldown
     -> ReplicationObjectV1 stable EntityId+generation and per-field allowed projected state
     -> per-client baseline/visibility epoch + delta/change-mask + quantization
     -> bounded priority scheduling, fair bandwidth budget, dependency ordering (spawn before update)
     -> optional per-approved-context compression (no secret + chosen text reflection)
     -> size/capability/MTU and NET-01 send admission -> datagram/stream
     -> explicit app-level baseline receipt (NOT QUIC ACK) and bounded history / resync
          Client: validated decode -> immutable display state -> NET-04 prediction/view
```
**Shared-work rule:** it is safe to share canonical *public-visibility identical* quantized object state within the **same security cohort and matching schema/source revision**; never share owner/private field material or unfiltered packet/ciphertext between distinct principals/roles. Partition caches by MatchId, WorldEpoch, visibility policy/version, role, recipient scope and content schema, with explicit invalidate on authorization change. Security-first correctness may cost CPU; only benchmark validated cache partitions.

## 4. Entity lifecycle and snapshot identity
- **`ReplicationObjectIdV1`** derives from WORLD-01 `EntityId+generation`/world epoch, not memory pointer or user-chosen actor path. Spawn/destroy/reparent/stream-in/stream-out must have stable ordered dependency references (world -> parent -> child -> component), and receive idempotent lifecycle receipts.
- **`ReplicationFrameV1`** authoritative SnapshotSeq/TickId + schema/hash, session/match/world/visibility epochs, baseline reference, projection-set digest and item type IDs. SnapshotSeq is per-replication stream; wrapping needs modulo policy and epoch fencing. No "latest packet timestamp" identity.
- **Full baseline** for join/resume/change of scene or invalid reference, then **delta** only against an **application-confirmed** usable baseline for same recipient, world generation, security policy and schema. Future out-of-order ACK window/bitset tracks confirmed received frames. QUIC/native transport ACK *does not prove* client's decoder applied baseline. Missing/evicted baseline -> bounded fresh keyframe/reset/resync, never decode using unrelated player's cache.
- Snapshot updates may be unreliable/loss-tolerant under NET-01. Gameplay-critical spawn/despawn/visibility revocation might require a separately approved reliable ordered *lifecycle* channel or refreshable idempotent state; reliability of a transport stream is not a guarantee client rendered/forgot secret. **Unauthorized data must not be sent after revocation**, and client purge instructions cannot cryptographically retract data already disclosed. Revoke/visibility change rotates stream visibility generation, invalidates projection/baseline caches, stops future sends and optionally emits safe despawn/clear; a malicious former recipient may retain prior data.
- Immutable field projection with explicit **PUBLIC, OWNER_ONLY, TEAM_ONLY, SPECTATOR_WITH_PERMISSION, SERVER_ONLY** policies, capability and match scope. Materializing object name/id alone can leak hidden entities: hide presence, bounding location, counts, delta size and error messages where threat model demands. Never "replicate all, encrypt packet" as replacement for authorization.
- Occlusion and fog visibility are game policy, not renderer z-buffer claims. World cell intersection is **relevance optimization only**. Role ACL and intentional prediction disclosure need game-specific owner validation. Teleport/scene stream/world origin shift resets candidate sets/hysteresis carefully. Interest changes in one tick must not deliver stale queued private updates after revocation.

## 5. Relevancy algorithm and priority policies
**Candidate algorithm:** leverage WORLD spatial index (uniform grid/hash for local worlds, BVH/octree for dynamic 3D, tile/chunk for 2D, scene portal/group for interiors and large-world cells) as **query inputs**, not a NET-03-owned second spatial DB. Compose broadphase query -> authorized filter -> scene/team/fog/LOS predicate -> consistent distance/frustum/owner rules -> per-recipient stable relevant set with configurable hysteresis/enter/exit grace. Hysteresis must *not* keep unauthorized objects in view once access revoked. User configurable rules are sandbox/capability checked, budgets for per-tick tests/LOS/alloc. Server retains final decision; client interest request is untrusted hint, not authorization.
**Scheduling:** `ReplicationPriorityPolicyV1` ranks objects by criticality of visibility revocations/lifecycle, owner/interactive nearby, movement relevance, age since last send, delta bytes, rate debt and starvation protection. Weighted deficit round-robin (or equivalent bounded fair scheduler candidate) across clients/channels/objects with explicit min/control budgets and aggregate host rate; **no guarantee every object is updated each tick**. Event-driven change journal suppresses unchanged objects but an idle baseline refresh/keyframe policy must prevent permanent stale state; high priority never bypasses access controls. Quantitative priority weights and updates Hz remain TBD and must be measured. NET-01 congestion level/PMTU is a **hard ceiling** not something the replicator can circumvent.
**Time:** server simulation tick, replication send tick and client interpolation clock differ. Send cadence may decimate snapshots relative to simulation TickId. NET-04 owns the interpolation/prediction buffers and causal input reference. Under network badness, prefer stale cosmetic expiration/drop to unbounded backlog, while correctness-critical lifecycle/data uses explicit ack/retransmit policy.

## 6. Change tracking, delta and serialization safety
- **DATA-04** owns semantic versioned serialization schemas and source data model; NET-03 defines a **network projection/codec profile** derived from approved DATA-04 schema with distinct wire negotiation and backward-compatible migration policy. Source save IDs and durable source CAS are not runtime packet ACK or network baselines.
- `ChangeMaskV1` per typed field/component may use dirty bits/change journal, but "dirty" doesn't mean allowed for every client; compute recipient/role-specific projection. Delta per recipient only against acknowledged canonical quantized values; avoid comparing raw floats/NaN payload byte equality without pinned semantics.
- Quantization includes range, origin, coordinate units (CORE-05), bit count/scale, rounding/saturation, signed/unsigned overflow, NaN/Inf rejection and quaternion/rotation stability, with separate profiles 2D, 3D, velocities, gameplay health and animation. Critical exact values must not be lossy if game rules or player entitlement require exactness. Quantized network value **never becomes authoritative server ECS state**.
- Choices: full snapshot vs XOR/change-mask, bitpacked array, delta-of-delta, small dictionaries, LZ4/Zstd frame compression. **Per packet compression may lose against headers/CPU** for tiny deltas, and compressor output may expose secrets through length correlation. Compress only after recipient authorization, with per-message size+CPU+decompression budgets, approved dictionary provenance and no secret/chosen-attacker-reflection mix without threat review. Disabled-by-default for sensitive mixed data until side-channel safe policy proven. Strongly separate stream of OWNER_ONLY fields from attacker-controllable public strings to mitigate BREACH-style leakage. Compression algorithm/level, dictionary and license not selected.
- Serialization must reject unknown required versions/fields, malformed varints/offset, oversized entity counts, recursion/decompression bombs and stale/world-epoch mismatch without allocating unbounded memory. Bit-level schema must be well-defined including endianness and alignment. Use exact backend cryptography NET-01 rather than "encrypting by compression".

## 7. Dynamic reference dependency + privacy
Critical spawn/ownership field before entity update; destroy/visibility revoke fences obsolete deltas. Object reparent, spawn flood, resurrect-with-same-index and cross-match interest need stable entity generations. Data buffered for peer A must never be accidentally routed to peer B after reconnect, and server must never send match A fog or private inventory to another match. Some entities require *anonymized* representations instead of full identity when client can see effects but not hidden enemy identity; this is explicit GAME-04 information policy, not a generic "always send proxy".
- Auditable projected field set and recipient role policy snapshot version; compare allowed/disallowed values at **decoded client wire**, not merely server "filtered count". Test spectator/GM/owner/team/fog edge transitions. Validate after a revoked role that no **future** bytes reveal newly hidden state, and snapshots/caches are invalidated. Previously disclosed values cannot be erased from a malicious client.
- Security of telemetry and error paths: never log raw private fields, player identifiers/IP, session keys, full hidden actor lists or decrypted packets by default. Anomaly counters and denial reasons should not expose hidden actor existence to unauthorized users. Controls require future NET-06 review.

## 8. Transport capabilities and target platforms
NET-01 `UNRELIABLE_LATEST` datagrams are a candidate for transient snapshots if MTU/size/expiry negotiated; an independent `RELIABLE_ORDERED` channel carries join/baseline/lifecycle if designed, with explicit in-order head-of-line costs and bounded queues. QUIC DATAGRAM RFC9221 does not retransmit, fragment or promise receipt; native GNS reliable/unreliable lanes and browser WebTransport/WebRTC alternatives have different coverage. WSS reliable stream only, not an invented DATAGRAM feature. Never auto-fallback to plaintext or send a private snapshot over a wrong peer session. The client is a **presentation consumer**; NET-04 prediction/lag compensation not re-implemented here.
