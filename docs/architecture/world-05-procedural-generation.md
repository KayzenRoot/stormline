## 1. Canonical acceptance and core promise
Catalog: **"Mesmo seed + versão produz resultado idêntico; edição manual preservada."** This is stronger than reusing a random integer. Define a *generation identity* tuple with exact frozen generator/graph/schema and asset versions, canonical input encoding, coordinate convention, numeric and algorithm profile, stable seed derivation, source revision and output schema. A same recipe, source bytes and scope MUST produce the same **canonical committed output bytes** under the approved deterministic CPU profile, regardless of thread scheduling, editor-vs-CLI-vs-headless and order in which cells are requested. A changed algorithm/graph/dependency/precision profile MUST advance a recipe fingerprint or report INCOMPATIBLE, not pretend identical results. User-owned manual edits are separate durable overlay source and never silently overwritten by a generator rerun.

Current registry: **26/80 research documented and 54 research pending (including historical CORE-04)**, **80 future code WOs BLOCKED/executor_ready=false**, no actual engine. WORLD-04 and DATA-03 coding #44 and its DATA peer are not merged, so WORLD-05 coding #45 cannot begin. This document prepares decisions/benchmarks only.

## 3. Typed generator DAG and immutable recipe
- \`GenerationGraphAssetV1\` contains stable GraphAssetId/GraphRevision, typed node stable NodeGuid (not visual label or array index), node AlgorithmId+Version+DeterminismProfile, edge stable port names/type/schema, dependency AssetId/content hashes, coordinate domain, numeric profile and project permissions. Graph is **acyclic** by default and evaluated by deterministic topological order with stable NodeGuid tie-break; deliberate iterative solvers (e.g. erosion/WFC) are a single pure bounded *node* with internal caps, not an unbounded graph cycle.
- \`GenerationNodeV1\` typed ports examples \`ScalarField2D/3D\`, \`VectorField\`, \`Mask\`, \`HeightDelta\`, \`BiomeWeightMap\`, \`PointSet\`, \`InstancePlacement\`, \`MeshRecipe\`, \`TileRules\`, \`MaterialMaskProposal\`, \`CollisionHint\` and \`OpaqueCookRef\`. Explicit units/meters/world vs patch-relative coordinates, origin/reference epoch, resolution/sample spacing and numeric domain; adapters are explicit and versioned. Outputs are **proposals**, not raw GPU buffers or runtime entity pointers.
- Finite graph checks: unknown node TypeId or unsupported algo version, invalid port connection/cycles, implicit scalar↔vector conversions, incompatible units/resolutions/color spaces, malformed AssetId or source hash, untrusted executable node/shader, oversized depth/nodes/edges, exponential fan-out, memory allocation/decompression and timeouts rejected **before** partially authored source mutation.
- \`GraphDependencyManifestV1\`: stable node-to-node/asset/content dependency graph, per-output hash, algorithm and asset fingerprints, relevant cells/patches and a deterministic invalidation key. DATA-05 owns actual content-addressed cache/cook/IO; WORLD-05 produces hash keys and graph evaluation provenance. A cache hit with mismatched provenance is a cache miss/fail, never a silent old world.
- \`GeneratorRecipeV1\` freezes seed key format, graph topology+revision, algorithm IDs/versions, asset hash list, parameter canonical encodings/order, precision and coordinate convention, explicitly scoped cell/patch and output type version. Canonical serial form uses explicit endianness, stable Unicode normalization/field order, number format/rounding, no compiler struct padding or transient pointers; DATA-04/05 own storage and bytes. **If any determinism-affecting input changes, fingerprint changes.**

## 4. Seed derivation and bitwise determinism contract
- Propose \`SeedDerivationV1\`: user-authored \`MasterSeed128\` + domain-separated \`{ProjectId,WorldId,GraphGuid,NodeGuid,CellId,PatchId,OutputChannel,ElementStableKey,SampleCoord,Counter,AlgorithmVersion}\`. Hash/PRNG encoding itself must be precisely specified and golden-vector tested (endianness, signed floor, overflow, domain labels); **do not use C++ std::hash, std::random_device, process clock, platform entropy, pointer addresses, order of map traversal, unordered scheduling, native compiler fast-math or ambient floating state** for canonical generation.
- Deterministic counter/keyed streams avoid sequence coupling: changing one node, adding a worker or requesting a neighboring cell cannot advance a shared global RNG and reshuffle unrelated content. Per-node/subdomain counters and stable ordering of candidate points/prefabs preserve unrelated placements when feasible; any intentional topology-dependent cascade belongs a new version and documented invalidation scope.
- **Canonical CPU profile** (proposed): defined integer arithmetic and fixed-point or fully specified floating-point operations/rounding/quantization where possible, stable noise lookup/table/tie-breaks and output encoding. IEEE floats alone do **not** guarantee byte-identical C++/WASM/WebGPU across contraction/FMA/compiler flags/SIMD libraries; require build/toolchain and golden-output byte proof. GPU compute and shaders can be fast approximate **visual previews** with \`NOT_CANONICAL\` receipt; never use them to author persistent gameplay/collision network state unless tests show identical canonical bytes for all supported targets.
- Use stable global sample coordinates for cell seams, not local patch re-seeding that creates border changes. Signed negative coordinate floor division, quantized sample grids and shared halo dependencies (neighbor cells) allow equality on overlapped borders; provide explicit halo radius and upstream footprint. Generation at a different stream tile order/worker count must yield same canonical bytes for equivalent region.
- The guarantee is **same entire pinned recipe+version+source assets+scope → same canonical result**, not a promise that all different versions of FastNoiseLite/OpenSimplex2 or all GPU shader implementations output identical noise. Version compatibility/migrations require explicit recorded regeneration/preview/approval, never silent replacement.

## 5. Algorithm palette and constrained solvers
- **Portable baseline NECESSARY:** seed→noise field and composable arithmetic/mask/domain warp, fractal ridged octave and remap/threshold, region masks, slope/altitude rules, stable density/Poisson-like point candidate placement, authored-biome point and foliage group proposals and terrain height deltas. Deterministic independent candidate keys are mandatory. Avoid inventing physically correct erosion/river networks or a full CSG/BREP mesh engine from a scalar field; those are optional future specialized algorithms after DoD.
- \`FastNoiseLite\` MIT (Perlin, Cellular, Value, OpenSimplex2 variants, domain warp) optional adapter; \`OpenSimplex2\` source README states mostly **CC0** and certain directory files **Unlicense**, exact file audit mandatory; neither is automatically selected as canonical without exact golden outputs/portability.
- Optional \`WaveFunctionCollapse\` MIT constraint/tile solver: weights/adjacency input with licensed source patterns, stable entropy/tie-break and bounded backtracking/restarts. **WFC can hit contradictions, and solvability/termination at arbitrary size cannot be guaranteed**; return typed \`CONTRADICTION\`, \`NO_SOLUTION_WITHIN_BUDGET\` or deterministic fallback defined by the authored graph, never infinite retries or silently invalid tiles. Sample images/tilesets have independent attributions/rights, no copied art.
- \`Random123\` (counter-based RNG, upstream BSD-style) optional algorithm reference. Random streams here are **not cryptographic/security tokens**. Cryptographic authenticity/integrity hashes of imported asset bytes handled via DATA-02/03/05 security owners, not mistaken for PCG seed generator.
- \`Unreal Engine PCG\` and \`SideFX Houdini PDG/Engine\` are proprietary workflow references, not mandatory SDK, engine dependency or permission to copy node graph/source/assets. Blender Geometry Nodes if used as an external reference/tool has GPL tool/code terms and distinct media asset rights; no mandatory integration.
- **Advanced OPTIONAL**: flow-accumulation rivers, erosion/hydrology, L-system plant and structure grammars, road/building network graphs, WFC dungeons/towns, neural/LLM-generated procedural rules only behind separate owner-approved security/perf/source licenses, constrained solver validation, no scripts executed automatically from AI prompts. Numeric seed version and generated provenance applies uniformly to any adopted algorithm.

## 6. Chunk/region independence, content identity and handoff
- \`GenerationScopeV1\`: immutable project/world/graph/algorithm/asset revision and canonical global \`CellId\` or terrain \`PatchId\`, resolution and halo. WORLD-03 requests generation **intent** based on streaming interest and budgets; no synchronous main-thread random expensive generation. DATA-05 has staged cooking/caching; source WORLD-04 authored patches/biome/masks and WORLD-02 scene/prefab are never overwritten by a background callback.
- \`GeneratedArtifactProposalV1\`: type + content hash, source recipe fingerprint, seed trace hash, algorithm versions, output ID namespace, world/patch/global bounding refs and optional producer diagnostics \`DETERMINISTIC_PROVEN/NOT_VERIFIED/NON_CANONICAL_PREVIEW\`. A stable generated placement ID is derived from immutable graph/node/channel/global sample key and scope, never volatile traversal ordinal alone; duplicate collisions must fail typed before publishing.
- Neighbor edge conditions must be deterministic: each patch computes halo in canonical global coordinates and uses explicit shared stage/fixed dependency versions; cross-cell roads/rivers/biomes/vegetation dedup stable ID and owner-cell single authority. For algorithms requiring a larger global context (rivers/hydrology/WFC), declare bounded **region graph scope** and solve in a deterministic shared region, not pretend arbitrary independent tile seeds yield contiguous content.
- \`GenerationPlanV1\`: graph DAG validated, range of affected outputs, estimated CPU/memory/cache IO and impact on manual authoring and stream residency. Tasks cancellable by world/recipe revision, generation token and owner caps; stale async completion discarded. Stage->Preview->Validate source and rights->DATA-04 commit author-approved recipe/overlay changes->DATA-05 cook->WORLD-03 cell safe publish after WORLD-04/PHYS/GFX ACK. Distinguish **source committed** vs **runtime published**; crash/fault uses last-good scene and idempotent recovery. Editor and headless use the same canonical CPU evaluator.

## 7. Preserve human authorship across regeneration
- **Generated base != manual edits**. DATA-04 stores durable \`ManualAuthoringOverlayV1\` with explicit stable node/patch/material/instance target IDs, override key and author/scene revision. WORLD-04 owns actual sculpt/paint/biome and foliage authoring semantics; WORLD-02 owns prefab/scene override semantics. WORLD-05 proposes changed base fields/geometry/placements and computes affected **provenance-aware diff**; it must never modify durable manual overlay or write scene assets directly.
- On regeneration \`OldGeneratedBase\` (base), \`NewGeneratedBase\` (theirs), \`ManualOverlay\` (ours): for unmodified source target, accept the new generator result; for manually overridden field retain author value and record new generator revision. If generator deletes/moves a node that the artist edited, return \`ORPHANED_MANUAL_EDIT\` and options \`PRESERVE_DETACHED/REMAP_WITH_APPROVAL/DROP_EXPLICITLY\` with rights and preview; **no silent discard or auto-flattening**.
- Independent stable generated ID and tombstones for **suppressed procedurally spawned objects** prevent a deleted rock/tree from respawning on every recook. Artist-added objects remain separate from generated candidates and are never implicitly cleared. If algorithm version changes IDs, require explicit migration/rebase mapping preview and conflict approval.
- Editor/UI/CLI/MCP parity: \`InspectGenerationGraph\`, \`PreviewGeneratorScope\`, \`CompareRegeneration\`, \`InspectGeneratedProvenance\`, \`StageGenerationGraphEdit\`, \`Validate/CommitRecipeEdit\`, \`StageApplyGeneratedProposal\`, \`Undo/Redo\` via DATA-04. Every mutating action includes scope/role/CAS/size/dependency approvals, no host executable graph node, Python script, shader injection, arbitrary filesystem/URL, cross-project assets or privileged NET/gameplay changes. A preview cannot alter durable scene or live-world authority.
- Deterministic output cannot make **all gameplay choices** deterministic automatically: runtime actor behaviors, physics and server weather decisions are PHYS/GAME/NET owners. Generator content is authored/cooked input; server authoritative scenes must be certified/hashed and broadcast at right revision, not regenerated differently per client.

## 8. Safety, performance and proposed R&D
- Threats: malicious graph with cycle/deep recursion, incompatible port type/units, exponential fanout, arbitrary untrusted code/plugin, SSRF/import traversal, untrusted asset binary, WFC exponential constraint solving, malicious seed exhaustion, negative/overflow global grid, cache poisoning, nondeterminism or per-worker RNG coupling, stale task publishing after teleport/revision, PHYS collision mismatch, sensitive source content leaked via MCP.
- Budgets: max nodes/edges/iterations/retries, output points/instances/geometry bytes, per-cell/global work and preview vs canonical CPU milliseconds, peak resident/staged bytes, worker memory and cancel/retry, source/prefab/collision downstream recook cost; numeric thresholds remain **UNDECIDED** until 1.0 DoD hardware/workload. Always report exact elapsed p50/p95/p99 and cache stats in future, not invented “infinite world” support.
- Optional **SCDI (Stormline Canonical Dependency Invalidation)** PROVE-OR-DROP: hash subgraph/node inputs to recompute only causally affected patches while preserving deterministic canonical output. Compare to full rebuild oracle on identical edits; if hidden dependencies or halo/neighbor changes produce stale content, DROP. A faster wrong generated scene FAILS.
- Native Windows/Linux/macOS and browser WASM CPU canonical, headless dedicated server, WebGPU optional visual preview and WebGL2 fallback editor/viewer must have independent golden fixture and source hash. No claim of bitwise cross-platform determinism until actual compiler flags/CPU float settings are tested, and no GPU/CPU bitwise parity assumed.
