## 3. Dual index architecture: streaming grid and hot spatial query
- **Coarse streaming partition** candidate: sparse hashed grid of `WorldCellIdV1` indexed in global integer 2D X/Z or 3D X/Y/Z coordinates, optional hierarchical cell levels for broad terrain/distant content. The chosen 2D/3D partition is a per-world policy with vertical stacking or special volumes; **not** a fixed universal square grid. Large objects overlapping many cells are represented by stable owner cell + references, counted exactly once per scene instance, not duplicated physical entities.
- **Hot dynamic query** candidate: loose dynamic AABB tree/BVH or independently benchmarked R-tree/loose octree inside loaded cells, to return entities/volumes for interest, proximity, spherical/capsule/AABB sweeps. World-03 owns spatial metadata and CPU query indexes, GFX-04 owns final frustum/occlusion/mesh visibility and PHYS owns collision broadphase; do not reuse a simulation index as an unsafe replica of the physics world.
- `SpatialQueryV1` has bound shape, global coordinate epoch, exact/approx mode, stable world/scene identity, filtering and ordering, maximum result/pagination. Indexes may provide **conservative candidate sets** (false positives allowed but bounded) and typed `MAY_BE_INCOMPLETE` for unloaded cells; never advertise exact full-world hit/absence when data is not resident. For an **exact** query, use reference intersection refinement on returned candidates and explicit unloaded-world completeness; the index alone is not proof of visibility or collision.
- Cross-cell objects: owner cell determined by checked centroid/anchor and bounding box with one canonical `EntityGuid`, referenced in other cells via light indirect proxy. Movement crossing boundary updates metadata at a tick fence with dedup, atomic old/new membership publication, no double spawn/destroy. Velocity-expanded bounds and cell-border overlap can reduce thrashing.
- Candidate indexes to benchmark: flat sparse hash uniform grid for near-O(1) cell lookup on uniform worlds (not guaranteed big-O for arbitrary adversarial hash); loose octree/quadtree for nonuniform distribution, R-tree/R*-tree (Boost.Geometry.Index BSL-1.0, libspatialindex >=1.8 MIT) for spatial queries; optionally BVH for immutable cooked cells. No library adopted and no patented speed claims. Benchmark correctness vs brute-force oracle and worst-case clustering/updates, not only average insert throughput.
- `SpatialCellCoordV1` should use checked signed wide coordinates with floor division for negative coordinates and overflow checks, independent of global render-float origin. Exact integer width/cell resolution remain 1.0 DoD decisions. A local floating origin must never change cell identity or persisted GUID and must not break GFX/PHYS/NET payloads.

## 4. Interest sources, residency and priority planning
- `SpatialInterestSourceV1`: source id, Project/World/authority, owner `PLAYER/CAMERA/AI/QUEST/NET/AUDIO/EDITOR`, pose and velocity horizon, radius/shape, layer/quality priority, required completeness, tick/epoch and explicit capabilities. Sources contribute to a **union** with priority/quality tier, not an implicit camera-only strategy. Separate **render interest** (camera/LOD) from **simulation-critical interest** (collision/quest/AI/server), which may remain pinned when offscreen. NET is owner of authoritative replication filters.
- `CellResidencyPlanV1` chooses cells `REQUIRED_PINNED`, `PREFETCH`, `OPTIONAL`, `EVICTION_ELIGIBLE` with predicted priority based on velocity direction, explicit mission portals, nearby active agents and memory quota. Lookahead time/expand radius are bounded and inspected for over-prediction under fast camera movement. Teleport triggers **priority reset and request cancellation** for obsolete speculatives, keeps old scene coherent until critical new readiness or an explicit safe loading barrier.
- Hysteresis on enter/exit distances, minimum dwell and cooldown stops threshold thrash. LRU/clock eviction only for **unreferenced, unpinned, zero-leases and post-fence** cells. No eviction of player support collider, live network authoritative entities, actively referenced scene or current audio when not released by owners. Force-budget violation must return explicit `BUDGET_UNSATISFIABLE` / safe loading-state, never delete critical simulated state or accept OOM.
- Multi-camera/splitscreen/observer sources share cached immutable bundles but separate view and source-scoped ACL. Editor camera cannot cause simulation authority to migrate, and adversarial remote player must not request the entire world by claiming arbitrary camera coordinates.
- World/scene layer filters may include gameplay DataLayers if owned by WORLD-02 and authorized by GAME/NET. No directly mutable server interest through visual editor panels.

## 5. Async cell lifecycle and versioned publication
`ABSENT -> REQUESTED -> FETCHING -> DECODED_VALIDATED -> CPU_STAGED -> (GPU_STAGED optional) -> READY_TO_COMMIT -> ACTIVE -> COOLING -> EVICTING -> ABSENT` with explicit `FAILED/CANCELLED/RETRY_BACKOFF` transitions and last-good handling.
- DATA-05 performs actual I/O/cook/decompress/caching with content hashes/dependency graph, origin/size/zip-bomb and rights check; WORLD-03 coordinates **intent** and tracks cell `CellGeneration`, `WorldInstanceEpoch`, `SourceRevision`, `TaskToken`. A delayed completed task with wrong generation/world/asset revision is discarded. Cancel is cooperative: stale callback returns receipt, must not publish objects after unload or teleport; idempotent retry capped with exponential backoff/jitter and no infinite busy-loop.
- CPU staged data never becomes live WORLD-01 entities until **CORE scheduler safe tick boundary** and WORLD-02+DATA-04 source revision validation. `Prepare -> Validate Dependencies & Owner ACKs -> Commit -> Publish Complete Cell Snapshot`, using immutable per-tick cell manifest. If runtime publication takes multiple ticks, mark `INCOMPLETE_NOT_VISIBLE` or last-good coherent snapshot: **do not report a partially loaded collider/mesh/AI cell as ACTIVE**. Failures/OOM recover idempotently, with a defined transaction atomicity unit and owner receipts, not a fictional cross-service atomic fsync+GPU+physics commit.
- CPU residency and GPU visibility are **different dimensions**. A headless server has no GPU stage; GFX-03 owns GPU fences/retirement/VRAM. PHYS must acknowledge collision insertion/removal at its safe step, AI/nav should not route into unavailable world as if traversable. NET replication must not signal active entity/state to clients before authoritative readiness.
- `CellLeaseV1` tracks owner/type/generation/expiry and required pin counts. No negative ref-count and no leaking pins through failures/deletes. Asset dedup and absolute cache memory owned DATA-05; WORLD-03 requests predicted and measured quotas and accepts truthful `UNKNOWN` availability, not its own global heap allocator.
- Streaming source can move while async work is in flight. New plan `RequestGeneration` supersedes older plans. Per-world budget and per-owner fair scheduling avoid one client starving local player, physics or loading UI.

## 6. Spatial origin, precision and headless/network consistency
- Absolute global world coordinates and cell keys persist, independent of camera relative origin. `WorldOriginEpochV1` is a **coordinated change request** under CORE-05 transform authority; WORLD-03 detects threshold conditions and proposes candidate shift `{oldOrigin,newOrigin,oldEpoch,newEpoch}`, but physics/transform/renderer/NET owners must ACK before publication. GPU local float transforms should be recomputed relative to fresh origin and GFX-07 temporal histories invalidated, not blindly reinterpret old matrices. Network packets transmit authoritative global or cell+offset semantic positions and origin epoch, **never** assume another client shares the same local rendering origin.
- Multiple observers may need independent local origins; don't force one authoritative global shift solely because a split-screen camera moved. For physics worlds tied to one local origin, the PHYS owner must define deterministic shift barrier/rebase and contact/collision handling, not WORLD-03 overwriting constraints.
- Rebase near cell borders, negative global coordinates, high speed, teleports, multi-player divergence, axis precision and integer overflow all need CPU mathematics oracles; 64-bit floating global positions are a candidate rather than a universal promise. A successful coordinate request never changes `EntityGuid` or durable `SceneNodeId`.
- World streaming **can reduce loading stalls, not guarantee none**. If required cell unavailable, stop/pause/travel-gate at well-defined safe boundary; never silently walk through unloaded collision or simulate with invented ground. Different render/audio LOD may remain degraded while gameplay-critical simulation remains complete.

## 7. Memory, resource and fairness policy
- Budgets: CPU streaming planning `ms/tick`, peak decompressed/staged bytes and pending tasks, DATA-05 disk/network bytes per sec, IO ops and decode CPU, LIVE ENTITY memory, GFX-03 GPU VRAM or UMA and fences, PHYS shape/collision insertion work, editor/headless resident cells, eviction latency and peak transition overlap. Hardware- and platform-specific target values **UNDECIDED** until 1.0 DoD. Separate queue wait vs I/O vs decode vs staging vs publish stall p50/p95/p99.
- `BackpressureReceiptV1` prioritizes mandatory sim pins then visible near-area interest then prediction, without starving async cleanup. At pressure switch to smaller quality tier / increased LOD distance **only through owner GFX/WORLD-04 approved policy**, never lower physics collider quality in a way that changes authoritative movement silently. If mandatory bytes exceed budget return `SAFE_LOADING_BARRIER` and readable reason.
- Publish pressure/lateness separately: an async API can be “async” while still creating main-thread 50ms mesh/physics instantiation stalls. Benchmark must trace all phases to demonstrate acceptance. Touch real platform data: local SSD, HDD, network throttling and browser fetch/cache/worker decode only where named, not assumed. High-latency WebGL2 and no SharedArrayBuffer/worker support can require a bounded main-thread fallback or explicit supported-browser restriction.
- Optional perceptual prediction `SIP: Stormline Interest Predictor` PROVE-OR-DROP. Baseline velocity/lookahead deterministic; any learned predictor must never override required pinned cells/owner security and must beat simple lookahead in miss rate without memory or jitter harm. No claim of original invention/ML agent performance now.

## 8. Safety, testability, Editor/CLI/MCP
- Semantic readonly: `InspectSpatialCells`, `QuerySpatialInterest`, `InspectStreamingPlan`, `InspectCellResidency`, `GetWorldOriginEpoch`, `GetStreamingQualityReceipt`, with bounded pagination and explicit completeness/provenance. Mutating config: `Stage/Validate/CommitWorldStreamingPolicy` only via DATA-04+WORLD-02 source CAS and project/role checks. Client/gameplay interest injection is managed by NET/PHYS owners, never open MCP.
- Reject untrusted remote source coordinate, entity count, extent/bounds, oversized dependency fan-out, duplicate CellId+asset revision mismatch, corrupt compressed payload, zip-bomb, script/shader execution and cross-project cache keys; verify asset signed/hashes/provenance and decompression limits through DATA-03/05. Never let a remote user pin infinitely many cells or leak another world via metadata inspection.
- Spatiotemporal queries and cell-load results carry source WorldInstanceEpoch, canonical Project/WorldId, GlobalOriginEpoch, `AssetHash`, request generation, and "UNKNOWN / MAY_BE_INCOMPLETE" when nonresident. No arbitrary memory addresses or private path disclosures.
- Exact assertions: return exhaustive query hits with reference oracle when `COMPLETE`; release old GPU/PHYS resources only after receipts/fences; preserve living scene source if last IO fails; teleport+generation race never resurrect stale cell or EntityHandle; no main-thread I/O/Zip/physics-ready stall budget violation. All are future tests and **NOT RUN**.
