## Source and trust pipeline (candidate future stage graph)
1. **Source gate:** checkout pinned immutable repository/ref/commit with `contents: read` and no persistence of credentials; validate source pack, approved ADR and Context Lock, declared scope, no allowed engine build until coding WOs themselves have independent owner approval. Current P00 documents only.
2. **Matrix planner:** future approved branch/target triplets with separate compile/host machine and support guarantee; select **named hosted standard runner labels** (`ubuntu-24.04`, `windows-2025`, `macos-26` / `xcode-27` if availability verified), never floating `*-latest` as sufficient toolchain pin. Runner labels are OS *image* families: [GitHub runner images](https://github.com/actions/runner-images) change installed tool versions regularly, so collect exact image version, installed software URL, SDK/compiler hash, linker, CMake, Ninja, libc/CRT and architecture in every receipt. Android/iOS/cross Web targets conditional separate approved budgets.
3. **Bootstrap pinned toolchain:** C++20 compiler family GCC/Clang/MSVC AppleClang and standard-library ABI, CMake Presets/Ninja preferred, `CMAKE_CXX_STANDARD 20` with no silent C++23 promotion, `try_compile` without assuming emulator, SDK licenses and selected runtime/driver dependencies. Cross-compile host vs target cannot be accepted as target host smoke. Never use external “curl | sh” bootstrap, mutable latest deps or unpinned action/workflow versions; third-party Actions pinned to immutable full commit SHA and license checked before future activation.
4. **Fast PR checks**, only after real code exists: deterministic format check (`clang-format --dry-run --Werror` with pinned style), source scope/docs checks, CMake configure and C++ compiler diagnostics (compile/semantic type checking is native C++ typecheck, not an unrelated mandatory TS typecheck), static analyzer (`clang-tidy` pinned + selected check profile), `cppcheck` optional independent, warning policy `-Wall -Wextra -Werror` with compiler-specific exclusions approved. CodeQL C++ is available for public repo candidate; query modes `none/autobuild/manual` differ in generated-code coverage, so choose after actual tests, never assume one is complete.
5. **Unit/integration tests**: future `ctest --preset <name>` with CMake Presets/TestPresets, CTest JUnit XML, per-run timeout, known fixture hashes, deterministic time/RNG/locale, critical lifecycle/headless/thread safe error paths, no display/GPU requirement for headless; targeted integration among modules only when owning modules exist. QA-02 owns broader golden-image/input-audio tests, QA-03 perf, QA-05 actual OS test qualification. No blanket claim of test PASS from a zero-test CTest run: fail if tests expected and count 0 or all skipped/filtered.
6. **Sanitizer lane**: Linux Clang ASan+UBSan and separate TSan concurrency lane when compiler/stdlib/runner supports, never mix ASan and TSan into same instrumented binary; Windows MSVC/Clang-cl ASan only with matching runtime and support; macOS AppleClang ASan and TSan only with actual supported SDK/arch/runtime; MSan **Linux-family only and needs all dependent code instrumented** (not a Windows/macOS required gate). Check unsupported combinations explicitly BLOCKED/UNSUPPORTED with owner justification, not fake green. [Clang ASan](https://clang.llvm.org/docs/AddressSanitizer.html) supports Linux/macOS/Windows with differing limitations; [TSan](https://clang.llvm.org/docs/ThreadSanitizer.html) supports Linux/Darwin but has large memory overhead and no 32-bit, separate quarantine; [MSan](https://clang.llvm.org/docs/MemorySanitizer.html) requires instrumented code, supported Linux/NetBSD/FreeBSD. Sanitizer runtime artifacts must **never ship in production packages**.
7. **Artifacts/evidence**: CI run/workflow attempt/job/runner image digest, base/head/source hashes, compiler/SDK/sysroot/OS tool versions, compile/CTest cases, lint/static scan, SARIF/JUnit logs, error severity and retry/cancel status, generated native artifact SHA and SBOM/provenance if explicitly enabled by downstream owners. Upload logs/test evidence with short retention, size caps, redaction and no binary/public release until approved; no accidental `CI green` because a conditional job skipped. Artifact **not** cache.
8. **Review/merge gating**: isolate trust: untrusted fork PR read-only no secrets, trusted main release workflows separate, no `pull_request_target` fetching and *executing* untrusted fork scripts with write token, no untrusted `workflow_run` artifact promotion. Caches from forks/PRs treated untrusted, read-only default branch for low-trust, immutable toolchain namespace/arch/SDK/source digest for cache key. Required checks/rulesets proposed **only after job names demonstrated stable**; observed current GitHub repo **zero rulesets**, so do not assert protected checks exist or modify them as part of research. Solo owner may merge after objective proof, not auto-approve on docs-only.
9. **Failure is first-class**: `CI_TEST_FAIL`, `COMPILER_UNAVAILABLE`, `SANITIZER_UNSUPPORTED`, `SOURCE_STALE`, `CACHE_UNTRUSTED`, `COST_GUARD`, `RUNNER_OFFLINE`, `MATRIX_INCOMPLETE`, `NO_TESTS_EXECUTED`, `ARTIFACT_UNVERIFIED`, `PERMISSION_DENIED`; no retries that obscure introduced failure or accept a flaky run as green; CI cancellation does not mean tests passed.

## 2026 runner and R$0 policies
Public repo was observed via GitHub API as **public**. Current [GitHub Actions billing docs](https://docs.github.com/en/billing/concepts/product-billing/github-actions) state **standard GitHub-hosted runners in public repositories have free compute**; larger runners cost money and private repos consume a quota and possibly paid overage; artifacts/shared packages/cache have separate included storage and overage, not blanket unlimited. [GitHub runner reference](https://docs.github.com/en/actions/reference/runners/github-hosted-runners) includes named Ubuntu/Windows/macOS M1 and macOS Intel runner families; capability changes, preview labels and image toolchain revisions must be detected rather than assumed frozen. **R$0 is a hard gating rule**, not a promise every unlimited cache/upload/service fits for free.
- Require public repository verification before enabling OS jobs; if made private or standard macOS unavailable, DISABLE/BLOCK and recalculate cost, do **not** silently buy larger runner or self-hosted commercial service.
- Limit per-job timeout, matrix fanout/concurrency and failure cancellation, schedule macOS expensive/slow lane only necessary on relevant changes once owner approves, use incremental lint/source scan on PR and heavier nightly only with 0-cost guarantee and no unattended paid budgets. Restrict artifact/log retention days/size, avoid uploading full SDK/build folders, monitor cache overages and shared artifact storage. No signing/account/cloud purchase.
- No self-hosted runner with privileged network access by default: in a public repo, untrusted PR code could execute on self-hosted machine and access local credentials; future self-hosted Mac fleet requires HIGH_ASSURANCE isolation, ephemeral runner, locked network and owner approved budget, otherwise unavailable.
- Standard GitHub-hosted macOS runner is an ephemeral VM and does **not** prove physical GPUs, Mac thermal behavior, peripherals or device signing; QA-05/PLAT-06 actual physical Mac evidence remains future.
