## Web host, thread and execution model
- Candidate C++20 -> **Emscripten + Clang/LLVM** with pinned WebAssembly32 and a deliberately thin JS/TS host for user gesture, DOM, browser async APIs and rendering coordination. Emscripten is a research candidate, NOT adopted. Raw WASI module alone does not supply DOM/WebGPU/browser I/O; WASI toolchains need a deliberately supported adapter if evaluated. Browser owns navigation/security origin; engine owns simulation under fixed tick CORE-04.
- Proposed **Tier W0 baseline**: single-threaded wasm32, size/initial/maximum memory guarded, an asynchronous launch state machine and WebGL2 capabilities for constrained 2D plus representative 3D scene. W0 **does not guarantee all browser installations support WebGL2**, must clearly display unsupported. WebGPU preferred optional **W1**, WebGPU advanced features optional **W2**, both behind actual secure-context/device/feature probes. No WASM memory64, threads, SIMD, garbage collection or relaxed-SIMD made universal requirements from research alone.
- Multithreaded Emscripten pthread variant is distinct from single-thread bundle, because SharedArrayBuffer depends on effective cross-origin isolation, compatible headers/assets and Workers. COOP same-origin + COEP require-corp/credentialless and Permissions-Policy interact with embeds, analytics, authentication and third-party content. A host **must verify** `crossOriginIsolated` and feature policy. Fallback to separate single-thread build, never attempt to run an incompatible pthread binary.
- Prefer keeping DOM interaction on main thread. OffscreenCanvas/worker WebGPU availability and transferable canvas behavior are **capability-conditional**; main-thread fallback remains. Do not block main thread with synchronous wait/pthread_join/Atomics.wait; observable frame responsiveness and worker/message ordering budgets are required. Worker startup, shutdown, dev tools, hot reload and tab visibility have explicit epochs.
- RequestAnimationFrame is *render scheduling*, not authoritative simulation clock: browser throttles hidden tabs, BFCache and background workers. On visibility freeze/resume, time-debt is bounded by CORE-04 policy, game input held states released and audio resumed only after permitted gesture when applicable. Fullscreen, pointer lock, gamepad, clipboard and audio start need user activation/permission in real browsers; no autoplay privilege assumption.
- Use `ResizeObserver`, viewport CSS pixels, `devicePixelRatio`, canvas backing pixel extent/limits and effective resolution scale separately. User browser zoom, mobile high DPR, orientation/fullscreen and tab detach require epoch invalidation. Responsive UI, Unicode/IME, tab focus and accessibility stay with their respective owner; no keylogger/global DOM injection.

## WebGPU and WebGL2 capability-driven graphics
- WebGPU: only on secure context and with effective `navigator.gpu` or `WorkerNavigator.gpu`, `requestAdapter` result, `requestDevice` requirements and actual feature/limit queries. Requested features cannot exceed adapter capability; colorspace, texture formats, max bind groups/sizes, sample counts, shaders and render modes are per-device. Browser WebGPU is **not** a one-to-one native Vulkan/Metal/D3D12 API; GFX-01 consumes bounded browser-safe capability descriptors and GFX-02 owns WGSL generation/translation and validation, no raw native shader injection.
- WebGL2: explicit fallback compatible with TWO-01 ordered alpha/painter batches and a **reduced but real 3D scene**; WebGL2 has no general WebGPU compute, ray tracing, bind groups or identical shader model. Revalidate GL extensions/precision/NPOT formats and GL context attributes. WebGL1 and 2D DOM Canvas only as separate research/fatal-readable alternatives, not falsely counted as W0 3D pass.
- Handle WebGPU `device.lost`, uncaptured errors, API validation scopes and WebGL `webglcontextlost` / `webglcontextrestored`, including resource generations. Restoring device requires fresh recreated buffers/textures/pipelines and rehydration through GFX-01/DATA-05. Cannot reuse stale GPU handles; repeated loss may return `RESTART_REQUIRED` or fallback after validated compatibility. No infinite loss-retry loop. WebGPU unavailability at initial load chooses supported WebGL2 only if actual creation and features pass.
- Canvas2D semantics retain stable transparency/clip order; full-resolution UI sharpness and color-management/premultiplied-alpha/sRGB tests independent of 3D scaled resolution. Format conversion, compression features and HDR/P3 are **optional negotiated**, not universally enabled or labeled HDR10. No universal GPU timer queries or physical GPU memory readings from WebGPU.

## Streaming, startup, offline and recovery
- DATA-05 emits **target-specific immutable signed-or-trusted-manifest-described content** with hash/length/codec/dependency DAG; PLAT-03 only fetches, validates and stages content. Content hash proves byte integrity **not publisher identity, authenticity or freshness**; trust of signing/release manifests is BIZ-03 and security policy. Manifest parsing and chunk decoding enforce compressed/uncompressed limits, depth, offsets, timeouts and memory quotas; no zip bombs/unsafe virtual paths.
- Stream wasm via `instantiateStreaming` or compatible Emscripten generated loader under correct `application/wasm` MIME, validate fallback if wrong MIME; never auto `eval` arbitrary script to work around CSP. HTTP Range requests are opportunistic: accept 206 with correct Content-Range, or safe 200 full-body fallback within budget; 416, mixed Content-Encoding, CORS denial, server changing ETag, network drop, chunk mismatch and timeout have typed rollback.
- Asset loading: bounded in-flight requests, cancellation, prioritized critical scene groups, progressive 2D and 3D mip/LOD under DATA-05 controls. Record before-first-interactive and before-first-frame separately. Avoid excessive simultaneous decompression/texture upload, memory copies, long main-thread tasks or cache stampede.
- CacheStorage, IndexedDB and Service Worker are origin-scoped **best effort**, quota/eviction/network/privacy-mode dependent; never assume persistent offline, atomic CacheStorage+IndexedDB transactions or permanent CDN availability. Use generation-numbered immutable assets, verified manifest pin, staged candidate cache + prior-good activation receipt, multi-tab update coordination and cleanup policy. Do NOT replace last-good on incomplete patch, unverified cached response or QUOTA_EXCEEDED.
- No anonymous remote telemetry; CORE-06 local-first redacted diagnostics, user-controlled export. Local projects and saves require scoped user gesture through File System Access API only when supported, else user-mediated download/upload or supported IndexedDB with explicit persistence warning; never grant Web FS/native path powers to MCP.

## Browser security model and deployment gate
- HTTPS secure-context, restrictive CSP with explicit `wasm-unsafe-eval`/script needs if required by browser implementation, no blanket `unsafe-eval`; COOP/COEP/CORP/CORS/Permissions-Policy preflight per deployment profile. SRI where supported for JS, verify wasm/assets by trusted manifest digests on the consuming side; no assumption SRI covers every streamed chunk. Beware COEP breaking third-party embeds and popup sign-in; use an approved isolation/hosting strategy, not ad-hoc disablement.
- CORS and CORP do **not** authenticate remote content. Reject arbitrary origin import, malicious Service Worker or XSS-generated Wasm, unsanitized chat/asset URLs, unbounded decompression, path traversal, token leakage or unauthorized project change. Host-controlled capability tokens, no private API keys in browser bundles, no arbitrary JS execution through project/MCP, no executable plugin download in v1 without separate security ADR.
- CDN static hosting, deployment fingerprints and HTTP headers must be tested on actual origin; localhost tests do not prove real HTTPS/cross-origin deployment. Source maps may expose paths/code, evaluate exposure. No public distribution until full owner-approved 1.0 DoD; **planning cannot deploy**.
- Maintain compatibility matrix named browser version, OS/hardware, GPU/driver/ANGLE backend if observable, secure origin/policy, memory/storage limits, feature flags and consent states. Chrome, Firefox and Safari are **matrix candidates**, not blanket supported versions. Mobile browsers are candidate conditional to PLAT-04 decisions; do not claim universal phone readiness.
