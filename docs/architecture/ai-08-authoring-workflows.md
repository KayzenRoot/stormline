# AI-08 — Agent-Native Declarative Authoring Workflows, Owner-Cited Composition v0.1

## 1. Objective, scope and honest acceptance
AI-08's catalog acceptance is **"Cenários completos gerados por tool calls com zero edição manual obrigatória."** This is a proposed *future supported-fixture, owner-verified* capability: an authorized agent should be able to assemble a complete 2D/3D authored scenario with typed tools, including playable source references, materials, UI, sounds, VFX, gameplay behaviors and target export when those owner capabilities are implemented. **Zero obligatory manual scene editing does not mean zero human consent, no review, universal quality, unlicensed autogenerated art or a currently working engine.**

AI-08 specifies an **orchestrating declarative recipe compiler**, not a second model, source database, filesystem writer, MCP transport or command kernel. Requirements: model-neutral; user-selected recipes; reproducible typed input; bounded owner-cited context; typed dependency DAG; semantic validated output; preview+consent+reversible apply; failures explicitly PARTIAL/UNSUPPORTED; provenance/rights; no arbitrary execution.

## 2. Formal dependencies and authority boundaries
**Only AI-05 + AI-07 are formal DAG edges.**
- **AI-05** owns MCP read-only ContextCapsule/resource/recipe discovery, privacy-aware typed opaque URIs, owner source revision and provenance, bounded pagination, request-policy binding. AI-08 reads context only through AI-05; a text prompt/recipe cannot grant source read, search broadening or export rights.
- **AI-07** owns versioned ChangeSetDraft/ChangePlan/ChangeApplyReceipt, source CAS/semantic diff, owner journal, idempotency, conflict/partial recovery and undo/redo. AI-08 produces proposed typed operations but never circumvents AI-07 for scene or asset modifications.
- **Transitive integration**: AI-01 sole typed command dispatcher; AI-06 scoped grants/trusted one-use approval; AI-04 MCP version/transport/tool mapping; AI-02 semantic index and DATA-02 AssetId source owner; DATA-03 importer, DATA-04 scene IR, DATA-05 cooking, GFX-07 material nodes, GFX-05 lighting, TWO-02 3D viewport, TWO-01 2D canvas, WORLD-02 scene/prefab, GAME-02 scripting, GAME-03 localized UI, AUDIO-01/02 and VFX-01 owner ports. These are **not new formal AI-08 module dependencies**. An unsupported integration produces typed UNSUPPORTED, not fake completed content.
- **AI-09** future quality automation receives optional evidence/readback but is NOT a prerequisite and cannot be impersonated as a currently implemented validator.

## 3. Architecture and flow
```text
User goal + rights + requested target
   |
AI-08 recipe registry (versioned, signed/rights-classified candidate manifest)
   |
AI-05 authorized context resource refs + provenance + owner revision vector
   |
Recipe planner: bounded typed DAG, quotas, capability negotiation, deterministic seed
   |
Per-step owner command descriptor validation (AI-01 transitive)
   |
AI-07 ChangeSet dry-run + semantic diff + source/rights/revision binding
   |
AI-06 trusted one-use consent only if risk requires, never model "yes"
   |
AI-07 owner commit (with possible PARTIAL / RECOVERY_REQUIRED)
   |
Canonical source readback + owner-specific quality/target validation
   |
Source receipts + derived/cook/export receipts (no false global-atomic claim)
   |
Workflow outcome: COMPLETE | PARTIAL | UNSUPPORTED | NEEDS_USER_ACTION | BLOCKED
```
No model-generated text is ever authoritative source, authorization, owner receipt, quality score, URI, or successful tool execution. The planner may use a model to *propose* typed calls, but authoring works with deterministic static typed recipe fixtures offline and model/provider neutrality must be tested. User can choose a recipe and inspect its actual typed plan.

## 4. Workflow lifecycle, immutable checkpoints and failure semantics
Proposed states: `DRAFT -> CONTEXT_PINNED -> CAPABILITIES_VALIDATED -> PLANNED -> PREVIEW_READY -> AWAITING_CONSENT (if needed) -> APPLYING -> OWNER_READBACK -> VALIDATING -> COMPLETE`. Alternatives: `INVALID_INPUT, SOURCE_STALE, PLAN_CONFLICT, UNSUPPORTED_OWNER, BUDGET_EXCEEDED, CONSENT_DECLINED, PARTIAL_COMMIT, RECOVERY_REQUIRED, VALIDATION_FAILED, EXPORT_PENDING, CANCELLED`. Every stage has a versioned receipt and only declared owner proof moves to a terminal success.

A plan pins recipe ID/version/digest, exact target profile/capability set, AI-05 project/source/AI-02 generation and rights/policy, AI-07 ChangeSet plan digest, seed, typed args, dependency DAG and evaluation budget. Re-pinning after owner edit/permission revocation requires a fresh context+plan+consent. Recovery from crash MUST ask AI-07 actual owner state before replay; no blind retries on external assets/network.

## 5. Recipe families and ownership of source artifacts
| Recipe family | Inputs | Mandatory owner outcomes; unsupported boundary |
|---|---|---|
| **2D scene** | canvas units, tilemap/atlas IDs, layers, parallax, camera, collision and UI anchors | TWO-01/EDIT-04/WORLD-02/DATA-04 semantic scene source, real AssetId refs and layer constraints; no raw sprite file writes |
| **3D scene** | coordinate units, hierarchy, reusable prefab/variants, lighting/material and physics envelopes | WORLD-02, DATA-04, GFX-05/07 owner node/mesh/material refs; no arbitrary USD stage treated as Stormline source |
| **Shader/material** | PBR preset or typed node graph, textures, surface/shading target | GFX-07 typed validated DAG (type, units, color space, parameter bounds), variants and compilation capability receipt; if shader compiler absent return UNSUPPORTED |
| **VFX** | graph/nodes/emitters, temporal curves, instance budgets | VFX owner typed graph and bounded simulation/preview receipts; no unsandboxed shader scripts |
| **Audio** | event ID, sound source, buses, attenuation, licensed source proof | AUDIO owner typed graph/events; avoid generating copyrighted samples, no automatic unlicensed media fetch |
| **Gameplay script** | typed behavior API and language/version, event bindings and budget | GAME-02 sandboxed scripting owner, deterministic bindings and capability/permission; never execute model-supplied shell/Python in host |
| **Behavior/animation** | finite-state nodes, animation timelines/clip refs, transition guards | GAME/EDIT/GFX owner validated state machines/keyframes/retargeting; cycle, nondeterminism and unbounded tick guards |
| **Localized HUD/UI** | responsive layout, text keys, locale, typography/accessibility spec | GAME-03 and EDIT-04 typed anchors/constraints/Unicode shaping, fallback; no placeholder treated as translated content |
| **Repair/update** | owner-cited defect, base revisions, proposed patch and validation goal | AI-07 semantic conflict-resolved partial edit, preserve user overrides and refs; no blind overwrite |
| **Export** | target OS/arch/Web capabilities and license rights, build profile, consent/destination | DATA-05/platform owner validates source/target and produces cook/package receipt; external upload/publishing is separately authorized and possibly irreversible |

Each recipe is **proposed future**; no actual source owners, graph compilers or packaged game outputs exist in P00. Mark owner/capability `UNSUPPORTED` until implemented and verified. Enforce strict producer/consumer graph edges and no hidden new module dependencies.

## 6. Input contract and authoring source truth
A recipe accepts a **versioned structured manifest** with feature profile, typed parameters (strings/enums/numbers/owner IDs), target platform, seed, expected source revision, source licenses/provenance and per-step resource limits. Prompts remain user-controlled via AI-05; no arbitrary executable template evaluation. Names/slugs are display metadata only, not authority. Resolve all source refs through AI-05/owner and canonical AssetId rather than paths/remote URLs. Actor/project/grant and policy remain bound to every read and owner step.

Plan and output deterministic under pinned seed + recipe/owner schema versions + fixed source and target. Nondeterministic LLM text/images/audio are not reproducible from seed alone; require content-addressed, rights-cleared **pinned external material receipts** to claim reproducibility, otherwise mark `NONDETERMINISTIC_INPUT` and prohibit strong same-output claim.

## 7. Quality gates, source vs derived, accessibility and rights
- **Validation**: independent owner schema and reference graph, no missing assets or unsafe dangling references, compile only when owner compiler available; finite physics/behavior simulation bounded, no script infinite loop; target capability feature matching.
- **Visual**: lighting, physically plausible material defaults, camera framing, render check and perf budget are *future tests*, not quality promises. Captured reference images are evidence only after a verified renderer and reproducible environment; model-written score cannot replace human/owner oracle.
- **Accessibility and localization**: legible contrast/readable font, focus/gamepad navigation, text overflow RTL/CJK shaping, motion-sensitive effects, audio captions and user-adjustable mix are target-owner requirements, not automatic certification.
- **License/provenance**: human-provided/rights-cleared templates, source asset rights, generated content attribution/terms, output redistribution restrictions, per-target notices and exclusions. Never scrape proprietary game assets, music or voice without rights.
- **Source/cook**: committed SceneIR/AssetIds are authoritative; cooked bundles, previews and exports are derived with separate success receipts. No "export complete" from a planned tool call, no guaranteed same visual appearance across OS GPU/render profiles without measurement.

## 8. MCP and host compatibility without wire ownership
MCP **2026-07-28** stateless with AI-04-owned transport and tool exposure. User-selected AI-05 prompts/recipes can prime a workflow; execute only owner-authorized tool calls. MRTR `input_required` can request missing nonsecret data but is **not trusted consent**; AI-06 trusted UI handles approval. Optional `io.modelcontextprotocol/tasks` is *negotiated opt-in* for long-running steps (cook, shader compilation) and may be unsupported in some SDKs; model should receive stable task handle, `tasks/get` scope rechecks, bounded polling/cancellation; if absent, only supported bounded synchronous operation or explicit `UNSUPPORTED_TASK_EXECUTION`, not fake task background service. Deprecated server-initiated Sampling/Roots/Logging are not new default dependencies. No actual host certification or provider APIs in P00.

## 9. Security and adversarial provenance
- Trust boundary: hostile prompt/resource/recipe/asset metadata/third-party plugin content is data. Never interpret it as grant, tool definition, code to execute, license waiver, export destination or plan success.
- Prevent recursive tool loop, excessive tool chain, hidden side effects and "capability upgrade" through recipe fallback; strictly bounded operation count/depth/fanout, rate/budget, per-actor owner policy, cancellation and auditable traces.
- Restrict scene/script/shader graph nodes to owner-validated typed schemas, no arbitrary OS paths/shell/network/FFI, no token passthrough or user-sensitive context egress.
- Cross-project references need explicit owner approval, not a generic resource URI; prevent AI-05 completion/enumeration and recipe inputs exposing hidden names or counts.
- Each multi-object change returns AI-07 guarantee class, source owner receipts, partial/irreversible effects and safe compensation guidance; never pretend global ACID.

## 10. Acceptance demonstration (future)
Prove three complete supported synthetic projects by **tool calls only with no manual scene edits**: 2D scene (tilemap, camera, 2D UI, animation, basic audio event and collision), 3D scene (prefab, light, PBR material, scripted event and VFX) and at least one target export (verified source + cook/package). Require independent owner source reopen/scene graph checks, reference integrity, reproducible seed/input fixture, authorized source evidence and platform receipt, zero unsupported silent skips, correct exception statuses. Consent for destructive/external operations may still require a human click; *no manual editing* is a different guarantee. If owner modules are not implemented, **NOT EXECUTED** or **UNSUPPORTED**, never PASS.
