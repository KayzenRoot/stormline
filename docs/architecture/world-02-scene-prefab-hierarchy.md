## 1. Product goal and non-negotiable correctness
Catalog goal: **"Alterações em prefabs propagam de forma controlada, com undo/redo"**. A reusable authored template can instantiate into many scenes, variants and nested templates. Parent-template edits must propagate to **non-overridden** fields without overwriting author-local overrides; unresolved conflicts must become actionable receipts, not silent data loss. A node reparent must not create a cycle or transform drift, and a saved/reopened scene must retain logical identities and provenance across versions.

This module owns **scene/prefab graph semantics**, not another ECS registry or independent database. Headless runtime must be able to instantiate/reconcile from a cooked scene without requiring editor UI/GPU. All 80 implementation WOs remain BLOCKED/executor_ready=false, mandatory **WORLD-01 and DATA-02 CODE are not yet implemented**, even though WORLD-01 research is documented.

## 3. Durable scene source graph: tree vs dependency DAG
- **Hierarchy inside one scene instance is a rooted forest** of `SceneNodeV1` stable NodeGuid/EntityGuid mappings, with at most one structural parent per child and no parent cycles. Roots are explicit; sibling authored order is an explicit ordinal/stable tie-break, not inferred from fragile array index. Some scenes may declare one logical root for serialization, while runtime may have multiple scene roots; contract must specify choice during activation.
- **Prefab source dependencies form a separate directed acyclic graph**: A may include reusable B and a Variant C may derive from B, but a nested loop A→B→A or variant parent C→C is invalid. Support bounded depth, node count, dependency count and expansion sizes; recursive materialization must reject cycles **before** creating partial live entities.
- `SceneAssetV1`: ProjectId/SceneId/revision/schema hash, roots, NodeRecords, prefab instance references, level group/layer metadata, rights and imported asset origins. `PrefabAssetV1`: PrefabId/revision, stable local NodeIds, typed component defaults and nested link declarations, attachment slots and parameter schema. A prefab instance is a **link+override set** in authored scene source, not an untraceable expanded node dump.
- Separate durable `SceneNodeIdV1` scoped to a scene/prefab source versus `SceneInstanceIdV1` unique per placement versus ECS `EntityGuidV1` and runtime `EntityHandleV1`. Runtime entity mapping derives from the scene/instance/local node identities using an approved collision-resistant stable mapping or stored explicit mapping (algorithm TBD), with authorization and duplicate checks. Copy/paste deliberately mints fresh InstanceId and ensures cross-references fixup. Reimport/move/name changes cannot silently relink an instance to a different source node.
- A node's logical name/path is **display/navigation**, not identity or sole serialization key. Rename and reparent preserve immutable NodeGuid and explicit references. Cross-scene asset refs stored as typed `AssetRefV1` or `ExternalSceneRefV1`; WORLD-03 streaming resolution returns AVAILABLE / UNLOADED / MISSING / INCOMPATIBLE, never a stale pointer.
- Component fields are WORLD-01 schema-authorized and DATA-04 serialized. WORLD-02 tracks component-source mappings and hierarchy relationships, not a duplicate component memory store.

## 4. Affine transforms and reparent policy
- `SceneTransformV1`: explicit local transform, parent TransformId and world transform via CORE-05 checked matrix multiplication; 2D/2.5D/3D paths are typed, with configurable local units, handedness, pivot and camera-independent axis. CPU double precision/world-relative origin from CORE for far scenes; GFX renders local relative snapshots. No extra transform solver.
- Reparent uses a **single atomic transaction** `ReparentNode(node,new_parent,KEEP_LOCAL|KEEP_WORLD)`. `KEEP_LOCAL` preserves local transform and adjusts world pose; `KEEP_WORLD` computes new local = inverse(new_parent_world) × previous_world only if mathematically invertible and within precision tolerance. Shear/negative scaling and nonuniform parent scales can make decomposing TRS lossy, so a fallback must store checked full affine matrix or **reject with TRANSFORM_NOT_REPRESENTABLE**, not silently alter visual pose.
- Constraints: child cannot parent itself/descendant, cannot cross world/project/prefab ownership boundaries without explicit import+rights, cannot depend on scene instance that is unloaded unless an external parent proxy is approved; scope/tick/source revision must match. Dirty transforms propagate to descendants iteratively bounded or topo-sorted; no recursive unbounded stack.
- Renderer/TWO-04/GFX-07 reads a **committed immutable transform snapshot** and PHYS/GAME accepts only relevant authoritative transform requests; scene-authoring reparent does not teleport physics-owned characters without owner acknowledgment.

## 5. Prefab templates, instances, variants and nested composition
- Prefab source composition layers: (a) base template fields/children, (b) nested-template base fields, (c) ordered variant inherited overrides, (d) specific instance overrides, (e) authorized scene-level runtime changes distinct from authored asset. Define explicit precedence **only for this bespoke model**, with a stable key `{source-node-guid,component-type-id,field-id}` and tombstones for removals. Avoid calling this OpenUSD's exact LIVRPS/LIVERPS order: OpenUSD composition semantics are more complex and include list editing.
- `PrefabVariantV1` holds immutable BasePrefabId and expected revision, thin field overrides and structural operations (add child, remove/hide, reparent where legal, add/remove component) with stable source-node GUID and ordered provenance; source defaults not copied wholesale. Nested prefab instance references base source and its own instance overrides, with expansion path and override provenance.
- Strong policy: **base field change propagates automatically only when instance/variant did not override that field**. If a field is overridden locally, keep local value and record new base revision. If base removes a field/component/node that is locally overridden or referenced, produce `BASE_REMOVAL_CONFLICT` with explicit choices (discard local patch, preserve detached node if authorized, map to substitute), not implicit delete. Type migration via WORLD-01/DATA-04 owner before rebase.
- `PrefabRebaseReceiptV1`: expected source old revision (base), new source revision (theirs), stored local override base revision (ours); perform **typed 3-way merge** at field+structural operation granularity. Conflicting simultaneous edits to same field return CONFLICT with base/ours/theirs typed summaries; do not silently favor latest wall-clock or overwrite. For lists/child order use stable node IDs and explicit reorder operations, not array-index patches.
- Instance flattening/break-link is an **explicit authorized destructive topology conversion**, with a dry-run preview and DATA-04 journal/undo; never happen on import failure, missing asset, cache miss or author accidentally renaming a node. Runtime may cook resolved snapshots for speed but authored source retains link+override tree for later propagation.
- No mandatory arbitrary deep inheritance/graph complexity: cap variant depth, nested prefab depth, instance count, structural mutations, total entity expansion and source-to-runtime dependency fan-out. Future WORLD-03 lazy loading/streaming can produce placeholders with typed readiness; not a silent break-link.

## 6. Consistent versioned update and undo/redo
- `PrefabChangeSetV1` holds author/project, expected DATA-04 revision, base asset revision, typed ops and affected instance IDs. Preview stage computes impacted non-overridden fields, overridden preserved fields, conflicts, orphaned refs and estimated work/dirty scope without actual mutation.
- `StageSceneEdit -> ValidateGraph/Transform/Permissions -> PreviewPropagation -> DATA-04 CommitJournal(CAS) -> WORLD-01 deferred entity commands at safe scheduler barrier -> PublishSceneRevisionReceipt`. Source and live-world phases can fail separately; define reconciler/outbox with **last committed source + generation** and idempotent runtime application; no false atomic guarantee spanning file fsync and arbitrary asynchronous ECS/GPU worlds.
- Undo/redo via DATA-04 journal and inverse semantic change operations with expected revision and provenance; undoing a base prefab edit must restore the base and re-evaluate dependent instances, respecting **newer local overrides** or reporting revision conflict (not blindly roll back other authors' later edits). Crash on staging/partial runtime apply recovers last-good journal and safely replays idempotently.
- Changes to prefab rev invalidate cooked scene snapshots through DATA-05; WORLD-01 receives create/destroy/field patch with EntityGuid mapping and epoch checks; render/audio/physics consumers only see revision-consistent scene snapshot, no half-applied scene invisible collider/trapped character.
- Dependency fan-out and budget: safe incremental propagation can batch in bounded ticks **only with a declared incomplete/blocked or prior revision visible**. Never publish a scene revision while only half its children have accepted changes as if consistent. Background rebuild and per-instance revisions are typed; implementation and scheduling policy to be finalized after benchmark.
