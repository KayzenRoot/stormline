## 1. Mission / acceptance truth
Catalog scope: **"Widgets, layouts responsivos, foco, texto, fontes licenciadas, idiomas e HUD."** Catalog proof: **"UI gamepad/mouse, legibilidade, foco e internacionalização."** Propose a stable Stormline-owned game UI semantic tree for menus, HUD, dialogue overlays, inventory, ARPG tooltips, maps and responsive cross-platform experiences that is accessible, multilingual, controllable with keyboard/gamepad/mouse/touch and independent of GPU/render backend.

**Non-goals:** do not build a browser DOM, Web browser/HTML parser, new GPU renderer/Canvas, global OS text input pump, game simulation, external localization CMS, arbitrary CSS/JS runtime, second ECS, editor widget framework or chat/AI ability to run untrusted UI scripts. Headless accepts validated UI plan/layout/accessibility metadata but never claims screenshots.

## 3. Unidirectional UI tree → layout → render
```text
DATA-04 authored UiDocumentV1 + locale/catalog/rights/AssetId
   -> GAME-03 validated immutable UiTreeV1 + style/layout constraints + state scopes
   -> LocaleResolver: BCP-47 -> Unicode CLDR49/ICU79.1 normalized message/units/dates
   -> Safe message interpolation and bidi isolate for untrusted player/entity values
   -> Text shaping: normalization policy -> segmentation UAX29 -> script/bidi UAX9 -> font fallback
   -> line breaking UAX14 + HarfBuzz shape / FreeType metrics and glyph raster candidate
   -> UiLayoutTreeV1 (logical px, safe area, DPI, constraints, focus geometry, semantic access tree)
   -> UiDrawPlanV1 (layer/clip/glyph run/texture references) -> TWO-01 glyph/sprite Canvas
   -> GFX-07 unjittered UI color/post placement -> GFX-01 actual display
           ^
  GAME-01 InputActionFrame + UI-owned FocusRoute / InputTextComposition
  GAME-02 bounded role-filtered game snapshots, authorized action intents
```

**Single-owner rule:** GAME-03 may shape text and propose glyph positions with HarfBuzz and raster strategy, but actual glyph atlas draw/upload/lifetime remains TWO-01. GFX-07 owns final display/nits/color. Explicit UI overlay composition after temporal world reconstruction, before/after display transform as GFX-07-approved path, no duplicate tone-map, maintain legible focus/hud under HDR and low contrast.

## 4. Widget and state model
- `UiDocumentV1` stable AssetId, schema version, project, layout tree revision and locale catalog refs. No executable script or arbitrary HTML/CSS document. Core nodes: Container, Text, Image, Button, Toggle, Slider, Progress, Scroll, List, Tab, Dialog, Tooltip, TextField, RichText with explicit supported subset. Specialized ARPG HUD nodes use composition, not hardwired inventory game engine.
- `WidgetNodeV1` stable per-document NodeId+generation, role, localized label/description/help, intended actions, layout/style tokens, layer/z-index, enabled/hidden/disabled/readonly and exposure; render draw order and logical navigation order are separate.
- `UiStateV1`: localized visible data, focus states, scroll anchors, edit cursor grapheme index, selection, modal stack, animation phase, accessibility preferences, user data-binding view; state mutations through validated UI event reducer with explicit version/owner. Avoid recursive render state side effects or adding script hooks on every frame.
- Default retained **semantic tree** and dirty-reconcile; optionally declarative build functions produce same tree. No arbitrary host pointers in node IDs; stable lifecycle epochs prevent stale callbacks after unload/reload.
- Data-bind read-only snapshot fields and UI computed state, with explicit update policy (tick-based, event-driven, throttled presentation) and versioned subscriptions. GAME-02/04 owns authorized action intent and game authority; UI never acts as trusted source of truth.
- Validation: max node count/depth, style values, layout recursion, text lengths, asynchronous measurement and virtualized list items; typed fail-safe placeholders for missing fonts/locales/images, never crash editor or stall frame on hostile document.

## 5. Layout and high-density UI correctness
- Separate **logical points/px**, physical pixels, DPI scale, user text scale, world-space panel projection, rotation/orientation, aspect and display safe area/insets, split-screen viewport, overscan/TV margins. Define transform chain: `UiDesignSpace -> ViewportLogical -> ScaledPhysical -> GFX07Output` with finite bounds, consistent rounding and unjittered text.
- Layout supports flex/stack/grid-like authored patterns, alignment, min/max constraint, intrinsic text measurement, anchors/nine-slice and fixed/percent/auto. **Single layout engine**. Candidate Yoga MIT as flex calculator; RmlUi MIT is a full markup+style+widget alternative that may duplicate owned widget semantics. Do not adopt both as mandatory or accidentally produce two focus trees.
- Breakpoints react to aspect, resolution, DPI, locale expansion, font fallback, user scale, input method, split-screen, TV-safe mode; recompute only affected subtrees and avoid measure-layout feedback loops. Distinguish true viewport resize from cosmetic UI settings update.
- Use safe top/bottom/side insets; no critical controls offscreen. Compose responsive HUD via consistent high-priority anchors; localized long labels wrap/ellipsis only with accessible full-text channel.
- Virtualize long inventories/quest lists with stable logical focus and accessibility item count; scrolling and focus restoration must work when items are recycled. Finite clip nesting and overflow behavior, with layout receipts for truncation/collision, not hidden silent clipping.
- UI animation/transition time belongs presentation clock, never changes gameplay tick. Motion-reduction preference disables parallax/flash/large movement; do not assume `prefers-reduced-motion` native engine signal exists without platform adapter.

## 6. Text pipeline: Unicode, fonts and typography
- **Unicode 18 and UAX boundaries:** UTF-8 source validated on import, preserve expected normalization (NFC only where semantically legal and explicitly configured); UAX#29 grapheme cluster for caret/selection/backspace, UAX#14 line break, UAX#9 bidi paragraph and resolved visual ordering, Unicode script/run itemization. A user-visible emoji family can be multiple code points and must not split at raw code units.
- **Shaping:** HarfBuzz candidate applies OpenType GSUB/GPOS for Arabic ligatures/context, Indic matra order/cluster, Thai scripts, CJK punctuation, kerning and variable font axes; shaping order is bidi run/script/font-aware. Rendering disconnected glyphs or reversing code points for RTL is not compliant.
- **Raster:** FreeType 2.15.0 candidate for hinted/color/variable font raster with FTL or GPLv2 license choice; HarfBuzz latest has its own raster/vector/GPU paths but missing hinting; compare only with real quality evidence. msdfgen MIT optional SDF/MSDF candidate for large scale text/HUD, but small pixel sizes, thin strokes, color emoji and mixed typefaces require grayscale/hinted raster fallback. No single mode is universally superior.
- **Font fallback:** explicit chain by locale/script/coverage and per-glyph cluster, compare font metrics/line height to prevent clip/jump, tofu replacement with typed receipt. Noto family is SIL OFL 1.1 asset license candidate; each font binary's rights/embedding/derivative naming, metadata, attribution, reserved font name and subset redistribution must be reviewed individually. Font library license does NOT confer font asset rights.
- **Glyph cache:** keyed font AssetId/revision, font face/axes/features, glyph ID, size/hinting/dpi/msdf mode, locale/render profile, GPU/device atlas generation; atlas actual page lifecycle and fences TWO-01/GFX-03, never GAME-03. Layout caches invalidate on locale/fallback/font/scale/viewport/rights/device revision, prevent stale UV/garbled glyphs. Headless metrics can test geometry but not screenshot.
- **IME and text fields:** GAME-01/CORE-01 provide host text/composition events, GAME-03 owns focused text buffer, composition spans, selection/caret by grapheme, password privacy, undo boundaries and candidate UI placement. Password/IME never sent to gameplay scripts/diagnostic logs by default; host platform may own native keyboard/IME candidate visuals.
- **Text fidelity:** signed distances not confused with glyph advance; UI text sharp/un-jittered under TAA; SDR/HDR contrast evaluate actual GFX-07 output and target display; fractional DPI and subpixel snapping/hinting need comparisons. Custom rich text is an allowlisted declarative span language, not injected HTML/CSS/JS.

## 7. Localization: data and safety
- `LocalizedMessageKeyV1` stable project namespace and semantic key/description/context, not embedded English display string. `LocaleBundleV1` locale BCP-47 language/script/region, catalog revision/hash, fallback chain, provenance/translator and asset rights, completeness and target manifest. Resolve locale with explicit user/project preferences and supported locale negotiation, never silently translate unknown keys.
- ICU 79.1 / CLDR49 current production candidate and Unicode MessageFormat 2 stable specification. **ICU C++ MF2 API still partly technology preview** as of ICU79 release notes: do not promise all MF2 constructs or standard complete API support across targets. Scope first translation formatter to stable ICU/CLDR plural/number/date/units and add MF2 only after version/pin/behavior validation.
- Params are typed, not preformatted interpolation: number/currency/date/calendar/time zone/measure/gender/select/plural rules depend on locale and CLDR version. Server time or game time source must be explicit; don't read OS UTC randomly for deterministic gameplay. CLDR 50 development is **not** assumed release-ready.
- Bidi attack surface: untrusted player/usernames and dynamic values isolated with Unicode bidi isolates (e.g. U+2068 FIRST STRONG ISOLATE and U+2069 PDI where applicable) and sanitized for invisible/confusable override controls; no displaying security-sensitive ID/transaction amounts with spoofed direction. **Do not strip legitimate RTL languages**. Rich placeholder markup parser allowlists style tags and escapes input values; no external URL/font fetch, executable action link or HTML injection from translator strings.
- Translation validation checks placeholder names/types, nested select/plural coverage, encoding/normalization, maximum expansion, line break and font coverage, fallback chain loops, missing/unused keys, right-to-left layout and mirrored directional icons. L10n edits staged by DATA-04 CAS with build/cook asset provenance. Runtime locale switching must invalidate shaping/layout caches without losing focused user input and menu navigation.
- Caption/SDH from AUD-04 uses its own timed-text cues; GAME-03 renders caption text/labels/accessibility and safe areas, but it must not reschedule audio sample clock or cinematic transport.

## 8. Input, focus, accessible semantics
- GAME-01 owns `InputActionFrameV1` and `PlayerSeat` device mapping; GAME-03 owns `UiFocusTreeV1`, actual focus target, spatial navigation graph, tooltip/modal priority, text input composition and `InputFocusRouteV1` returned to GAME-01. A focused text field must suppress GAME-01 gameplay shortcuts as proposed.
- Multiple navigation policies: logical reading order vs spatial nearest rect (gamepad D-pad/analog, TV menus), explicit directional neighbor edges when authored, wrap policy opt-in, focus restoration after popup, screen transition, list virtualization, orientation/density/locale change. No invisible modal focus trap; protected Back/Cancel recovery.
- Pointer hit testing based on final transformed/clipped visual geometry, not stale pre-DPI plan. Pointer cancel/up semantics and gamepad confirm are consistent and not double-dispatched; keyboard-only essential controls work.
- Accessibility tree: role/name/value/state/description/help, hierarchy, tab order, focus visibility, error announcement, live region throttling, captions/transcript text equivalents. Abstract semantics independent of platform accessibility API; expose through PLAT adapter after target native/Web screen-reader feasibility proven, not silent claim.
- WCAG 2.2 keyboard focus order/visible, target size, reflow, contrast, text resize, keyboard alternatives, pointer gestures, dragging and concurrent input modalities are **design references**; game-specific scenario and OS adaptations need independent audits. Avoid blanket WCAG or screen reader certification without actual human/assistive tests. Color-blind/reduced-motion preferences provide semantic policy, don't claim physiological adequacy.
- Coordinate with GAME-02: scripts can bind to permitted read-only view models / publish intent event IDs with scope/role, cannot evaluate arbitrary UI markup/JS, bind unrestricted code closures or rewrite protected focus/security fields. Game logic owns inventory or quest transitions, not button widget.

## 9. Security, privacy, quotas, failures
- **Untrusted assets:** font binaries, SVG/rich text, localization strings, dynamic player labels and theme documents are import-bound adversarial data. DATA-03 parses/sanitizes/sizes and records rights; GAME-03 validates semantic schemas, cyclic refs, node fanout/depth, markup parser/placeholder types, URI schemes and text/control characters. No remote CSS/JS/script, inline SVG script, untrusted font download, native clipboard capture or arbitrary host filesystem.
- **Rendering:** bound nodes/draw calls/clip nesting/glyph count/atlas pages/overdraw, fail-safe fallback and GPU device-generation invalidation; no script-provided shader. GFX-03/TWO-01 own actual GPU allocations/fences. UI data-binding snapshots contain no credentials/private inventory unless authorized per role; no logging typed passwords, chat content or secret values by default.
- **Focus/input:** stale NodeGeneration, WindowEpoch, PlayerSeat and UiTreeRevision must be rejected; UI transitions can't leak canceled pointer capture or leave focus on removed dialog. USER confirmation for destructive action and server authority still belong GAME/NET.
- **DoS:** malicious 1MB nested text/rich styles/font parsing and huge bidi/many emojis can explode CPU/cache. Enforce quotas and CPU job/atlas budgets; never block realtime audio callbacks or gameplay tick on font raster/reflow. Runtime fallback before deadline may show accessible placeholder and log typed reason.
- **Web:** browser DOM/IME/focus and font platform policies are PLAT-03 capabilities, not assumed identical to desktop/native. Browser text rendering and font sandbox may differ; no claims of native-Web pixel exactness. Headless validates semantic tree/layout/locale without a UI display.
- **Rights:** licensed font library != licensed font assets. SIL OFL distribution requires exact text/notices and reserved-font-name rules for modified fonts; screenshots/exports need attention to embedded commercial fonts/emoji rights. No chosen font assets or shader/SDK adopted.
