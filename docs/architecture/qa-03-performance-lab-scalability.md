## Performance clocks: separate seven time domains
1. **CPU simulation/update:** monotonic thread/clock spans of state update, physics, AI, animation and VFX; characterize CPU *wall latency vs summed worker CPU busy* (parallel work makes sum > wall); queue wait, lock contention, priority inversion and scheduler disturbances. Thread wall time is not “GPU frametime”.
2. **CPU render/submit:** command list recording, graph compile, shader/PSO stalls, upload/decompression, queue submit. Distinguish CPU command submission and GPU execution; pipelined frames overlap and individual phase sums need not equal display frame interval.
3. **GPU pass/queue:** future GFX-RHI/PLAT owned timestamp readbacks with queue-specific support/valid bits and conversion; fences required before read. Vulkan [timestamp queries](https://docs.vulkan.org/spec/latest/chapters/queries.html) use `timestampValidBits` (nonzero), `timestampPeriod` (ns/tick), multi-queue clocks/calibration and wrap; [D3D12 timing](https://learn.microsoft.com/en-us/windows/win32/direct3d12/timing) uses `D3D12_QUERY_TYPE_TIMESTAMP` per heap, `GetTimestampFrequency`, resolve query data and `GetClockCalibration`; copy queue requires feature check. [Metal counters](https://developer.apple.com/documentation/metal/gpu-counters-and-counter-sample-buffers) require supported counter sets/sampling boundaries and [CPU/GPU clock correlation](https://developer.apple.com/documentation/metal/converting-gpu-timestamps-into-cpu-time). Never subtract raw timestamp domains across unrelated queues/devices.
4. **Present/actual display:** CPU frame start, submit, present requested, present completed, compositor/flip queue and display onset are different events. [Intel PresentMon](https://github.com/GameTechDev/PresentMon) ETW tracks displayed/presented frame pacing on Windows if available; minimize capture overhead. “FPS from CPU loop” does not prove evenly delivered pixels. Report stutter/late/duplicate/dropped frames and input-to-photon only with actual reliable instrumentation.
5. **Browser/WebGPU:** [WebGPU spec](https://www.w3.org/TR/webgpu/) optional `timestamp-query` feature exposed only if device supports and security/privacy allows; values intentionally lower precision and command encoding/readback async, not authoritative physical display timing. Browser performance.now/rAF/Performance APIs have throttling and privacy rounding; hidden tabs, battery saver, device loss, compositor and refresh rate tracked. Missing timestamp feature => UNSUPPORTED and CPU/rAF surrogate labeled as *surrogate*, never GPU clock.
6. **Memory/residency:** track peak/resident CPU process memory, committed/virtual, engine heap and allocator groups, GPU allocated vs resident vs **dynamic OS budget**; Vulkan [VK_EXT_memory_budget](https://docs.vulkan.org/spec/latest/chapters/memory.html) per heap budget/usage estimate, D3D12 [IDXGIAdapter3::QueryVideoMemoryInfo](https://learn.microsoft.com/en-us/windows/win32/api/dxgi1_4/ns-dxgi1_4-dxgi_query_video_memory_info) `Budget/CurrentUsage`, Metal [`currentAllocatedSize` and `recommendedMaxWorkingSetSize`](https://developer.apple.com/documentation/metal/mtldevice/recommendedmaxworkingsetsize) and `hasUnifiedMemory`. VRAM total ≠ process entitlement; unified RAM shared with CPU cannot simply sum GPU+CPU consumption.
7. **Power/thermal:** fan/temperature/GPU clock/utilization/performance state, CPU package/GPU board power or system battery/power supply if actual accessible, ambient/charge level, thermal throttling. Sensor origin, units, access denial and polling overhead required. Standard hosted VM cannot truthfully report physical target GPU power or stable per-device thermal state; never infer joules from speculative watts. Physical fleet or owner local device only, no unapproved hardware purchase.

## Reproducible experiment life cycle (future)
`SourceLock -> QA02 FixtureLock -> HardwareProfile -> QualityTier -> WorkloadPlan -> Warmup/Stabilize -> InstrumentationCalibration -> IndependentRuns -> RawFrameTrace -> Statistics+Confidence -> PairedRegression -> Evidence/Audit`.
- **A. Fixture lock:** original rights-cleared 2D tile+UI, 2.5D parallax/isometric, 3D PBR/light/particles/streaming, Web profile approved. Same source scene/seed/fixed sim/camera/input/texture variant/resolution and GFX-08 VFX graph/revision across A/B. Use QA-02 golden state/image gates; can't call a faster wrong frame a performance win.
- **B. Hardware & OS lock:** vendor/GPU/device ID, driver/API version, VRAM and unified status, CPU model/cores/NUMA/SMT, RAM, disk/cache/OS/kernel/compositor/display refresh/resolution/HDR, power/thermal state, background processes, vsync/VRR/frame limiter, build compiler/flags/sanitizers, shader binaries/PSO caches, renderer tier, recording stack and plugin license. Segment baseline by *hardware class*, not merge unknown GPU families to claim universal performance.
- **C. Warmup:** distinct cold launch/shader compile/asset IO phases (quantified separately) vs warmed steady state; warmup until pre-declared clock/power/working-set stabilization criteria and finite timeout, no unbounded “wait until benchmark passes” loop.
- **D. Record:** CPU spans+GPU calibrated timestamps+present events+memory budgets sampled in bounded buffers; segregate with-profiler and without-profiler runs to measure instrumentation overhead. GPU counters may serialize/perturb work; collect low-overhead always-on frame pacing separately from heavyweight hardware counter captures.
- **E. Analyze:** retain raw ordered frame intervals as `ns` (nonnegative, valid source), use documented nearest-rank/type-7 quantile convention **chosen once**, p50, p95, p99, p99.9 only with sample-count confidence; median/mean/SD/CV; stutter frame ratio vs target display budget, 1% slowest durations report *duration*, avoid misleading “1% low FPS” unless definition explicitly stated. Exclude warmup only via precommitted phase boundaries, report all outliers/clock discontinuities/drops, don't delete ‘bad runs’ after observing slow results.
- **F. Regression:** same hardware/driver/quality/source fixture, pairs A/B randomized/ABBA order across independent sessions, block/bootstrap by run/session accounting for **temporal autocorrelation**. Report effect size (% and absolute milliseconds), p50/p95/p99 interval and number of frames/sessions, uncertainty, reliability and confidence threshold; don't assert significance from thousands of correlated frames in one session. If device class/quality differs or run count insufficient: INCOMPARABLE/INSUFFICIENT_DATA rather than PASS/FAIL.
- **G. Change gates:** numbers are only compared against owner-approved **quality tiers** and thresholds calibrated on actual low/mid/high/Apple/browsers with fidelity and battery constraints. Example frame budgets (1000/60≈16.67) ms and (1000/30≈33.33) ms are reference arithmetic, **NOT approved target/DoD**; cannot mark tier success from average FPS alone. Adaptive quality experiments must log tier transitions, avoid oscillation and respect gameplay readability/accessibility.

## Proposed budget taxonomy (no concrete owner thresholds)
| Budget axis | Unit/measure | Example scenes and gate |
|---|---|---|
| Frame interval & presentation | ns/ms from actual present/display events; p50/p95/p99 | missing/dropped/late frames/VRR vs fixed Hz, report frame pacing |
| CPU simulation/render | ns/phase and blocked/scheduling/wait, total CPU usage | 2D input+tile/2.5D sorting/3D culling/physics, avoid workers summed twice |
| GPU pass execution | ns per queue+pass with calibrated timestamp provenance | 2D UI, 2.5D translucency, 3D shadow/PBR/transparent/VFX, async overlap |
| CPU memory | resident/peak allocated bytes; allocator counts/leaks | scene streaming/shader compile, unbounded heap over time |
| GPU residency/VRAM | OS budget vs process usage/heap fragmentation/paging | tier quality, texture cache/mip, VFX transient heaps; pressure fail closed |
| IO and streaming | asset bytes/second, stall ms, shader pipeline PSO warm/cold | camera/flythrough/hot-reload and gameplay traversal |
| VFX scalability | live particles/spawns/draw/overdraw/compute ms, memory | GFX-08 effect graph bounded policy, conserve gameplay semantics |
| Power/thermal | W/J/°C/clock/temperature if sensor allowed; uncertainty | battery vs AC, TDP classes, sustained test after stabilization |
| Reliability | crashed/invalid frames/timeouts/OOM/device-loss and recovery | never discard failure samples as “not part of benchmark” |
| Accessibility/fidelity | text size/contrast, particles legibility, motion reduction | QA-02 expected semantic/golden oracles must pass before performance claim |

## Tier candidates, NOT selected release classes
`QUALITY_LOW` (limited GPU, conservative VFX budget, simplified shadow/texture), `QUALITY_BALANCED`, `QUALITY_HIGH` and `QUALITY_CINEMATIC` as **quality settings only**, not approved OS release classes or fixed hardware minimum. For every tier define exact feature/asset/shader/FX/fidelity and target resolution separately after measurement. A scalability tier is not automatically a 1.0 mandatory class.

## Failure taxonomy, privacy and truth
`SOURCE_STALE`, `FIXTURE_MISMATCH`, `RENDER_CORRECTNESS_FAIL`, `CLOCK_DOMAIN_UNKNOWN`, `GPU_TIMESTAMP_UNSUPPORTED`, `GPU_QUERY_INVALID`, `NO_DISPLAY_EVENT`, `THERMAL_UNSTABLE`, `POWER_STATE_CHANGED`, `VRAM_BUDGET_INVALID`, `RUNNER_NOT_PHYSICAL`, `TRACE_DROPPED`, `MEASUREMENT_PERTURBED`, `STATISTICS_INSUFFICIENT`, `QUALITY_TIER_UNAPPROVED`, `FLEET_UNAVAILABLE`, `COST_GUARD`, `SECURITY_BLOCKED`. No missing samples replaced by zero, negative duration or FPS cap. Capture is opt-in on owner-controlled original scenes only, redacts project paths/PII and forbids remote analytics by default. Input trace hashes not player behavior analytics. No paid CI/GPU lab, unsafe driver admin, profiler process injection or private shader disclosure.
