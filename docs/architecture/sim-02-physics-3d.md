## 1. Acceptance and design objective
Catalog acceptance: **"Testes de colisão/escala, memória e simulação headless."** Stormline must own versioned semantics and stable entity references for 3D rigid-body physics. Candidate capabilities: static/dynamic/kinematic bodies; sphere, box, capsule, convex hull, compounds, static triangle mesh and static heightfield terrain; collision matrix, broadphase/narrowphase, contacts/sensors and ray/overlap/sweep/shape casts; hinge, fixed, distance, slider and cone/swing-twist joints with limits/motors; CCD, sleeping and deterministic fixed tick profile; ECS/scene transforms, asynchronous world/terrain stream and game/network authority. Headless CPU first, no GPU needed. Unconditional large-world or deterministic cross-platform claims require future tests.

Baseline: **28/80 module researches documented, 52 pending incl historical CORE-04**, all **80 coding WOs BLOCKED/executor_ready=false**, no executable engine; mandatory future code WORLD-02+CORE-03 absent, coding #47 OPEN/BLOCKED.

## 3. Types, units and identity
- `PhysicsWorld3DIdV1` is ProjectId+WorldId+WorldInstanceEpoch+backend/profile and immutable handedness/world unit. Proposed right-handed world meters with **Y up or Z up must be selected by approved CORE-05 math contract**, not guessed by an adapter. Gravity m/s², velocities m/s, angular radians/sec, forces N, torque N·m, mass kg, density kg/m³, inertia kg·m². Finite coordinate/bounds checked before native solver calls. PhysX/Jolt/Rapier/Bullet transform coordinate conventions and quaternion order normalized at private backend boundary.
- `PhysicsBody3DHandleV1`, `PhysicsShape3DHandleV1`, `PhysicsConstraint3DHandleV1`: private WorldInstanceEpoch, slot and generation, no SDK body pointers or provider IDs exposed. Qualified WORLD-01 EntityGuid mapping optional, source WORLD-02 prefab node path and AssetId revision. Stale destroyed/reused slots, cross-project/world handles and post-unload contact events rejected.
- Multiple colliders per body, body mode STATIC/KINEMATIC/DYNAMIC, sleeping and mass/inertia declaration. Static collider may be source CELL chunk; dynamic EntityGuid belongs a single ECS world and remains pinned while gameplay-critical. Kinematic target from authoritative GAME input; dynamic pose after solver fixed tick. GFX interpolation between two committed tick snapshots is read-only and may not feed into physics integration.
- Parent transforms/nonuniform scale/shear and negative determinant: flatten/cook collision shape using verified world scale/affine matrix at safe barrier or reject. No in-place mesh reparenting while contacts unresolved; preserve global pose after WORLD-02 prefab revision or CORE-05 origin shift. Dynamic triangle mesh is not general safe default; default triangles/heightfields STATIC only; dynamic body uses convex/compound or explicit backend-supported carefully bounded special case.

## 4. Scene lifecycle, shapes and collision
- Source `ShapeAsset3DV1`: original registered rights-checked assets, canonical cook version/revision, primitive dimensions, convex hull finite planar/winding, compound subshapes, mesh triangle indices/adjacency/material and static heightfield resolution. Polygon soup, malformed triangles, duplicate vertices, NaN/Inf, huge/negative scales, zero-mass inertia and wrong-handed normals rejected pre-cook via DATA-03. Mesh and heightfield collider revisions are **not** assumed equal to visual LOD tile displacement; physics source coordinate contract required.
- Jolt docs caution that dynamic mesh collisions against other mesh/heightfield are not generally supported and dynamic mesh mass/inertia is not inferred. **Contract fails closed on unsupported dynamic mesh**, no “automatically collider-safe” source geometry or false support assertion.
- Physics `broadphase` candidate AABB tree with static/dynamic object layers and group/mask filtering belongs SIM-02 collision solver, not WORLD-03 spatial interest or GFX-04 occlusion. Native broadphase returns candidates, exact narrowphase shape cast determines reported true contact/hit. If query order varies under parallelism, sort canonical by stable engine ID + fraction and refine against real shape bounds when deterministic API promises require it. Jolt docs note broadphase queries alone can be non-deterministic due concurrent AABB expansion.
- Contacts and sensors yield immutable post-step `Physics3DEventBatchV1` with tick, pair IDs/generation, normals/impulses and activation/retirement epochs. **No ECS or solver body mutation from multithreaded contact listener**; callbacks stage only bounded internal data, game effects queued at next tick. Avoid untrusted contact modifiers and re-entrant raycasts/allocations while solver locks held.
- Filters have `CollisionLayerId`, `MaskBits`, group ignore/team policy plus explicit trigger/sensor flag and joint connected-body collision bit; render layers distinct. Collision material friction/restitution combine rule versioned in backend profile. Query `Ray/Overlap/SphereCast/BoxCast/CapsuleCast/ConvexCast` (feature-gated) returns sorted/truncated completeness/precision receipt, not silently promise exact nonresident terrain and no duplicate hit across cell edges.
- Joints/constraints types `FIXED`, `DISTANCE`, `HINGE`, `SLIDER`, `CONE_TWIST`, `SIX_DOF`, `MOTOR` conditional on pinned backend. Validate anchors, axis normalized, limits/angles, spring stiffness/damping, motor max impulse/torque, break threshold if supported, connected-body lifetime and multithread mutation. SIM-04 owns animation/ragdoll integration and SIM-05 vehicles; basic joint type availability does not deliver either module.

## 5. Simulation tick, precision, CCD, replay and rollback
- CORE-06 fixed timestep and maximum catch-up per presented frame; 60Hz is a candidate **not approved hardware/DoD budget**. SIM-02 owns one solver Step at a CORE barrier, commands validated + stable ordering before step, deferred query/event/shape publication after step. Solver may use multiple cores via CORE job/adapter with actual architecture tests, never assumes GPU.
- Jolt `CROSS_PLATFORM_DETERMINISTIC` flag can help across compilers/OS, but only pinned exact source code, defines (e.g. `JPH_DOUBLE_PRECISION`), inputs, creation order and worker-command barrier permit a scoped claim. In Jolt some **broadphase query responses may vary** under multithreading; after bounding-box/narrowphase refinement and stable sorting, full ENGINE-owned event/command determinism remains future proof, not a result of compiling the flag. Other solvers' state and profiles not interchangeable.
- Headless scene physics may need high global coordinates: store durable transforms with CORE-05 global precision, use local solver island and `PhysicsOriginEpoch` shift at step barrier with GFX/WORLD-03/NET ACK. Never directly persist floating local physics position as global asset coordinate. Static world collision from WORLD-04 source and streaming cells needs origin epoch consistency.
- CCD flags and sweeps for fast bullets vs thin walls/targets, substeps/time-of-impact and late contact event quotas; **not** guarantee every fast dynamic/sensor pair; explicit cast for high-speed gameplay triggers if policy requires. Sleeping/activation/deactivation events kept consistent after teleport and streamed collider replacement.
- Determinism contract includes TickId/ordered Commands/world numeric profile/shape source hashes/backend version/compiler and flags/worker creation schedule; compare full position, velocity, sleeping, constraint impulses, events and hashes across native (Windows/Linux/macOS/ARM64) and browser CPU WASM if actually supported. Float bitwise equality is a **separate measured capability**; approximate replay must disclose precision/epsilon and never claim network lockstep.
- Optional rollback requires **backend-complete solver state** (contact manifold warm-start, island/sleep/constraints IDs) or explicitly documented re-simulation from initial canonical authored scene + complete input log; transforms-only snapshot is INSUFFICIENT. Restore must remap/invalidate generational handles and event epochs; NET authoritative prediction remains separate owner. Source authoring DATA-04 CAS commit != immediate physics-runtime publish.

## 6. Streaming terrain and critical collision readiness
- WORLD-03 cell staging gets DATA-05 cooked `StaticMesh3DColliderAssetId` or WORLD-04 `TerrainHeightColliderAssetId` immutable revision, validates terrain/cave topology and origin, stages solver body at PRE_STEP barrier and waits PHYS ACK for source+revision+epoch before `ACTIVE_COLLISION`. Missing required ground means explicit `COLLIDER_PENDING` or simulation navigation barrier, not silently falling through an uncooked map.
- Unload waits active dynamic bodies/constraints/owner leases, step contact expiry and memory fence/pin; CELL source removal generates coherent end contacts. Large dynamic bodies crossing cells owned once by WORLD-01 and pinned, never duplicated by each resident region. Texture/mesh visual LOD may be lower than collision fidelity, but any actual changed walkable ground needs PHYS revision ACK before replacing visible authoritative scene.
- CPU physics memory owned CORE-03, job buffer synchronization CORE-06, content caching DATA-05, asset rights DATA-02, source/undo DATA-04. CPU headless no GPU/RTX/CUDA dependence; PhysX GPU is **optional platform-specific path**, not Windows/macOS/browser baseline, and must not silently change authoritative simulation outcomes compared with CPU.

## 7. Security, platform and performance gates
- Reject ill-conditioned convex hulls, huge compound recursion, triangle mesh indices out of bounds, degenerate normals, infinite impulse/position and pathological constraint/collision graph, shape cook bombs, malicious imported assets, overlarge event buffer and unauthorized source edits/remote physics impulses. Input decompression quotas, asset permission, bounded world bodies/constraint/query/output count and cancel/retry policy. Return typed errors and no partial stage. Audit native memory with ASan/UBSan/TSan where supported.
- Future hardware profiles: headless x86-64 and ARM64 Linux, Windows DX-neutral CPU, macOS Apple Silicon native, Web WASM single worker fallback and optional multithread only under verified browser/security prerequisites. GPU rendering/render-target not needed for core physics. Candidate 100/1000/10000+ synthetic rigid bodies are **workload scales**, not promised supported counts or FPS.
- Bench independent convex collider vs ray oracle, stacks/sleep/joint drift and contact jitter/CCD tunneling, terrain/cave ground consistency, memory/active bodies, CPU tick p50/p95/p99 and worst, worker count 1/2/8, origin shift and world stream. Numerical tolerances/hardware thresholds currently unapproved; never claim “zero stalls” or fully deterministic before real runs.
- Candidate **S3P (Stormline 3D Physics Publication Gate)** optional PROVE-OR-DROP: snapshot-based staged collision activation after source+server ack, shared across WORLD-03 source/PHYS, measure lock time and extra memory vs simple barrier and drop if complexity/latency worse. Basic explicit barrier is NECESSARY, fancy speculative optimization is not. No superiority/novelty claim.
- Before coding: approve Scope+DoD+ADR-0032 and exact solver/version/license+ABI, integrated WORLD-02+CORE-03 implementation and WORLD-01/03/DATA/CORE owner contracts, raw SHA-256 source Context Lock, native/headless/Web builds and actual tests, benchmark and review 0 known HIGH/CRITICAL. `SIM-02` code #47 remains OPEN/BLOCKED; CORE-04 historical research gap pending.
