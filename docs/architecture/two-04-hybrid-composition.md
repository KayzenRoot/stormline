## 1. Mission: premium, coherent 2.5D without a second renderer
A true mixed 2D+3D composition model that can author pixel-art sprites and Canvas layers *in front of*, *behind* and *occluded by* 3D geometry, or anchor sprite characters to floors, terrain, walls and cutscene props. Ortho+perspective cameras, normal-mapped lit sprites, cast/receive proxies when justified, 2D animation and VFX, parallax and robust HDR/AA/UI ordering all share authoritative scene data/GFX render resources. Do not fake visual correctness through one unspecified sort list.

Owner catalog goal **"Projeto mistura sprites e mundo 3D preservando ordem/iluminação"** means future validated representative scenes and tests, **not** guaranteed quality or performance now.

### Three explicit composition semantics
1. **SHARED_DEPTH_WORLD:** 2D world sprites/billboards/2D-ground-plane elements become declared render primitives in GFX-03 same 3D depth/stencil view and compatible camera projection. Opaque/masked pixels may depth-write per material; blended sprites depth-test but generally **do not depth-write**. 3D meshes occlude sprites with correct per-fragment depth where geometry is comparable. World-space sprite material receives GFX-06 scene lighting and GFX-07 HDR as defined by explicit flags. THIS is the primary mixed-occlusion candidate; not all interpenetrating translucency can be perfect.
2. **ORDERED_CANVAS_OVERLAY:** pure Canvas layer with explicit order and alpha isolation, HUD/subtitles/pixel UI overlay at native physical resolution and unjittered GFX-07 output. Layers can be before/after whole 3D scene or composited by an explicit author-authored boundary. **No automatic mutual 3D depth occlusion**; requested depth illusion beyond that must warn or change mode, not invent per-pixel depth.
3. **ISOLATED_SUBVIEW:** a 2D or 3D camera renders to a GFX-03 offscreen target and feeds another pass as texture/viewport. Appropriate for in-world screens, picture-in-picture, 3D preview inside UI and portals only with explicit pass graph. By default this preserves **color and alpha but NOT cross-view geometric depth**, because projections/camera planes differ; depth reconstruction/reprojection is experimental, requires compatible linear depth, camera matrices and occlusion error bound. Never simply mix two arbitrary depth images.

All layers require typed declaration of mode, reference view/camera, color space, depth and painter precedence. Invalid mode combos reject with diagnostics instead of silent fallback that changes artist intent.

## 3. Typed coordinate bridge and projections
- Canonical `HybridScenePlanV1` references immutable world revision, scene-linear color target, camera+viewport (GFX-07), CanvasId and 3D mesh draw list (GFX-04); source coordinate conversion owned by DATA-03. Define explicit handedness+axis+units: glTF uses a **right-handed +Y-up coordinate system and meters**; this is a source format convention, not necessarily Stormline's engine global convention. Convert on import with coordinate metadata, no silent axis flip, scale factor, negative-determinant normal error or winding inversion.
- `HybridTransformBridgeV1`: source logical 2D pixel/world-unit ↔ 3D local meters ↔ camera view+clip ↔ depth normalized values ↔ framebuffer device pixels, with integer/relative origin and checked finite matrices. Optional pixel density mapping via `pixels_per_unit` and `baseline_offset`, validated at camera zoom/dynamic resolution and high-DPI.
- Billboard orientations: `VIEW_ALIGNED`, `AXIS_LOCKED` (e.g. world Y-up), `WORLD_PLANE`, `SCREEN_OVERLAY`; origin/pivot, physical size, world scale, tilt/normal and facing basis explicit. Camera roll and degenerate up vectors require fallback or typed error. Alpha cutout depth-writing changes what occludes it; blend depth-writing is dangerous and opt-in only with tested semantics.
- Depth handedness/reverse-Z: `DepthConventionV1` captures NDC convention, device format (e.g. depth24plus/depth32float if supported), near/far/clip-range, reversed-Z optional, perspective/ortho depth linearization, compare op and motion-vector projection. Must derive from GFX-01 and GFX-07 adapter, not hand-wave “0-1” universal. Near/far invalid, precision loss at near plane, negative scale and point behind camera must be tested. Camera at large 64-bit world position uses relative local origin and GFX-04 bounds.
- Orthographic sprites and perspective 3D may coexist **under one compatible projected view** if explicitly transformed; arbitrary second-camera depth maps cannot be merged via raw texture depth without reprojection/clipping and a reconcilable view. Mixed camera “cutscene shot” authoring must select a composition mode, not assume shared projection.

## 4. Layer order, depth, cutouts and transparency correctness
- `HybridCompositionLayerV1`: stable LayerId, authored order, mode, object group, view/projection id, depth test/write, mask/clip, alpha material, owner revision, optional receive/cast light channels and output role. Treat painter order as observable for ordered canvas elements; store source indices and stable tie-breaking.
- World opaque meshes write depth. World alpha-tested sprites may write depth at surviving fragments, giving good overlap and shadows but hard cutout edges; MSAA alpha-to-coverage optional device+quality proof. World *blended* sprites normally depth test but **do not write**, sort stable back-to-front per view or local collection with correctness caveats for intersecting geometry and soft particles. Sprite sort point (feet vs center) and stable actor group sorting prevent grass/character clipping, but center/Y sorting **is not equivalent** to per-pixel depth.
- Overlapping transparent 2D and 3D with incompatible order can be mathematically ambiguous; fallback choices: explicit render group+author priority, split meshes/layers, approximate weighted-blended OIT **optional** (depth weighting approximate, does not perfectly solve intersecting refraction/refractive glass, color order or group alpha), scene-only transparency stage. No blanket claim that OIT solves all cases or that PPLL is cheap WebGL2. GFX-08 still owns its particles and can request hybrid pass slot with reactive/depth.
- Depth/stencil and offscreen groups: GFX-03 validates attachment formats, resolves and hazards; do not independently own a depth buffer for the Canvas overlay. Stencil/path mask/clip ownership TWO-01; screen-space UI and 3D world depth cannot be silently collapsed to same region. In compositor run transparent sort per declared policy, never change Canvas painter source-over on a performance whim.
- Ground plane perspective billboards need explicit topological order and projected bounds, not a single Z “sort everything” scalar; camera dolly/tilt/crossings and static/dynamic meshes must be included in quality oracle.
- **No hidden loss of depth for post:** Unity warns that “Sort as 2D” on a 3D group clears its depth, so depth-based post-process ceases to work for it. Stormline must expose depth-preserving vs flattening modes at authoring time, rather than assuming correct depth-aware fog, DoF, SSAO, motion blur and TAA when information is unavailable.

## 5. Lighting and shadow bridge
- World-space sprites may carry unlit baseline or GFX-05 material normal/roughness for opt-in GFX-06 2D/3D scene lighting. `HybridLightingBridgeV1` requests explicit receiver/caster/normal orientation/two-sidedness, shadow geometry proxy, light group and budget class. No one shadow-casting local point light per sprite/VFX particle.
- In-world billboard normal orientation must be chosen: face-camera normal vs constant world-plane normal vs authored normal-map tangent space. Bad tangent mirror transforms can invert brightness; negative scale, double-sided normal handedness, linear colors and correct HDR emissive should be tested. Transparent shadow casting is special-case/approx with receipt, no arbitrary physically perfect transparency.
- Occluder geometry is visual shading only, PHYS remains collision/hit authority; do not treat visible shadow or sprite alpha as gameplay geometry. 2D lights for Canvas are GFX-06, not second shader pipeline here.
- Volumetric fog, light probes and GI share GFX-06/GFX-07 3D output. For 2D overlay no implicit depth, so depth-dependent fog or DoF is either unavailable or an explicitly supplied authored proxy. Unlit overlay must remain legible and use no excessive HDR exposure compensation.

## 6. Temporal coherence and composition order
- GFX-07 owns scene-linear HDR, exposure/tonemap, AA, motion vectors, TAA/FSR/XeSS plugins and history invalidation. TWO-04 only **requests** compatible per-object motion vectors/reactive/disocclusion flags, camera-cut/scale/rebase/atlas/skeleton events, plus pixel-art/rig crispness policies. World-space blended sprites can create TAA ghosting; no fabricated history.
- Preferred reference pass DAG (GFX-03 actual schedule owner): `validate source snapshots -> GFX04 3D opaque + depth -> GFX06 light/fog -> TWO01 depth-tested world sprite masked pass -> world transparent meshes/sprites/VFX per authored policy -> GFX07 scene-linear post -> pure unjittered Canvas HUD/overlay -> GFX01 display`. This is **a hypothetical pass-order reference**, not executed and not correct for every lit/opaque stage: exact placement must be verified through GFX-03 dependencies and material/light recipes. Alternative need to draw depth-writing sprites before lighting if they must participate in deferred G-buffer. Contract must expose stage and hazards.
- In-world scene UI (world-space labels) can be before/after world transparents depending policy but retains antialiasing/readability; native-size pixel art overlays must not be forced through scene downscale/upscale or temporal accumulation. Output scene-linear HDR alpha and premultiplied compositing before final output transforms when appropriate, UI post-tone-map only after explicit scene/display color mapping and accessible contrast verification. HDR10/P3/SDR negotiated by GFX-07 device capabilities only.
- Camera changes (ortho/perspective switch, FOV, dynamic resolution, viewport resizing, teleport, origin rebase, projection clip change) must invalidate appropriate temporal history, depth views and cached draw plans; never re-use disocclusion history across incompatible views.

## 7. Offscreen subviews, portals and Web fallbacks
- Subviews declared as render target graph dependencies with explicit sampling frequency, max pixel size/VRAM and per-view camera. A subview can be used for a minimap, item viewer, 3D actor preview in 2D UI, 2D screen in 3D, picture-in-picture and future portals; actual portal recursive teleport/physics is OUT OF SCOPE. Render-to-texture color/alpha and optionally depth source are typed; if depth cannot be transformed into host view, composite as **flat texture** with no incorrect host-world depth promise.
- Bound subview recursion and cycle detection in GFX-03 graph; no read-while-write same attachment, no stale use-after-free on resize/device loss, forbid cross-scene/project camera/data disclosure in Editor/MCP. Child view and parent view timing can be decoupled with exact frame/epoch metadata, stale update warning.
- WebGL2 minimum reduced tier: CPU-prepared sprite quads as Canvas/TWO-01, host 3D depth-tested alpha where capability is available, bounded draw layers/offscreen targets and **no compute/SSBO/PPLL/bindless assumed**. WebGPU device features probe for depth/resolve and target texture usages; Metal/Vulkan/DX12 variants need their own actual proof. No equality claim between reversed-Z depth formats across backends.
- Performance budgets are contracts, not magic: per-view color+depth bytes, MSAA sample count and resolves, subview width/height, pixel fill/overdraw, transparency draws, 2D-3D bridge instances, shadow proxies, GPU flush/stall, VRAM unknown vs measured, frame p50/p95/p99. When memory pressure triggers fallback, preserve painter/depth correctness and visible documented quality receipt.

## 8. Editor/CLI/MCP authoring, permissions and reliability
- Preview authoring must expose mode, camera, layer/depth/alpha policy, sprite anchors, per-object light receiver/proxy, subview source and documented compromises. Common safe semantic operations `InspectHybridScene`, `PreviewHybridSortPlan`, `PreviewDepthCoverage`, `InspectHybridLighting`, `PreviewSubViewBudget`, `Stage/Validate/CommitHybridEdit`. Resource estimates **are not screenshots**.
- Authoring transactions scoped to project/scene and expected revision via DATA-04 journal, bounded changes and role capability. No arbitrary shader/script, direct GPU resource handle, untrusted imported glTF source path/network, cross-project subview, readback of sensitive frame, export of copyrighted art or hidden permission escalation.
- Device loss / shader/memory failure / invalid depth target / scene hot reload: staged fallback must expose `DEPTH_UNAVAILABLE`, `ALPHA_MODE_UNSUPPORTED`, `WORLD_SPRITE_FALLBACK`, or previous valid subview with freshness indicator, not silent foreground sprite-through-wall bug or leaked transient buffers.
- XR/stereo, full portal with spatial depth reconstruction, 3D UI interaction focus/collision, ray traced sprites, sprite shadow GI improvements and SDF dense lighting are IMPORTANT/FUTURE not automatic NECESSARY.
