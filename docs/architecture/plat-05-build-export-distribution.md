## Contract and owner objective
Catalog scope: **"Export templates, assets por target, package manifests, símbolos, checksums e distribuição"**. Catalog acceptance: **"Export reprodutível de aplicações aprovadas; falhas claras por target."** Editor and exported 2D/2.5D/3D games are required on Windows, Linux and macOS (NLE-D017), browser games are planned with owner classification unresolved, mobile Android/iOS only if separately owner-approved. A reproducible *build plan*, a completed unsigned local export, a verified signed artifact, a staged candidate, a public release and an installed/updated application **are distinct evidence states**. No public build allowed until all version-1.0 DoD satisfied (NLE-D013), even if debug smoke builds eventually become possible.

## Export graph: verified snapshots, not shell injection
`ApprovedProjectSnapshot(AssetId/Scene revision/permissions)` -> `ApprovedTargetProfile` -> `ResolvedToolchainLock/ExportTemplateHash` -> `DATA-05 validated immutable cook generations` -> `versioned target-specific host/runtime modules` -> `deterministic stage tree` -> `unsigned payload hash and SBOM/license` -> `policy gate` -> `optional signing/notarization with new final hash` -> `signed candidate manifest, provenance and staging` -> `BIZ-03 release approval/publish/installation/rollback`. Each transition is an explicit job, signed-or-not status and receipt with immutable content-addressed IDs.

1. Preflight: verify Git HEAD/source SHA-256, Work Order + canonical Source Lock, approved ADR/release class/permissions, resource budget and target OS/ABI; **reject STALE or unapproved target**. Export only from a consistent project snapshot, not a writable source tree. Lock down file/mount paths and allowlist manifest keys and tools/command flags; no user project, remote asset or AI/MCP may inject shell, arbitrary build scripts or signing commands.
2. Resolve: version-pinned, hash-verified C++ compiler, CMake Presets/Ninja, sysroot/SDK, linkers and Emscripten/Wasm, OS-native packager; separate **host** and **target** identities; [CMake cross compilation](https://cmake.org/cmake/help/latest/manual/cmake-toolchains.7.html) cannot execute compiled target binaries on build host by default. Offline/no network except explicitly declared dependency fetch with pinned digest; license and redistribution policy checked before toolchain adoption.
3. Cook: invoke DATA-05 target-specific immutable manifest, stable AssetIds, texture/audio/mesh and shader tier, dictionary/codecs/length/hash; no reallocation based only on OS brand. Reject stale source rev/cook mismatch/budget overflow, case-fold or Unicode collisions, archive traversal and symlink attacks. Cooked bundles are derived outputs, never overwrite user-authored asset/scene documents.
4. Build: deterministic tool invocation with explicit input digests, environment/timezone/locale, stable source timestamp ([SOURCE_DATE_EPOCH](https://reproducible-builds.org/docs/source-date-epoch/)), archive entry order, permissions and uid/gid, prefix-map debug paths, UUID/build-id, stable process environment, deterministic zip/tar if tool allows. Avoid copying secrets or absolute paths into artifacts. [CMake Presets/toolchains](https://cmake.org/cmake/help/latest/manual/cmake-toolchains.7.html) are candidates, not committed versions. Diffoscope/independent two-build comparisons **future**.
5. Stage: fixed target template version & hash, bundle metadata (product/channel/version/semver, architecture, minimum OS, entrypoint, dependencies, native library and WASM/JS/data hash), required icons/locale/splash/rights, canonical JSON manifest serialized with deterministic key order/encoding. Exports reside under a clean staging root per artifact generation and never inside authored source path; no writable input sandbox used by untrusted plugin.
6. Verify: structural/ABI/SDK dependency scan, installed-runtime library existence and API checks, dependency license/SBOM and image/font/notices, file digests and independent readback; fail if any required target feature unsupported. Separate **reproducible unsigned payload** vs **signed/repacked distribution**. Signatures/notary timestamps intentionally vary; inspect the final signed package digest and attestation, never falsely demand bytewise equality after signing.
7. Attest: [SLSA v1.2 build provenance](https://slsa.dev/spec/v1.2/build-provenance) uses in-toto Statement v1 and predicateType **`https://slsa.dev/provenance/v1`**, `subject` digest, `buildDefinition` (external params + dependencies) and `runDetails` builder id. [GitHub artifact attestations](https://docs.github.com/en/actions/how-tos/secure-your-work/use-artifact-attestations/use-artifact-attestations) can generate verify-able build/SBOM attestations for eligible public repos but **no attestation can be claimed until a real eligible build/job and verification**. SLSA Build L1/L2/L3 requirements escalate with trusted builder/isolation; including metadata does not confer security level.
8. Stage/commit: only after tests+security+owner release gate, immutable artifact manifest references payload hash and optional final signed digest, signed source provenance and SBOM; BIZ-03 controls release channel, staged rollout, active generation pointer and update/rollback. Prefer immutable GitHub releases only when separately configured, not implicit. For crash/power loss record last-good, recoverable self-contained generations and atomic pointer swap when filesystem supports; **atomic rename of one pointer does not provide multi-file or cross-volume atomicity**. Platform-specific manager/store update policies override generic installer.
9. Any denied/unsupported/stale/no-signer/unlicensed result is typed and preserves previous valid generation and user project. Unapproved private key or Developer ID/CA account not created, no paid service, no root/sudo, no store submission, no AI agent auto-sign/publish.

## SBOM, supply-chain, rights and provenance policy
- Candidate machine-readable **SPDX 3.0** ([official](https://spdx.dev/use/specifications/)) or **CycloneDX 1.7** ([official](https://cyclonedx.org/specification/overview/)), select one default after tool compatibility and verifier availability proof; include transitive native/static/dynamic libs, JS/Wasm/npm deps, codecs, shaders, fonts, images, samples, runtime/platform redistribution restrictions, license texts and source notices. SBOM is *not* a source license grant nor proof absence of malware.
- Content hash SHA-256 for each code/native library, bundle/chunk, debug symbols and manifest, file lengths and formats, no MD5-only release identity. Derive distinct source/toolchain/cook/export/payload/signed artifact/channel IDs. Package license compatibility checks and SPDX identifiers must be manually/automatically verified for exact versions; NLE-D009 engine license OPEN => **PUBLIC DISTRIBUTION BLOCKED**.
- [SLSA provenance](https://slsa.dev/spec/v1.2/build-provenance) and optional Sigstore/in-toto or GitHub OIDC signing must bind trust policy to repository/ref/builder/commit and subject digest, not just “metadata exists.” CI with untrusted PRs may build docs but cannot access deploy credentials; tokenless read-only permissions by default. **Never claim SLSA L2/L3 solely from an attestation file.**

## Updates, rollback and BIZ-03 interface
Product release channels INTERNAL / CANARY / BETA / STABLE with approved semver/order and release class. BIZ-03 owns immutable publication and install/update state: verify signer + provenance + source/target arch + security policy + target SHA; download to quarantined staging with size/codec/range/budget limits, full checksum; save prior generation, stage full dependency closure, atomically change active release pointer when on single volume, journal recovery, disk-full/power-loss/signer revoked/kill switch. **Do not overwrite running binary or mutate user project**. Browser requires origin/build manifest + service worker generation and offline stale cache evacuation, not a POSIX rename. OS stores may govern rollout/revocation. Roll-forward security fix rather than rollback to known vulnerable build unless approved security exception. Downgrade prevention/rollback exception must be signed and audited, not untrusted asset command.
