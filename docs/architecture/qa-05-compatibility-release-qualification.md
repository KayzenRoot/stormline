## Capability probing over model marketing labels
- **Windows D3D12:** enumerate adapter and feature levels, Shader Model/Root Signature/feature support and presented frame/device removal. Device vendor string or “DirectX 12 compatible” alone is insufficient.
- **Vulkan:** instance extension, physical device feature bits, queue families, memory heaps, surface formats/presentation modes, driver/API version, Vulkan Profiles profile-conformance claims only with actual matching query; portability subset separately validated where applicable. [Khronos Vulkan Profiles](https://docs.vulkan.org/guide/latest/vulkan_profiles.html) maps required capabilities, not automatic real test.
- **Metal:** use `MTLDevice.supportsFamily`; older `MTLFeatureSet` API is deprecated. Apple ARM shared system memory and Intel GPU memory/resource limits differ, do not claim identical tier or Rosetta as hardware equivalence.
- **WebGPU:** secure context + `GPUAdapter.features/limits` vary by browser and privacy tier; request only supported features, check device lost; WebGL2 fallback if approved separately. [WebGPU spec](https://www.w3.org/TR/webgpu/) prevents unconditional feature inference.
- Software-only WARP on Windows, SwiftShader Vulkan CPU, browser software raster, virtual GPU, Xvfb/llvmpipe may validate basic API/functional semantics **and must be tagged SOFTWARE/VM/HEADLESS**. Never substitute for actual AMD/NVIDIA/Intel/Apple performance, driver, HDR, display/VRR, device loss/thermal qualification.

## Future gate model and states
`NOT_RUN -> NEEDS_HOST -> TESTING -> PASS | FAIL | INCONCLUSIVE | UNSUPPORTED | BLOCKED`, with `STALE` when source/fixture/driver/toolchain or owner target floor shifts. A scene/replay test passes only if QA-02 visual/audio/input/semantic oracle and build artifact QA-05 manifest agree. False green when skipped or unsupported must be rejected. **Support claims include only explicitly qualified complete platform cells**; unreached drivers/models logged as NOT_QUALIFIED and owner release gates determine scope.

## Hardening and clean-room install, update/revert
- **PLAT-05 source/manifest:** exact build toolchain/SDK/version/ABI/native arch, compiler and libc runtime, app bundle files+digests, driver minimums and resource counts, certificate/notarization verification where owner approved; reproducible independent build/diff proof *separate* from valid signatures. Code signing identity cannot be invented or acquired in documentary research.
- **Clean environment:** package install/uninstall/reinstall, permissions, missing runtime/DLL or `.so/.dylib`, user data persisted independently from application install, localized paths/non-ASCII names, read-only filesystem, network offline, missing GPU, high DPI/hotplug, user install vs system install.
- **Recovery strategy:** project/save written to versioned temporary file, flush/sync as supported, hash/schema validate, atomically replace (with platform-specific FS and directory durability caveats), maintain independently verified *last-good* snapshot, recover after crash/power failure and prevent corrupt state from replacing backup. A mere “rename” is **not** universal guarantee of durable atomic persistence across power loss; injection/reboot real FS tests required.
- **Schema migration:** versioned directed transitions and reversible/irreversible map, backup before migration, crash injection after each stage, idempotency on replay, rollback/roll-forward with authored source SHA/manifest and data compatibility. If format downgrade cannot be safely supported, deny downgrade and offer restore from pre-migration backup, never silently truncate.
- **GPU reset:** queued commands/fences cancel, swapchain/device generation invalidates stale resources, recreate according to GFX owner and restore QA-02 fixture state; device-loss testing includes actual driver/device if permissible and separate controlled simulated fault. Real induced driver resets require explicit owner permission and isolated hardware.
- **Soak/stress:** long replay on physical available hardware with resource/memory/VRAM/present, saved state checksums, crash/hang counters and event logs, QA-03 p95/p99 as integration but not extra formal dependency; thermal/power sampled if sensor allowed. Predefine duration/repetitions/acceptable slopes and fail if required hardware not actually available. No claim from Docs CI.
- **Browser resilience:** HTTPS origin/cache/asset versioning/service worker if approved, browser tab suspension/resume/WebGPU lost, orientation/zoom/DPR, memory limits, text accessibility, save/storage quota and migration before refresh; security policy/CSP and privacy ownership integrated without silently changing PLAT-05.
- **Upgrade and rollback:** verified release subject hashes/signatures/metadata, tested upgrade path N→N+1 and downgrade N+1→N for both executable and save; no unsigned rollback, no live user data overwritten in test. Recovery drill only on original synthetic project fixtures with access controls.
