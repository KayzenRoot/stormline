## Proposed tiered test strategy
1. **T0 strict functional state and invariants**: unit C++20 assertions after real code exists; content-addressed input fixtures; compare precise integers/IDs, stable scene hierarchy, simulation events, action maps, serialized output, error codes and rendering graph DAG/cycle/access results. CMake [GoogleTest gtest_discover_tests](https://cmake.org/cmake/help/latest/module/GoogleTest.html) is candidate, but cross-compile discovery runs test executable and requires `CROSSCOMPILING_EMULATOR`; `gtest_add_tests` static fallback can preserve discovery if no emulator. Catch2/doctest alternatives; framework owner choice undecided, don't introduce duplicate test runtimes needlessly. Native CTest must execute nonzero expected test count with stable seed and timeout.
2. **T1 deterministic software/offscreen goldens**: fixed C++ clock, fixed-step simulation, seeded RNG, canonical stable IDs/order/serialization, immutable asset/scene/version hashes, locale/timezone, font stack, render resolution/viewport/DPI, camera & exposure, shader/compiler flags. A CPU/software Vulkan reference such as [SwiftShader](https://github.com/google/swiftshader) can be a pinned R$0 candidate, but **CPU-only/software proof does not certify physical GPU hardware, Metal, D3D12, driver accuracy or power**. Chromium's [SwiftShader fallback](https://chromium.googlesource.com/chromium/src/+/main/docs/gpu/swiftshader.md) is intentionally deprecated for general automatic WebGL and insecure for untrusted content, never globally force `--enable-unsafe-swiftshader` on arbitrary projects. Linux virtual framebuffer alone cannot create a functional GPU/render graph backend.
3. **T2 graphics API/driver class constrained goldens**: register baseline per backend (Vulkan/D3D12/native Metal/WebGPU/WebGL2 as future approved), vendor/driver/GPU family, image format, colorspace, sample count, depth/origin/convention, shader revision, postprocess and target quality tier. Exact same deterministic software stack permits **pixel-exact** for well-defined integer/ID/flat UI passes only; cross vendor/driver has floating point, rasterization, interpolation, precision, dithering, HDR and MSAA differences. Compare in specified linear-light and display-referred sRGB with explicit decode/encode, ICC/color-primary/exposure metadata; strict semantic outputs (IDs/geometry, depth sign, alpha premultiply, UI legibility, text clipping) override permissive SSIM.
4. **T3 perceptual and anomaly oracles**: [OpenImageIO idiff](https://openimageio.readthedocs.io/en/latest/idiff.html) for absolute/relative errors and signed heatmaps, [scikit-image structural_similarity](https://scikit-image.org/docs/stable/api/skimage.metrics) for SSIM with **explicit `data_range`** for floating images, optional perceptual LPIPS only if model license/weights and reproducible inference validated. [Khronos Vulkan development tools](https://docs.vulkan.org/guide/latest/development_tools.html) validation/synchronization/GPU-assisted layers are distinct functional GPU correctness gates, not image quality pass. Use metrics **RMSE/MAE, max channel error, fraction mismatched, SSIM, edge map, semantic masks**, report all; **hard invariants cannot be waived by high SSIM**. No arbitrary “one universal threshold” or baseline laundering across driver classes.
5. **T4 interactive gameplay/Editor/browser**: deterministic input/event trace (mouse/touch/gamepad/keyboard/action), scene timeline fixed ticks and world hashes; headless simulation run on Linux/Windows/macOS only after actual runtime. Automated playtest asserts trigger/collision/navigation/world persistence/action semantics and includes failure replay first mismatch tick. Browser [Playwright toHaveScreenshot](https://playwright.dev/docs/test-snapshots) pinned browser/OS/DPR/fonts and fixed animation, screenshot assertion uses pixelmatch threshold/maxDiffPixels/maxDiffPixelRatio and **platform-specific snapshots**, no automatic rebaseline on failure. [ARIA snapshots](https://playwright.dev/docs/aria-snapshots) for browser semantic accessibility and keyboard focus, but native Editor accessibility requires actual OS UI automation/physical or QA-05; screenshots do not certify VoiceOver/Narrator/TalkBack.
6. **T5 audio test oracles**: when AUD module exists, render deterministic PCM from original generated waveforms (sine, impulse, silence, pink noise, sweep with seed, channel pan, pitch) into **in-memory/offline** buffer with known sample rate/channel/bit depth/dither/latency and mixer graph. Exact sample hashes for same deterministic scalar DSP path; across SIMD/compiler/device use owner-approved max absolute/RMS error, spectral band powers, normalized cross-correlation/onset latency bounds, DC offset, peak/true-peak/clipping, silence gate/channel isolation and loop/crossfade continuity. Acoustic output/speakers/background device controls are different hardware tests; no playback of copyrighted game music. Avoid naive floating PCM bitwise cross-driver guarantee or “loudness equivalent” when audible transients differ.
7. **T6 fault, a11y and security**: negative fixtures for corrupted scene/assets, resource/stale generation, GPU device loss, false sleep/clock jumps, font missing/unicode shaping, keyboard-only navigation, high contrast, motion reduction, flash/seizure triggers, screenreader semantics, audio mute/captions as future owners permit. Threat model: malicious PNG/EXR/GIF/wav/video/parsers/zip/decompression bomb, symlink/path escape, PII in screenshots or recorded voice, counterfeit baseline/update, untrusted test fixture scripts, license of goldens and ML weights, deterministic cache poisoning and artifact leakage. No arbitrary project scripts or render-mode workaround with privileged permissions.
8. **T7 gate and governance**: two-snapshot independent owner-reviewed update for intentional visual change with signed `BaselineChangeReceipt`, source+fixture+backend/driver hash, before/after heatmap and reason, review/evidence, CI and expiration. No auto-`--update-snapshots` on failing branch or AI-generated golden acceptance without review. Red test provides raw+expected+diff, first failing frame/tick, metric/mask/threshold, CTest failure and replay command; true nonfatal driver differences become bounded **explicit tier** with owner signoff and expiry, not global golden “pass”.

## Deterministic fixture specification
- `TestFixtureManifestV1` includes unique stable fixture ID/version, original asset creation/license attribution and hashes, project/world/scene revision and DATA-05 cooked asset hash, seed, initial sim state, fixed tick Hz + count, stream of timestamped INPUT action id events, headless/visible mode, camera position/projection + origin, physics world state and expected semantic state hash, render graph pass/resource ID + device generation.
- `CaptureProfileV1` includes backend and renderer/device driver/software flag, compiler/shader permutation/build/source hashes, resolution, DPI, ICC transfer/color primaries, LDR/HDR format/tone map/exposure, MSAA, TAA jitter seed/disabled, motion blur, alpha premultiplication and capture pass, frame index+GPU barrier/readback fence proof and array format. Vendor/driver **UNKNOWN** means cannot join physical GPU baseline.
- Reference content approved via code review/PR and versioned **raw content hash, baseline lineage**; PNG/EXR canonical encoding/readback bytes and metadata (for HDR EXR native float data range, never compare raw encoded HDR values to LDR PNG). Clean immutable fixture packages can be content-addressed; no license-derived screenshot of third-party proprietary games; no original assets currently exist.
- Backends may choose `NO_GRAPHICS`, `SW_VULKAN`, `PHYSICAL_GPU_VULKAN`, `D3D12`, `METAL`, `WEBGPU`, `WEBGL2`, never convert a software result to proof of another backend. Golden acceptance requires runtime capability receipt and exact scene/backends baseline key.
- Temporal goldens: multiple frames, causal event action/time, history/resets TAA, particles, stochastic shaders seeded, frame-in-flight GPU fence and resource hazard validation. Define expected behavior when nondeterministic GPU scheduling prevents exact pixel equality: separate semantic and perceptual thresholds with measured reference **not arbitrary broad tolerance**.

## Failure and evidence semantics
`MISSING_BASELINE`, `STALE_FIXTURE`, `NO_TESTS_EXECUTED`, `TEST_FAIL`, `GOLDEN_DIFF`, `DRIVER_CLASS_MISMATCH`, `COLOR_SPACE_UNKNOWN`, `CAPTURE_UNSYNCHRONIZED`, `RENDER_DEVICE_LOST`, `AUDIO_MISMATCH`, `A11Y_FAIL`, `LICENSE_UNCLEAR`, `UNTRUSTED_FIXTURE`, `COST_GUARD`, `INFRA_FAIL`, `BASELINE_REVIEW_REQUIRED`. Never mark a regression PASS based only on fuzzy SSIM. Store failing actual/expected/diff and signed provenance if supported in owner-authorized access, redact project paths and secrets. Include first mismatched tick/frame and compression/raw hash, not silent "all good".
