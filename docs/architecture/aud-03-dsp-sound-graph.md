## 1. Objective and acceptance truth
Catalog scope: **"Filtros, efeitos, RTPC/automation, snapshots, mixing hierárquico."** Catalog acceptance: **"Graph validado, teste de clipping, estabilidade em tempo real."** Define an **engine-owned, typed and bounded DSP processing graph** for original 2D/2.5D/3D games, native Windows/Linux/macOS, optional browser AudioWorklet and CPU/headless NullSink. Propose predictable EQ/filter, dynamics, delay, distortion, reverberation, convolution, sends and sidechain control with automation and graceful quality tiers. Real quality/latency is not established by docs, and "best" DSP claims need measured original test signals and matched competitors.

Graph authority explicitly excludes physical PCM output. **AUD-01 exclusively owns AudioDevice, AudioVoice, buses, PCM mixer, callback, sample rate/sample-frame clock**, including already-planned bus gain/pan/sends. AUD-03 may attach one versioned **effect chain or graph plan** to AUD-01 bus/voice inserts and buses' effect lanes without duplicating the hierarchy or separately summing output. **AUD-02** produces spatial HRTF/IR and room sends and may request AUD-03 convolution, with no duplicate spatial source or device. **AUD-04** controls adaptive music/dialogue timing/automation as a consumer, not DSP engine. Every architecture item is **not implemented**.

## 3. Two-stage graph and immutable runtime plan
```text
Editor/CLI/MCP authenticated StageDspGraph + expected DATA-04 CAS revision
  -> non-RT schema and asset rights validation
  -> graph topology check, port/channel/layout and sidechain connections
  -> rejects unbounded cycle, unsupported node, zero-delay feedback, bad latency
  -> per-node DSP state and immutable graph revision + memory/CPU estimates
  -> CORE-03 non-RT compile/FFT plan/IR load, dry-run and safe allocation
  -> immutable `DspExecutionPlanV1` with topological schedule and scratch offsets
  -> AUD-01 quantum-fence publish with one DeviceEpoch/BusGraphRevision
  -> preallocated RT process: reading buffers, bounded f32 filter/sidechain/FX kernels
  -> AUD-01 master bus mixing and device output, one sample-frame authority
  -> typed `DspRenderReceipt` / redacted non-RT counters and deferred retirement
```
Compiler must prove **finite work**: bounded `node_count`, `edge_count`, `max_channels`, `scratch_bytes`, `state_bytes`, `latency_frames`, `tail_frames`, total IR/FFT partitions, automation events/quantum and complexity tiers. NodeFactory accepts only allowlisted built-in deterministic-safe types in first slice. A "plugin" cannot quietly write arbitrary code into audio thread, bypass validation or access host paths/network. Any library adapter must remain private to Stormline and own its error/stop lifetime.

**Graph structure:** a directed acyclic processing graph (DAG) of zero-latency edges and explicit processing nodes; per-voice/bus insert effects are graph roots or named slots exposed by AUD-01. Parallel sends use single AUD-01 bus routing authority, not duplicate summation in DSP engine. Sidechain/key input is a separate typed **signal/control** port, never a pointer to hidden voice state. Feedback/comb/reverb are supported only as **bounded prevalidated internal delay node with minimum delay and spectral/stability cap**, never arbitrary zero-time cycle. An intentional feedback graph cannot be enabled until its actual sample-block causality and memory/peak proofs exist; first phase rejects cycles.

## 4. Blocks, channels, processing model and latency
`DspNodeDescriptorV1` declares node type/version, input/output ports and channel layouts, sample rate supported range, latency/tail semantics, in-place safety, SIMD alignment and scratch requirements. `DspProcessContextV1` has immutable sample `frameStart`, `frameCount`, rate, DeviceEpoch, preassigned buffer spans, parameter segment events and errors; **never raw malloc/free or callback on arbitrary node startup**. Allow 0, 1, and variable quantum sizes only after observed backend capabilities; 128/256/512 frames are **benchmark workloads not universal defaults**. Channel layout explicit tags for mono/stereo/5.1/7.1/Ambisonics; no implicit channel swapping or hidden resampling.

Latency handling: `NodeLatencyFrames` and `GraphLatencyFrames` computed offline/graph compile. Parallel dry/wet, bus returns and sidechains require measured delay compensation or a **typed unsupported/DEGRADED result**, not phantom zero-latency sound. Report lookahead compressor/limiter latency, FIR/partitioned convolution algorithmic delay and oversampling group delay. `TailFrames` bounded and voice/bus retirement policy must keep reverbs audible or intentionally fade with explicit receipt; infinite tail prohibited. AUD-01 handles audio timing and device clock; graph reports cumulative fixed sample delays and can request safe remap after sample-rate changes. Atomic graph swap uses crossfade/zero-discontinuity strategy, deferred freeing old buffers after callback epoch, and explicit buffering budget.

## 5. Built-in filter, EQ and dynamics candidate semantics
**Filters/EQ:** first proposed NECESSARY reference nodes are gain, mute/bypass, one-pole low/high-pass and stable biquad peaking/shelf/bandpass/notch (RBJ cookbook as formula reference; DSPFilters MIT candidate). Constrain frequency `0 < f < Nyquist`, Q and gain, avoid poles on/outside unit circle, avoid NaN coefficient division and pole interpolation instability; use coefficient smoothing or recomputed safe structures, no structural rebuild on each sample. Denormals/NaN/Infinity clipping after failed hostile input should produce bounded silence/bypass, not audio speaker blast. Filter gain in dB vs linear clearly typed.
**Dynamics:** envelope follower RMS/peak with attack/release and optional lookahead, compressor threshold/ratio/knee/makeup, expander/gate, de-esser input signal optional, hard/soft limiting only under explicit peak semantics. Simple sample peak clip limiter **does not ensure true peak** after reconstruction; true-peak requires oversampling and explicit lookahead, declared latency and validated intersample reconstruction. Avoid zero-attack/zero-release oscillation/infinite gain; bounded sidechain. Compressor prevents **gain increase from invalid sidechain** and never trusts arbitrary packet RTPC.
**Saturation/Distortion:** selectable soft clip/hard clip/waveshaper with finite, DC-filtered and aliasing-aware quality tiers; optional oversampling after measured tradeoff, not a default claim. Distortion and high gain must have deliberate output protection but not silently overwrite artistic source controls.

## 6. Time-domain FX, reverberation and convolution
**Delay/chorus/flanger:** circular preallocated ring buffers, bounded delay time, interpolation, feedback magnitude and wet/dry, modulated rates with anti-click smoothing, negative/huge ring lengths rejected. No file I/O or memory resizing in callback. Reverbs (Schroeder comb/allpass/FDN) must account for decay-time `T60`, damping and energy stability and avoid unbounded feedback and cross-channel leakage.
**Convolution** (FIR and partitioned FFT): optional high-quality impulse response reverb and HRTF-derived kernels. IR source validated DATA-03/05 with rights, max length/channels/rate, specific bakes from AUD-02. FFT planner, IR partitioning, window/twiddle and resample happen on CORE-03 non-RT jobs; RT uses fixed preallocated overlap-save/add buffers and measured bounded per-quantum processing. KissFFT BSD3 and DSPFilters MIT are comparison candidates, not adopted. PocketFFT BSD3 may allocate temporary scratch per transform, so wrapping it in RT needs demonstrated scratch control or off-RT route. FFTW GPL/commercial excluded from unreviewed engine linking.
**Spatial/IR ownership:** AUD-02 owns geometric room/IR selection/asset; AUD-03 owns general DSP convolution filter scheduling/state; AUD-01 only applies bounded effects after auditable graph insert points. Avoid duplicate HRTF convolution or reverb reprocessing.

## 7. RTPC, sample-accurate automation, snapshots and game time
RTPC (Real-Time Parameter Control) is not hardcoded to one gameplay system. Typed `DspParameterId` with units/range/rate/class and default smoothing, `AutomationCurveV1` containing ordered sample offsets or TickId mapped rationally through AUD-01 `AudioClockMap`. Accept authoring from GAME/NET-validated producer with role/source/sequence/expected parameter revision. Curve evaluation inside RT is **bounded by per-block events, precompiled segments and non-allocating state**. Sample-accurate ramps are possible only when renderer declares supported granularity; otherwise report control-rate quantization/DEGRADED, not false sample accuracy. Clamp cross-parameter dependencies, blend priorities (manual+game/RTPC+scene snapshot) via documented precedence and restore on gameplay state rollback.
`AudioMixSnapshot` from AUD-01 governs global buses/gains; `DspParameterSnapshot` from AUD-03 governs effect-node states. A scene/acoustic room snapshot requests wet/dry/tail changes by parameter refs and expected graph revision, not direct rebuild in callback. Sidechain compressor key route is graph compiled and latency compensated. Game/NET event and sound audibility remain distinct: a client's UI effect setting never changes authoritative combat/perception gameplay.

## 8. DSP quality tiers and safe fallback
Future tiers: `DRY_SAFE` (bypass or gain), `BASIC_EQ_DYNAMICS`, `STANDARD_FX` (bounded delays/saturation/reverb), `HIGH_CONVOLUTION` (long IR/oversampling) and `EXPERIMENTAL_PLUGIN` (unsupported until isolated). Tier changes use crossfade, explicit tail/memory and live `AudioCapabilities`, not silent shader/physics edits; headless NullSink must be capable of deterministic original PCM golden tests without sound card or GPU, but no build exists now.
If CPU deadline/RT callback budget missed: emit `DSP_BUDGET_EXCEEDED`/typed degraded receipt, bypass expensive effect or retain last known stable coefficients with click-free transition, never infinite silence/output blast or block. Progressive degrade may prioritize dialogue/accessibility/UI over ambience. Decouple sample-control and gameplay-physics clocks, report observed XRUN and latency rather than falsely guaranteeing zero xruns.

## 9. Plugin security, isolation and licensing
**Important policy:** the CLAP specification is **MIT**, but a CLAP/VST/LV2 binary is **arbitrary third-party native code** running with host process permissions if loaded in-process. Interface compatibility is **not a security sandbox**. Therefore an untrusted plugin host is **FUTURE and disabled by default**, subject to explicit user opt-in, license/asset rights, plugin trust/signature/allowlist, per-vendor ABI/feature review, process isolation or tested WebAssembly sandbox, bounded shared memory/ring communication, no RT blocking IPC, lifetime/watchdog/crash recovery, denied host file/network/secret access. In-process trusted signed plugin remains an elevated risk; no security claim just from "signed".
A low-latency bridged plugin introduces at least buffering/scheduling/synchronization and measured crash recovery; if isolation cannot be guaranteed within latency budget, **do not offer arbitrary plugin load**. CLAP MIT, LV2 ISC candidate are **standards**, not free plugin licenses. Faust compiler output licensing depends on input DSP libraries/architecture files; GPLv3 functions can contaminate a shipped compiled catalog even if compiler license doesn't. Soundpipe MIT is **archived since 2024**; standalone module licenses/transitives and code maintainability must be checked. FFTW GPL/commercial excluded default. Every vendor license pin/SBOM/attribution/NDAs and NLE-D009 engine license remain **OPEN**.

## 10. Security and recoverability
Threats: adversarial graph cycles, invalid port/channel layouts, zero-delay feedback, denormal CPU storms, NaN coefficients, IR decompression bombs, huge delay/FFT allocations, floods of parameter events, stale sample/DeviceEpoch, hot-reload node/plugin UAF, memory corruption from native plugins, exfiltration of source voice/data and unauthorized MCP or client automation. Proposed guards: bounded schemas, type+range, DATA-03 sandboxed input, CORE-03 non-RT compilation, preallocated CPU time/memory budget, immutable execution plan and epoch-controlled retirement, typed role/command permission, offline/no arbitrary filesystem plugin default, ASan/UBSan/TSan/fuzz (FUTURE).
Metrics from CORE-06 outside callback: graph revision, CPU per node, RT p50/p95/p99, true/false peak, clipping count, denormal events, silent bad input, planned vs actual latency/tail, control event late/drop, voice/bus FX count, IR bytes, plugin crash/timeout if ever enabled. No private PCM/audio samples exposed to untrusted telemetry and no microphone/recording permission.
