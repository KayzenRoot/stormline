## 1. Problem, user journey and completion contract
Stormline needs an original, productive, professional-grade **manual** editor for 2D/2.5D/3D and eventually browser-authored workflows across **Windows, Linux, macOS**. The explicit catalog acceptance is **"Workspace salva/reabre, UI de múltiplos monitores com erros recuperáveis."** A future first functional test is to open a blank project, dock/undock/swap panels, rename workspaces, use keyboard and menus, persist/restart, unplug/move a monitor, restore every essential control visibly with no lost project data, and use keyboard/assistive navigation. Do not mistake a screenshot/demo of a toolkit for a functional editor or a native viewport test.

**Architectural thesis (PROPOSED):** Stormline-owned **Editor Shell semantic core** independent of a replaceable native UI toolkit adapter. Provide a command registry, focus/selection scope, accessibility semantic tree contract, window/dock graph, workspace versioned snapshots with safe migration and external tools host, explicit viewport surface ownership and action permission checks. A toolkit adapter translates shell commands and semantic state to widgets, windows and screen readers but does **not** decide project/game authority. The full engine still has separate windowless headless server.

## 3. Process and event-loop separation
**Proposed host lanes:** OS/window event & accessibility adapter on UI-main-thread (backend restrictions), typed EditorCommandBroker, DATA-04 async persistence/transactions, viewport RHI surface subscription with bounded frame mailbox, optional isolated play-in-editor process or safe plugin subprocess. Editor UI event loop stays responsive while runtime/asset load/renderer stalls, with cancellable progress and no lock-coupled frame presents. Headless NET-02/server does not depend on UI and cannot call editor code. Do not assert a particular thread model until backend has been selected and platform-native demos validated.
 
**Editor pane model:** `EditorWindowRef` and `DockNodeRef` stable scoped IDs, panel role and registered factory, ownership in a window/dock graph with tab groups, split ratio, min/max and close/float constraints. Panels can detach to OS windows **only if** backend/platform reports a tested capability. Accessibility and focus ownership accompany panel across windows. A closed panel is restorable from command palette; no orphaned essential menu or keyboard trap.

## 4. Workspace, persistence and recovery
`WorkspaceSnapshotV1` fields: workspace ID/version, app/build and display-layout compatibility, per-panel stable semantic ID/role plus dock tree, normalized geometry+monitor fingerprint (never serial/unique identifier exposed), DPI at save, viewport selection and user theme/shortcut profile reference, dirty flag, checksum/schema and opaque backend state **only for trusted locally generated data**.
- Save through DATA-04 atomic write/compare-and-swap, no partial layout replacing last known good; version schema upgrade uses explicit reversible migration, validation prior to allocation, bounded node depth/count and normalized ratios. Archive last known good and safe built-in fallback layout. Never deserialize untrusted toolkit binary blob from shared project/file/network without safe guard; **Qt QMainWindow::restoreState docs explicitly warn against restoring untrusted binary state**.
- Monitor topologies: primary-only, 1/2/3 monitors, same/different DPI, monitor removed, negative origin, scaled display, portrait and Wayland compositor restrictions; map **logical device-independent** coordinates to physical pixels per current screen; clamp off-screen/floating panels and rehome indispensable commands to visible primary monitor on restore. No fake absolute OS-position guarantee on Wayland.
- Concurrent editor instances: workspace user profile distinct project save state, multi-project instance lock/CAS, conflict resolution and versioned recovery; no surprise overwrites. Persistent user layout does not encode private project auth keys or untrusted executable plugin.
- Temporary dock drag/close operation should have cancellable/non-destructive undo of **host layout only**; actual scene/asset undo belongs EDIT-03/scene transaction and DATA-04. Distinguish Undo in active context with visible command scope and conflict warning; never route Ctrl+Z to an arbitrary inactive panel or replay game economy.

## 5. UI interaction, keyboard, accessibility and localization
Semantic editor command registry `CommandIdV1` with name, description, category, enabled predicate, selection type/target, authorizing capability, action+undo scope, required origin (menu/palette/key/MCP), shortcut profile and conflict resolution. Shortcut chords normalized by OS keyboard layout/IME and meta/ctrl keys, reserved OS combos never grabbed, localizable labels. Focus chain/tab order works across dock/float windows and modal context; Escape cancels drag/dialog safely; mouse and keyboard full functionality for core shell. Gamepad optional for viewport navigation when meaningfully supported; do **not** impose gamepad parity on text editing or file manager without explicit scope.

Accessibility host must expose a coherent **semantic tree** with role, accessible name/description, state, relationships, actions, focus and progress/error announcements; evidence on Windows UI Automation, macOS accessibility API, Linux AT-SPI and real assistive tech (NVDA/VoiceOver/Orca as available). Contrast, font scaling, reduced motion, keyboard-only docking alternative, visible focus, no essential hover-only action, text input/IME, bidi/shaping via proper UI toolkit. Dear ImGui immediate mode alone does not automatically provide screen-reader parity, so bridging or native widgets may be necessary and a decision gate.

## 6. 2D/3D viewport hosting and failure isolation
Viewport is an **opaque RHI surface owner reference**, not raw GL/Vulkan/Metal pointers in arbitrary widget. GFX layer owns device, swapchain/render graph, texture memory barriers, color space/HDR and GPU recovery. EDIT-01 owns viewport rectangle, active/hover/focus/capture, resize/DPI transform, visibility/occlusion/target frame budget, event coordination and texture/surface lifetime handshake. Panning is not simulation time: edit camera vs game camera vs preview-process camera separate. Resizing/dragging panels must not free texture while queued GPU reads use it. On device lost or monitor changed, show recoverable placeholder and rehydrate viewport after GFX owner acknowledges, not crash whole editor; if GPU absent, editor shell can still open status/project navigation without playable preview (capability degraded).
 
Backend-specific compatibility must compare native compositor/X11/Wayland, macOS Metal/Cocoa, Windows DWM/DirectX/Vulkan and sandbox/window embedding restrictions without promising universally embeddable child swapchain. No hard dependency from headless server to Qt/ImGui/Tauri/WebView or GPU.

## 7. Security, privacy, plugin and AI-native editor
Untrusted project paths, UI layout, command args, scripts, plugin manifests, SVG/fonts/markdown/html, external URLs and asset previews are hostile data. Allowlisted panel factories/manifest capabilities, bounded parsing and output HTML text escaping (for WebView); plugin loads through approved isolation (subprocess/sandbox when needed), signed/hashed manifests when adopted, package and filesystem grants to DATA-01 with no directory traversal or file overwrite from unsanitized URI. A plugin cannot register privileged global shortcut, steal focus invisibly, request clipboard/network/secrets or execute a shell silently. Tauri window/webview capability **merges** matter, so a compromised low-trust view may inherit unintended privileges if attached to multiple capabilities. Native C++ plugins also share process memory, so permission list alone does NOT isolate malicious native code.

AI/MCP uses exactly the same semantic registry and permission/expected source revision as manual UI, with preview/stage/validate/commit and explicit consent for destructive or paid operations. No generic "LLM click around the app" as security authority; stage/commit operations must be inspectable and auditable. Workspace focus/selection commands may expose sanitized metadata but cannot leak project secrets/hidden remote data.

## 8. Technology and staged approval
Leading proposal is **backend-agnostic semantic shell + evaluated native toolkit**, with an early controlled spike for **Qt 6 Widgets vs Dear ImGui docking**. Qt offers native dock and strong accessibility, but real LGPLv3 dynamic linking/compliance or commercial license obligations; certain modules GPL only. Dear ImGui is MIT and fits engine-tool viewport integration, but accessibility/complex text/IME/floating monitor parity and safe layout persistence require evidence. Slint has triple-license including proprietary royalty-free desktop with attribution conditions; Tauri dual MIT/Apache and OS WebView capability boundary, wxWidgets wxWindows licence and Nuklear MIT/public domain alternatives. **No option selected by merging these documents**; no dependency installed or license approved.
